ABSTRACT 
Savidya Premasundera: Multi-Agent System for Automated Code Reviews 
Master of Science Thesis 
Tampere University 
Master’s Degree Programme in Software, Web & Cloud 
December 2025 
 
 
 
 
Code reviews play a key role in software quality assurance , yet the process is often time-
consuming, inconsistent, and dependent on reviewer expertise . Although recent Large 
Language Model (LLM) advances have introduced automated review tools, single -model 
systems often suffer from inconsistency, redundancy, and limited trust when relying on a single 
agent. This thesis addresses these limitations by proposing a multi -agent LLM -based 
automated code review system in which four domain -specialized agents , Readability, 
Refactoring, Performance, and Security, independently evaluate code changes, and collaborate 
via a Consensus Agent that consolidates, scores, and ranks the issues identified. The system 
introduces an Evaluation Matrix Consensus Scoring (EMCS) model that balances reliability and 
impact by combining consensus metrics such as confidence and inter -agent agreement with 
priority metrics such as severity and category importance to compute a final score for each is-
sue. 
Empirical results indicate that the multi -agent approach broadens coverage across catego-
ries, reduces redundancy, and yields more stable confidence distributions compared to a single-
LLM baseline. The agents exhibit strong domain -specific specialization, with meaningful 
differences in issue types, severity profiles, and confidence levels, while achieving moderate 
overlap that supports cross-agent validation. The Consensus Agent significantly improves clarity 
and actionability by merging semantically similar issues, filtering low -value detections, and 
integrating reliability and impact metrics. The final ranked output is more concise, structured, 
and trustworthy than that of individual agents. 
This work presents a novel architecture for automated code review that combines domain -
specialized agents with a conscientious consensus mechanism . It demonstrates how multi -
agent collaboration enhances the reliability, clarity, and usefulness of LLM-generated feedback. 
Together, these advances demonstrate that multi-agent consensus can improve the trustworthi-
ness and clarity of automated code review, offering a practical pathway for integrating LLMs into 
developer workflows and opening doors for future research on adaptive weighting and protocol-
driven orchestration. 
 
 
Keywords: Multi-agent systems , Large Language Models , Automated Code Review , 
Software Quality

1. INTRODUCTION 
1.1 Project Overview 
Software development has become increasingly complex, collaborative, and fast -
paced, with modern systems requiring contributions from distributed teams working 
across diverse languages, frameworks, and domains. As software projects scale, con-
ducting thorough code reviews becomes essential to uphold quality standards, en-
hance maintainability, and ensuring long-term system sustainability [2]. Code reviews 
help identify errors early, maintain coding standards, improve maintainability, and pro-
mote developer knowledge transfer [2], [3], [4]. However, despite its importance, man-
ual code review suffers from persistent limitations. It is inherently time -consuming, cog-
nitively demanding, inconsistent, heavily dependent on reviewers’ domain expertise 
and availability, and increasingly unsustainable for large, fast -evolving projects [5], [6], 
[9], [12]. Traditional static analysis tools are highly reliable for detecting well-defined er-
rors, but they rely on a fixed set of rules and lack the flexibility to adapt to evolving cod-
ing practices [20], [22]. 
Artificial Intelligence (AI) has become increasingly embedded in modern software de-
velopment workflows. Tools based on Large Language Models (LLMs), and LLM code-
assistants integrated in IDEs now routinely assist developers with code generation, 
documentation, and even debugging [15]. Recent studies indicates that LLMs can also 
provide valuable support for code review by identifying defects, generating explana-
tions, and suggesting improvements [18], [22]. Nevertheless, the majority of AI -driven 
code review tools rely on monolithic model architectures, which remain limited by sev-
eral well -known issues including hallucinations, unstable reasoning, and insufficient 
contextual understanding [3], [4], [21]. These models tend to generate feedback that is 
verbose, partially redundant, or insufficiently actionable for real-world development use. 
As a result, neither static analysis tools nor single -agent LLM systems fully meet the 
need for a coordinated, comprehensive, and multi-dimensional automated code review 
process. 
To address these limitations, this thesis proposes a Multi-Agent System 
(MAS) designed to perform automated code review through distributed specialization 
and structured consensus. Rather than relying on a single general -purpose LLM, the

[[page 11]]

system employs multiple lightweight, domain -specific reviewer agents , each focusing 
on a distinct aspect of code quality such as readability, refactoring, security, and per-
formance. Each agent independently analyzes the code changes and produces a set of 
structured issues aligned with its domain expertise. Their outputs are then processed 
by a Consensus Agent , which integrates the findings from all specialized agents and 
applies structured scoring mechanisms to resolve conflicts, remove redundancies, and 
generate a coherent, prioritized list of issues with enhanced clarity, reliability , and 
actionability. 
This architecture mirrors the collaborative dynamics of human code reviews, where 
multiple reviewers with different expertise contribute unique perspectives, ultimately 
producing higher-quality insights through collective reasoning. 
1.2 Aim 
The aim of this research is to develop and evaluate a multi-agent system for automated 
code review that uses domain-specialized agents and a consensus mechanism to gen-
erate feedback that is comprehensive, reliable and actionable. 
1.3 Objectives 
The main objective of this thesis is to design, develop, and evaluate a multi -agent sys-
tem for automated code review that produces clear, reliable, and actionable feedback 
by combining the strengths of specialized reviewer agents through a coordinated con-
sensus-based decision-making process. 
Specifically, the objectives are to: 
§ Develop specialized domain specific review agents (Readability and Maintaina-
bility Reviewer Agent, Refactoring and Best Practices Reviewer Agent, Security 
Reviewer Agent, Performance and Efficiency Reviewer Agent). 
§ Implement a Consensus Review Agent that integrates, prioritizes, and explains 
feedback from multiple agents. 
§ Evaluate the system’s effectiveness and performance compared to Single mon-
olithic LLM reviews, internal MAS components, and final consensus output. 
1.4 Research Questions 
1. How effective is a multi -agent system in improving the quality of automated 
code reviews compared to single-agent or monolithic LLM models?

This question investigates whether a distributed multi-agent approach produces higher-
quality and more comprehensive code review outcomes than traditional single -agent 
(monolithic) LLM. The analysis focuses on evaluating improvements in issue detection 
accuracy, coverage across multiple quality dimensions (readability, security, perfor-
mance, and maintainability), and the overall usefulness and interpretability of the gen-
erated feedback. 
2. How do specialized domain -specific agents differ in the types and prioritiza-
tion of code issues they detect, and to what extent do they achieve reliable 
consensus? 
This question examines the internal dynamics of the multi-agent system by focusing on 
the diversity, specialization, and collaborative reliability of its individual agents (Reada-
bility, Refactoring, Security, and Performance ). It investigates how each agent contrib-
utes unique insights through differences in issue types, severity, and confidence, while 
also assessing the degree of alignment or overlap between agents. Furthermore, it 
evaluates how reliably the Consensus Agent integrates these findings, identifying 
which issues are preserved, merged, or filtered to produce coherent, high -quality re-
view outputs. 
3. How does a Consensus Agent enhance the clarity, actionability, and trustwor-
thiness of automated code review feedback by balancing reliability (confi-
dence and inter -agent agreement) with impact (severity and category priori-
ty)? 
This question focuses on the integrative role of the Consensus Agent, which consoli-
dates and prioritizes findings from multiple specialized agents through the Weighted 
Evaluation Matrix for Consensus Scoring (EMCS). The goal is to determine how this 
aggregation process improves the interpretability and usefulness of automated code 
review outputs.

2. LITERATURE REVIEW 
2.1 Chapter Overview 
This chapter reviews the foundations, developments, and emerging directions in auto-
mated and multi -agent–driven code review. It begins by outlining the role and im-
portance of code review in software engineering practice, followed by an examination 
of automated techniques including static analysis, machine learning –driven review 
support, and recent advances in LLM –based code review systems. The chapter then 
surveys multi -agent LLM frameworks, focusing particularly on those applied to code 
understanding and review tasks. It concludes with a comparative synthesis highlighting 
the gaps that motivate this thesis and justify the proposed multi -agent consensus -
based architecture. 
2.2 The Role of Code Review in Software Engineering 
Code review, first formalized by Fagan in 1976, plays a vital role for improving code 
quality and detecting defects, with structured inspections significantly enhancing 
productivity and software quality by identifying and addressing errors early in the de-
velopment process [1]. Code review is an essential and widely used practice in soft-
ware engineering for ensuring code quality, detecting defects, maintainability, and pro-
moting a continuous improvement among development teams [2], [3], [4]. 
Although code review is essential , notable misalignments remain between existing 
tools and developers’ actual goals and workflows, reducing efficiency and contributing 
to frustration [7], [12]. Research shows that developers devote a considerable portion 
of their time on code reviews, typically 10 –15% of their overall development effort [6]. 
Moreover, effective evaluation of code changes requires selecting reviewers with com-
prehensive knowledge of the corresponding source code to thoroughly evaluate modifi-
cations and identify defects [2], [3], [4], [5], [6]. Yet manual reviewer selection often fails 
to identify the most appropriate reviewer, resulting in inefficient or declined reviews and 
ultimately delaying the review process [3 ], [5]. Furthermore, consistently assigning re-
views to the most qualified developers can create an excessive workload, which has 
been shown to negatively affect the overall quality of their reviews [9]. These challeng-

[[page 15]]
6 
 
es highlight the need for modern code review approaches that preserve the benefits of 
code review while minimizing manual effort and inconsistency [2], [12], [40]. 
2.3 Automated Code Review: Tools, Techniques, and Limita-
tions 
Modern code review, a substitute to conventional code inspections [4], evolved as a 
technology-driven approach to enable efficient and effective quality assurance [2], 
complementing continuous integration and deployment (CI/CD) for frequent and 
reliable feature releases [4]. Automated code review has become increasingly essential 
to modern software engineering workflows [2], [8]. A range of strategies has been ex-
plored for strengthening code review effectiveness, such as advancing tool capabilities, 
introducing automation, recommending appropriate reviewers, and improving feedback 
quality [4], [14]. Numerous tools and models have been proposed to assist developers 
in identifying issues ranging from syntax errors to deeper semantic inconsistencies. 
Static Analysis and Early Automated Approaches 
Static code analysis techniques examine programs by analyzing their source code or 
intermediate representations without executing them [10 ], [11]. These techniques en-
hance software quality by identifying potential defects, violations of programming con-
ventions, and problematic constructs early in the development lifecycle, but they are 
inherently limited because they cannot infer broader intent, adapt to evolving project 
patterns, or learn from contextual feedback, and their approximate analyses often lead 
to false alarms when flagged issues never occur in actual execution 
[11]. Consequently, their scope is limited to static, predefined rules, which makes them 
less effective for addressing nuanced or domain-specific quality concerns [20], [22] and 
ultimately requiring human judgment and developer expertise [33]. 
Parallel to static analysis, IDE -based support tools attempted to enhance code 
comprehension and identify potential issues, but these early aids have been largely 
supplanted by centralized platforms such as GitHub, GitLab, Bitbucket, and Gerrit, 
which provide integrated review workflows [4]. 
LLM-Based Code Review: Advances and Challenges 
Recent advances in artificial intelligence, particularly in LLMs, have further expanded 
the capabilities of automated review tools. Modern LLMs demonstrate an ability to in-
terpret code semantics, detect complex defects, and generate natural -language expla-
nations at a level unattainable by traditional static analysis approaches [13 ], [15], [16].

[[page 16]]
7 
 
They can articulate their reasoning and provide human -readable explanations for de-
tected issues, improving accessibility and contextual understanding of code behavior 
[4]. State-of-the-art models such as Codex [13], GPT -4 [17], Code Llama [15], and Co-
deGen [18] have shown strong performance in tasks including code generation, refac-
toring suggestions, vulnerability detection, and semantic reasoning about program in-
tent [14], [16]. Their ability to process and explain code in natural language, coupled 
with structured review comment generation, makes them appealing candidates for au-
tomated reviewing. Recent studies have used machine learning to support multiple as-
pects of the code review process, including suggesting reviewers, ranking review tasks 
based on change characteristics or defect risks, and helping reviewers understand and 
inspect code [4], [19], [20], [22], [32], [33]. 
Several research efforts explored single-model or ensemble-based automated code re-
view using pretrained models. Tufano et al. [22] explored how pre-trained sequence-to-
sequence models can be used to improve the automation of code reviews, demonstrat-
ing that such models can generate meaningful review comments by learning from large 
datasets of real -world code reviews. Their study demonstrates that pretrained LLMs 
can capture reviewer intent but also exposes limitations in comment specificity and pri-
oritization. AUGER [32] similarly explores comment generation using pretrained trans-
formers. It automatically generates review comments by conditioning on code changes 
and reviewer context. Although effective in text generation quality, AUGER does not 
differentiate domain categories and lacks mechanisms for eliminating redundancy or 
adjusting severity. AutoCommenter [33] takes a related approach by assessing coding 
practices and generating feedback using neural architectures trained on review da-
tasets. While useful as a classification and feedback tool, AutoCommenter remains re-
stricted by single-model reasoning and limited interpretability. 
Moreover, CodeReviewer [34] uses a large-scale pretraining on review comment cor-
pora to improve LLM -generated review suggestions. Although it consistently outper-
forms smaller models, it remains a monolithic architecture that lacks the diversity and 
iterative reasoning required for comprehensive and reliable reviews. However, despite 
these capabilities, prior work consistently highlights challenges such as hallucinations, 
inconsistency, and limited domain specialization, demonstrating the need for more reli-
able, collaborative, and domain -aware review mechanisms [3], [4], [21]. These limita-
tions motivate the development of multi-agent approaches, where LLM specialists col-
laborate to produce more reliable and interpretable outputs.

[[page 17]]

Multi-Agent Systems for Code Review 
Multi-agent systems ( MAS) present an opportunity to address the weaknesses of sin-
gle-LLM approaches. MAS research emphasizes collaboration among multiple auton-
omous agents to solve complex or distributed tasks efficiently, offering advantages in 
specialization, distributed reasoning, and error resilience [23], [36]. The emergence of 
LLM-based Multi-Agent Systems (LMA) enables multiple specialized agents to collabo-
rate and address complex problems with near-human reasoning, planning, and prob-
lem-solving abilities beyond the capabilities of a single model [24], [25], [26], [27], [28], 
[36]. In software engineering, which includes requirements, development, testing, and 
maintenance, LMA systems offer unique benefits by autonomously breaking down 
complex tasks into smaller sub -tasks that mirror real software development workflows 
[27]. They also enhance robustness by validating outputs through cross -agent debate 
and verification, which mitigates the risk of hallucinations common in single LLMs [25 ], 
[27]. 
Over the past years, a number of LMA frameworks have been proposed for software 
development, offering varying levels of autonomy, communicative ability, and domain 
specialization [28], [36]. MetaGPT [29] introduces a collaborative multi -agent system in 
which LLM agents take on specialized roles, including product manager, architect, and 
engineer, enabling coordinated generation of software artifacts. MetaGPT emphasizes 
workflow decomposition and cross-agent communication but is oriented toward end -to-
end development rather than code review. Similarly, ChatDev [27] constructs a team of 
communicative LLM agents that simulate software engineering teams to perform de-
sign, coding, and testing tasks collaboratively. These frameworks demonstrate the 
power of structured role assignment and agent -to-agent dialogue but do not offer fine -
grained issue detection, clustering, or prioritization necessary for automated code re-
view. Moreover, AgentMesh [28] proposes a collaborative multi-agent generative AI 
framework designed to improve reliability in software automation tasks by enabling de-
centralized agent collaboration. Although the system covers planning, coding, testing, 
and reviewing, it offers only broad MAS coordination and lacks a consensus mecha-
nism for prioritizing review comments or suggesting fixes; instead, it relies on human 
review and to validate AgentMesh’s output. Collectively, these systems highlight the 
trend toward orchestrated agent collaboration in software engineering, but they do not 
directly address the unique analytical and evaluative requirements of code review. 
Most importantly, they fail to recognize that code review fundamentally relies on inter-
action and collaboration [2].

2.4 Comparison of Multi-Agent Code Review Approaches 
More recently, researchers have started to explore MAS explicitly for code review 
tasks. CodeAgent [30] proposes a set of communicative agents that autonomously re-
view code changes by discussing potential issues and validating each other’s outputs. 
Although CodeAgent demonstrates improvements in issue identification through con-
versational self-verification, it has two limitations: it lacks domain -specific agents with 
specialized expertise (e.g., performance vs. security), and it does not incorporate struc-
tured clustering or a scoring mechanism to control redundancy or prioritize findings. A 
more comprehensive system, Hydra-Reviewer [31], introduces a multi -agent structure 
where multiple LLM reviewers independently generate comments before undergoing a 
two-stage merging pipeline. Hydra-Reviewer agents are dimension-oriented rather than 
domain-oriented, resulting in a large number of narrowly scoped agents whose outputs 
require heavy post-processing. This system demonstrates that multi -agent redundancy 
can yield higher -quality comments, but its merging process primarily focuses on com-
ment generation rather than modeling reviewer reliability, severity weighting, or catego-
ry-level prioritization. 
The comparison across existing systems reveals three major architectural distinctions: 
specialization strategy, collaboration model, and consensus quality. 
Specialization. 
A key distinction among multi-agent code review architectures is how they define agent 
roles. Some systems like MetaGPT [29] and ChatDev [27] rely on professional -role 
specialization, which supports workflow decomposition but does not address domain -
specific code review categories. Systems such as CodeAgent [30] use generic review-
er agents without explicit specialization, limiting coverage diversity. The present thesis 
differs by implementing four pre-defined heterogeneous domain-specialized agents: 
Readability, Refactoring, Security, and Performance, consistent with human review 
domains reported in empirical studies [6], [35], [31]. 
Collaboration and Communication 
Multi-agent code review systems also differ substantially in how agents communicate 
and collaborate. Conversational systems like CodeAgent [30] and ChatDev [27] em-
phasize dialogue-based collaboration, but dialogue alone does not prevent redundancy 
or hallucinations, as agents can become distracted by unrelated context, nor does it 
guarantee structured outputs [37]. Hydra -Reviewer [31] and ensemble approaches in-
stead rely on independent generation followed by merging. The proposed system 
aligns with this mod el but improves upon it by incorporating structured embeddings,

[[page 19]]
10 
 
clustering, and domain diversity to ensure that outputs remain structured, consolidated, 
and minimally redundant. 
Consensus and Output Aggregation 
Consensus strategies across prior work are either absent, minimal (simple deduplica-
tion), or heavily heuristic. Hydra-Reviewer [31] uses text clustering but lacks a reliability 
model. CodeAgent [30] uses cross-agent discussion, but its acceptance criteria are not 
explicitly scored or ranked. In contrast, this thesis proposes a scoring-based consensus 
agent that aggregates per-agent confidence, measures inter-agent agreement, normal-
izes severity rank, transforms category priority, and combines these into a final score 
used to rank issues. 
Weighted consensus algorithms in multi -agent research further reinforces this design. 
Olfati-Saber et al. [39] describe consensus as a process in which agents iteratively re-
fine shared beliefs according to weighted contributions. By adopting a similar weighted 
strategy, this thesis designs a final scoring function that synthesizes reliability (confi-
dence and inter-agent agreement) with impact (severity and category priority), enabling 
principled and explainable aggregation of heterogeneous agent outputs. 
The consensus mechanism in the proposed system also draws on recent advances in 
self-consistency and multi -agent reasoning. Wang et al. [38] demonstrated that self-
consistency, an approach that explores multiple reasoning paths and selects the major-
ity or most coherent answer, significantly enhances the reliability of LLM reasoning. By 
extension, cross-agent agreement acts as a collective reliability signal: if multiple inde-
pendent domain agents highlight the same issue, it is statistically more likely to repre-
sent a true concern.

4.3 Technology Selection and Justification 
Python was chosen as the primary language for implementing the multi -agent code re-
view system because it provides a mature ecosystem for scientific computing, natural 
language processing, and large language model integration. NumPy was used along-

evaluation metrics, confidence distributions, and clustering statistics. 
The system uses natural language processing techniques to cluster and merge seman-
tically similar issues across agents. Sentence-Transformer embeddings (specifically all-
MiniLM-L6-v2) were employed to generate compact semantic vectors that enable accu-
rate grouping of paraphrased issue descriptions at low computational cost. When em-
beddings are unavailable, hybrid similarity methods combining token-level Jaccard sim-
ilarity with sequence matching serve as a fallback for short or simple texts. These 
methods collectively help maintain consistent issue grouping while balancing perfor-
mance, semantic accuracy, and portability. 
Matplotlib [51] was selected as the main visualization library due to its reliability and de-
terministic output, which is important for reproducible academic figures. Seaborn [52] 
was used where appropriate to simplify the styling of heatmaps and distribution plots, 
providing consistent and readable visual outputs. Although these tools offer less inter-
activity than alternatives such as Plotly, they are sufficient for producing the static fig-
ures required in a research thesis. 
The frontend interface was built using React [47] and Vite [48], with TypeScript [49] for 
type safety and maintainability. This combination provides a fast development experi-
ence and a clear structure for creating an interactive interface for developers to inspect 
issues and review system outputs. Tailwind CSS [50] was used to streamline styling, 
offering a utility -based approach that allows rapid adjustments without managing com-
plex CSS files. While the chosen technologies do not include server-side rendering, cli-
ent-side rendering is fully adequate for a research -focused tool and keeps the imple-
mentation simple and lightweight. 
The backend architecture is implemented using FastAPI [46], OpenAI’s [45] GPT-
based models, and Model Context Protocol (MCP). This design was chosen after eval-
uating several alternative methods and technologies, and was selected for its transpar-
ency, replicability, and architectural flexibility, as described below.

The Consensus Agent synthesizes the outputs of all micro -agents and produces a sin-

1. Unify issues from all agents into a coherent review. 
2. Merge equivalent issues using semantic clustering. 
3. Compute reliability and impact scores using a weighted evaluation matrix. 
4. Filter issues.

5. Optionally generate explanations using an LLM. 
To meet these goals the Consensus Agent performs semantic clustering, computes 
aggregate metrics per cluster, computes a consensus reliability score and a priority 
score, combines these into a final score, filters low value items, and optionally gener-
ates a human readable rationale with an LLM. 
4.5.1 Semantic Clustering of Issues 
Agents may describe the same issue using different phrasing. Therefore, the Consen-
sus Agent performs semantic clustering using a hybrid similarity approach. Whenever 
embeddings are available, each issue description is encoded using a Sentence-BERT 
model (all-MiniLM-L6-v2), which provides a vector representation well -suited for short, 
technical sentences such as code review findings. These embeddings are compared 
using cosine similarity to detect paraphrased or conceptually equivalent descriptions. 
In cases where embeddings cannot be reliably applied , such as exceedingly short 
messages or descriptions dominated by code tokens : the system falls back to lexical 
similarity measures. This includes both Jaccard similarity computed on token sets and 
a Sequence Matcher ratio for string alignment. The system chooses the maximum of 
these measures to ensure that both semantic and lexical cues are considered. 
Because code-related messages sometimes include identifiers, variable names, or in-
line code fragments, the clustering process also incorporates a code -aware similarity. 
Identifiers are extracted from the descriptions and overlapping code tokens provide an 
additional similarity boost. The final similarity score is therefore defined as the maxi-
mum of the textual and code-token similarity values.

4.5.7 Issue Filtration 
A filtering mechanism was applied because LLM-based agents may occasionally gen-
erate low-confidence or minor suggestions that add little value to the final report . An is-
sue is removed only if it simultaneously meets four criteria: it was identified by just one 
agent, has a low confidence score, corresponds to low severity (severity score < 2.0 
i.e., below medium ), and belongs to a low -priority category such as readability. This 
multi-criteria filter avoids discarding potentially important single -agent findings (for ex-
ample, isolated security warnings with high confidence) while reducing noise from mi-
nor stylistic suggestions that lack cross-agent agreement. 
4.5.8 Arbitration Layer 
While the system provides a quantitative evaluation mechanism, it can be extended 
with qualitative insights from a Large Language Model (LLM). When enabled, the LLM 
is provided with the computed metrics and the ranked issues and is asked to produce a 
short justification explaining the ranking decisions. This additional layer provides hu-
man-interpretable reasoning, improving explainability and trustworthiness. This com-
bined use of quantitative scoring and qualitative reasoning brings together the precision 
of deterministic evaluation with the contextual depth of interpretive analysis. 
4.6 Chapter Summary 
The implementation integrates multi-agent analysis with a structured consensus mech-
anism designed to reduce redundancy, quantify agreement, and prioritize issues based 
on both reliability and potential impact. The Consensus Agent employs semantic clus-
tering, hybrid similarity computation, metric aggregation, and weighted scoring to pro-
duce a coherent, ranked set of findings. Through this combination of deterministic scor-
ing and optional narrative explanation, the system offers both analytical rigor and inter-
pretability. This implementation provides the foundation for evaluating the effectiveness 
of multi-agent collaboration and forms the practical basis for addressing the thesis re-

5.1 Chapter Overview

5.2 Evaluation Process 
The evaluation of the proposed multi -agent code review system followed a unified 
methodology across all three research questions . The purpose of this evaluation pro-
cess was to assess the effectiveness, internal behavior, and final output quality of the 
system under controlled and repeatable conditions. 
The evaluation of the proposed multi-agent code review system was performed using a 
researcher-constructed GitHub pull request intentionally designed to serve as a con-
trolled and realistic test environment. Since publicly available open source pull requests 
rarely contain a balanced distribution of issues across all four target categories 
(Readability, Refactoring, Performance, and Security), a synthetic PR was required to 
ensure that each agent could be evaluated under comparable conditions. To further 
approximate conditions encountered in real -world repositories, the PR spanned multi-
ple files written in different programming languages (Python, JavaScript, and Java), 
enabling the system to be tested against heterogeneous codebases with diverse syn-
tax and semantic patterns. The code in these files was generated using ChatGPT 
under explicit instructions to embed representative examples of common software 
defects. Designing the PR in this way allowed the evaluation to cover a wide spectrum 
of realistic issue types while maintaining full control over the presence and distribution 
of problems. 
Since no human -labeled ground truth dataset was collected, the evaluation did not 
measure traditional accuracy metrics such as precision or recall. Instead, the assess-
ment relied on a suite of internal, model -driven metrics designed to quantify system 
behavior, agent diversity, inter-agent agreement, and consensus reliability. These met-

rics were complemented by a comprehensive set of visualizations including distribution 
plots, similarity matrices, stacked contribution charts, and consensus ranking graphs , 
which together provided a structured, interpretable view of how the multi -agent system 
detects, aggregates, and prioritizes issues. This evaluation approach allowed a multi-
dimensional analysis despite the absence of external human-labeled benchmarks. 
All experiments were executed using a dedicated evaluation service integrated into the 
multi-agent system. All experimental results were captured as structured JSON outputs 
accompanied by visualizations saved as PNG images within the evaluation workspace. 
This approach maintained a clear boundary between the system’s operational interface 
and its research -oriented validation process. Together, this evaluation methodology

6.1 Chapter Overview

while the consensus mechanism plays a crucial role in improving clarity, trustworthi-

6.2 Conclusion 
This thesis investigated the design, implementation, and evaluation of a multi -agent 
system (MAS) for automated code review, integrating domain -specialized large lan-
guage model agents with a Consensus Agent intended to improve the clarity, reliability, 
and actionability of review feedback. The system comprises four specialized agents 
(Readability, Refactoring, Performance, and Security ) and a Consensus Agent that 
merges, filters, and prioritizes their findings into a unified ranked output. The evaluation 
was organized around three research questions, each examining a different dimension 
of system behavior. 
RQ1 evaluated MAS against a single monolithic LLM and demonstrated that multi -
agent review provides broader coverage of issue categories, detects more diverse 
problems, and produces feedback with higher structural clarity. Although the raw out-
puts of the agents occasionally exhibited higher fragmentation and variable confidence, 
the overall coverage breadth and category diversity exceeded that of a single LLM. 
These findings suggest that the division of responsibilities among agents improves the 
overall capability of the system beyond what a single model can deliver. 
RQ2 investigated the internal dynamics among the specialized agents. The findings re-
veal meaningful diversity in issue types, severity assessments, and confidence distribu-
tions. Each agent demonstrated domain -specific expertise, contributing unique issues 
that others did not detect, supporting the idea that specialization improves the com-

[[page 60]]
51 
 
pleteness of reviews. Inter -agent agreement was only moderate, reflecting productive 
specialization rather than redundancy, and consensus acceptance rates showed that 
most initial findings were coherent and aligned with system -level expectations. The 
Consensus Agent managed these variations effectively, maintaining a stable internal 
balance between specialization and corroboration. Overall, these results confirm that 
the MAS architecture gains value from the complementary perspectives of heterogene-
ous agents without producing conflicting behavior. 
RQ3 examined the Consensus Agent’s effectiveness in improving clarity, actionability, 
and trustworthiness. Quantitative results indicated strong improvements across all clari-
ty metrics, including notable reductions in duplicate issues, filtering of weak findings, 
and consolidation of descriptions. Reliability was strengthened through the integration 
of cross-agent agreement and confidence weighting, while the ranking mechanism ef-
fectively elevated high -severity and high -priority issues. The balanced scoring model 
ensured that both impact and reliability contributed meaningfully to the final review. 
Taken together, these results show that consensus is not simply a merging step, but a 
critical reasoning layer that transforms distributed multi-agent outputs into structured, 
developer-ready review feedback. 
Overall, this thesis demonstrates that a coordinated multi -agent approach provides a 
promising direction for advancing automated code review . By integrating domain spe-
cialization, parallel reasoning, and structured consensus, the system achieves higher 
diversity, enhanced prioritization, and more reliable recommendations than a single 
LLM working independently. The MAS offers broader coverage, a richer variety of is-
sues, and more stable prioritization, while the consensus mechanism effectively con-
solidates and organizes these outputs into coherent, trustworthy feedback. These find-
ings contribute to the expanding understanding of how LLM -based multi -agent work-
flows can enhance practical developer tools. 
6.3 Limitations 
This study has several limitations that affect the generalizability of its findings. First, the 
evaluation lacked human-labeled ground truth, meaning that measures of correctness, 
precision, and false positives could not be assessed directly. Instead, the analysis re-
lied on internal agreement, confidence, and consensus -based metrics, which reflect 
system behavior but do not provide a definitive measure of accuracy. 
Additionally, obtaining rich, real-world PRs containing all four issue categories (Reada-
bility, Refactoring, Performance, and Security) was not feasible. As a result, the evalua-

[[page 61]]
52 
 
tion used a curated PR from the author's own repository. While this approach ensured 
consistency and control, it may not fully capture the complexity, imbalance, or noise 
typically present in real-world industrial PRs. 
Large language models exhibit unpredictable behavior even under fixed prompts and 
parameters, and although the consensus mechanism mitigates some variability, results 
cannot be reproduced with perfect consistency. Small differences in context windows, 
model state, or decoding may yield different issue sets, which complicates rigorous 
benchmarking and comparative studies. 
The outputs of LLM agents are inherently nondeterministic, and although the consen-
sus mechanism helps reduce variability, results cannot be reproduced with perfect 
consistency. Even with fixed parameters, minor differences in context windows or 
prompt variations can lead to different outputs. Additionally, the agents use OpenAI 
GPT-4 for the model may limit the generalizability of the findings. While GPT -4 is a 
highly capable language model, its performance may not represent the full range of 
possibilities across different models or versions of LLMs. The results could differ if al-
ternative models, with different architectures or data, were used. 
Finally, the evaluation focused on issue detection and ranking rather than the quality of 
suggested fixes, and no end-user study was conducted. As a result, the practical usa-
bility and perceived value of the system remain unvalidated. 
These limitations indicate that while the system exhibits structurally strong perfor-
mance, further work is needed to validate accuracy, scalability, and real -world applica-
bility. 
6.4 Future Work 
A primary direction for future work is incorporating human-annotated ground truth, such 
as expert-labeled reviews or crowdsourced annotations. This would enable precise cal-
culation of accuracy metrics, allowing a better assessment of the system's perfor-
mance. Ground -truth-validated severity scoring and large -scale benchmarking across 
multiple PRs would enable a more standardized comparison, thereby enhancing the 
overall validity of the findings. 
The current evaluation was limited to a curated PR containing issues across four cate-
gories. Future evaluations should extend testing to large open -source repositories 
across multiple programming languages, focusing on real -world code review scenarios 
with unbalanced issue types, noisy diffs, and large PRs. This would provide a deeper

[[page 62]]
53 
 
understanding of the system's generality and robustness, revealing how the MAS per-
forms across diverse repositories and realistic code review distributions. 
Another opportunity lies in benchmarking against alternative multi -agent architectures. 
Approaches such as argumentation -based agents, cooperative self -refinement loops, 
or hierarchical evaluators could expose strengths and weaknesses of the consensus -
based architecture and identify optimal system designs for different tasks. 
The Consensus Agent itself also offers potential for improvement through more ad-
vanced strategies. Future research could explore Bayesian consensus models, argu-
mentation-based reasoning (where agents explain the validity of issues), or reinforce-
ment learning-driven ranking strategies informed by human reviewer preferences. Addi-
tionally, voting systems that dynamically adjust weights based on agent reliability over 
time could enhance the system's adaptability and context-sensitivity. 
In addition, integration into real development environments, such as IDEs (VS Code, 
JetBrains) and CI/CD pipelines (GitHub Actions, GitLab CI, Jenkins) would transform 
the system from an experimental research prototype into a practical, developer -ready 
tool suitable for large-scale adoption in modern software engineering practices. 
Finally, integrating developer-in-the-loop feedback presents a valuable direction. Allow-
ing users to rate or correct issues could guide adaptive learning, preference modeling, 
and personalized review behavior. Such feedback loops would transform the MAS into 
a continuously improving and context-aware code review assistant capable of adapting 
to project standards and developer expectations. 
6.5 Chapter Summary 
This thesis demonstrates that multi-agent code reviewer offers promising new capabili-
ties for automated code review. By combining domain specialization with structured 
consensus, the system delivers clearer, more actionable, and more trustworthy review 
feedback than a single model alone. The findings help clarify the design trade -offs in-
volved in multi -agent orchestration and provide a roadmap for future intelligent devel-
oper tooling. As LLMs evolve and multi -agent techniques mature, this work positions 
multi-agent consensus-based review as a viable and effective direction for augmenting 
the modern software development workflow.
