Abstract—Large language models (LLMs) have shown promis-
ing code generation capabilities; however, they still face chal-
lenges in generating successful code for non-trivial programming
tasks. To enhance the LLM’s code generation abilities, we
investigate, in this paper, the combination of two complementary
inference-time strategies: multi-agent collaboration and runtime
execution-based debugging. We conduct an extensive empirical
study to evaluate our proposed framework using 19 diverse LLMs
on two established coding benchmarks, measuring functional
accuracy as a code quality characteristic. Our study reveals
that that our combination outperforms the basic performance
of LLMs and the individual approaches. In particlular, on
HumanEval benchmark, across 19 LLMs, our approach achieves
64.82% accuracy compared to 56.48% achieved by the basic
one-shot prompting approach. It also outperforms the individual
multi-agent collaboration approach by more than 7.66%. More-
over, our extensive empirical study revealed that optimal combi-
natory improvement is achieved when both individual strategies
perform at similar levels. The proposed framework can be readily
deployed in existing development pipelines to enhance the relia-
bility of code generation while maintaining reasonable generation
speeds, offering a practical solution to improve automated code
generation in enterprise environments. Our code is available at:
https://github.com/nazmus-ashrafi/multiagent vs debugger

I. I NTRODUCTION
The emergence of Large Language Models (LLMs) has
revolutionized Natural Language Processing (NLP), enabling
progress across numerous applications such as conversational
AI systems, document summarization, and automated con-
tent creation. Code generation stands out as a particularly
noteworthy use case for LLMs, attracting considerable re-
search interest due to its capacity to automate complex pro-
gramming tasks [3, 12, 16]. The pursuit of improving code
quality and reliability in LLM-generated outputs has spurred
the creation of diverse inference-time approaches, including
retrieval-augmented generation (RAG), collaborative multi-
agent feedback systems, and iterative code refinement through
runtime debugging. These inference-time methods enhance
task performance by implementing computational techniques
solely at the inference stage, without modifying the model’s
learned parameters [6]. These approaches enable performance
gains in less powerful models while preserving computational
cost-effectiveness.
The collaborative multi-agent strategy [10, 11, 15] utilizes
multiple LLM-powered agents working in concert, with each
agent addressing distinct components of code generation. AI
agents, broadly defined as autonomous goal-driven systems,
are implemented in this work as separate LLM instances
with specific roles and objectives, guided by system prompts.
Through establishing interactive role-based exchanges among
agents, this technique fosters a collaborative framework that
emulates the task distribution commonly found in professional
software engineering teams. The alternative strategy employs
runtime execution feedback to enable more informed debug-
ging procedures [5, 9, 17]. Through analyzing the execution
correctness of code components, this method offers crucial in-
sights into potential defects and program behavior. These two
inference-time methodologies present compelling opportuni-
ties for advancing LLM-based code generation. While existing
research has explored these approaches independently, there
remains limited comprehensive evaluation of their sequential
integration and combined effectiveness.

sequentially applies two inference-time techniques: first, multi-
agent collaboration as a process-oriented pipeline to gener-
ate code, followed by a runtime execution feedback as a

II. L ITERATURE REVIEW
This section reviews literature on the two inference-time
methods underlying our framework: multi-agent collaboration
and runtime execution-based debugging for LLM code gener-
ation.
A. Multi-Agent Collaboration
LLM-based multi-agent systems have garnered significant
attention across academia and industry alike. These frame-
works utilize sophisticated agent interactions to create a solid
groundwork for generating code. AgentCoder [10], for in-
stance, implements a multi-agent architecture where an LLM-
driven test designer develops test cases, while a test executor
runs the generated code and delivers feedback to the coder
agent for iterative improvement. MapCoder [11] represents a
multi-agent system that mirrors human programming work-
flows through four LLM-powered agents: Retrieval, Planning,
Coding, and Debugging. These components function sequen-
tially, with successive stages building on prior results via
dynamic communication and feedback loops, enhancing code
generation through relevant example utilization, systematic
planning, and validation mechanisms. The self-collaboration
approach presented in [7] deploys three LLM agents within an
organized pipeline: the Analyst Agent breaks down program-
ming tasks and develops a high-level strategy, the Coder Agent
executes the solution following this strategy, and the Tester
Agent continuously assesses and directs the Coder Agent
toward code refinement. Multi-agent interaction presents a
compelling direction for advancing LLM-based code gener-
ation, as it enables role-based cooperation and division of
labor, which are essential characteristics of effective software
development teams in real-world scenarios.
B. Runtime Execution Information-Based Debugging
Utilizing runtime execution data to improve code gener-
ation represents a well-established strategy in this domain,
with numerous frameworks adopting this technique receiving
significant research interest. The Cycle framework [5], for
example, enables pretrained LLMs to perform self-refinement
through continued training on data samples derived from three
information types: high-level problem descriptions, previously

traces to track intermediate variable values within each basic
block. It employs an LLM to evaluate block correctness
and interpret the execution pathway, applying this analysis
to iteratively refine the code. Through the strategic use of
runtime execution data for debugging purposes, these studies
convincingly illustrate its effectiveness in advancing LLM-
based code generation.
III. R ESEARCH METHODOLOGY
Our research employs a sequentially integrated approach
that combines structured multi-agent collaboration with run-
time execution debugging for enhanced LLM-based code gen-
eration. The complete implementation, including source code,
experimental scripts, and agent prompts, is publicly available
in our GitHub repository 1 to ensure full reproducibility.
As illustrated in Figure 1, the framework functions through
two sequential stages. In the initial stage, three specialized
LLM agents (Analyst, Coder, and Tester)collaborate using an
modified waterfall methodology within a multi-agent system.
The subsequent stage involves runtime execution debugging,
which is triggered when the initially generated code needs
refinement. This sequence mirrors typical software engineering
workflows: collaborative planning and coding, followed by
systematic debugging.
A. Multi-Agent Collaboration (ACT) Implementation
The first stage of our hybrid methodology constitutes the
process-driven component and employs a multi-agent col-
laborative framework consisting of three specialized agents:
an Analyst, a Coder, and a Tester. This design parallels the
collaborative framework outlined in [7] and is illustrated in the
ACT module shown in Figure 1. We chose this architecture
due to its straightforward design and limited agent count,
making it an appropriate example of conventional agent-based
workflows in the field. Furthermore, this structure provides
adaptability, allowing for easy modification of interaction
complexity through the addition or removal of agents. Within
this stage, the Analyst Agent decomposes programming tasks
into smaller, manageable components and formulates a com-
prehensive implementation strategy. Following this strategic
outline, the Coder Agent generates the solution, progressively
improving the code through an iterative process informed by
the Tester Agent’s evaluation, which includes code inspection,
syntactic verification, and requirements validation. To balance
computational cost and effectiveness, this refinement cycle is
limited to a maximum of three iterations (retriesCT=3).

B. Runtime Debugging (Debugger) Integration
The product-oriented debugging phase adapts the Large
Language Model Debugger (LDB) approach as proposed in
[17]. When code produced by ACT does not pass the vis-
ible test cases, we break down the problematic code into
fundamental blocks through Control Flow Graph (CFG) de-
composition, illustrated in the Debugger module of Figure
1. Our implementation employs block-level decomposition,
which yields the most accurate results among the available
decomposition strategies. As the code executes with test cases
that trigger failures, we track and record the values of inter-
mediate variables contained within each block. A debugger
agent receives this execution trace to analyze the errors and
produce diagnostic explanations, which subsequently inform a
coder agent that generates revised code. We limit this iterative
debugging process to 4 cycles (retriesD = 4), a reduction from
LDB’s standard 10 iterations, to balance effectiveness with
computational efficiency.
C. Experimental Setup
We begin by segmenting the HumanEval and HumanEval+
benchmark datasets into three components: task descriptions
(function identifier and natural language requirement), visible
test cases (for framework execution), and hidden test cases
(for final evaluation). Our chained framework then processes
problems sequentially: first through ACT collaboration until
code passes visible tests or reaches maximum iterations, then
through debugging phase if needed, until success or iteration
limit.
Large Language Models: We evaluate 19 LLMs spanning
diverse architectures, training methodologies, and providers,
including OpenAI (GPT-4o, GPT-4o-mini, GPT-3.5-Turbo),
Anthropic (Claude 3.5 Sonnet/Haiku, Claude 3 Haiku), Meta
(LLaMA variants), Google (Gemini 2.0 Flash, Gemini 1.0 Pro,
Gemma 2), Microsoft (Phi-3.5), Alibaba (Qwen2.5), Mistral
(Mixtral 8x7B, Mistral-Instruct), and others (A table summa-
rized the LLMs utilized in our study along with API endpoint
details can be found in our GitHub repository 1). Our selection
ensures comprehensive coverage across: (1) parameter scales
from 3.8B (edge deployment on devices like smartphones)
to 671B parameters (cloud-based models pushing AI perfor-
mance boundaries); (2) training specialization from general-
purpose to instruction-tuned and code-specific models; and (3)
accessibility paradigms spanning both open-source and closed-
source architectures.
All models were prompted with identical role-specific in-
structions to ensure experimental consistency. For decoding,
we set the temperature to 0, following common practice
in code generation benchmarks, as this yields deterministic
output and allows for fair comparison across models.
Datasets: We conduct experiments on HumanEval [3] con-
sisting of 164 handwritten programming problems in Python,
and HumanEval+ [13] which enhances the original dataset
with 80× more test cases.
Evaluation Metrics: We use pass@1 as our primary metric,
measuring functional correctness of single generated solutions.

IV. R ESULTS
A. Experimental V alidation of ACT-Debugger Integration
We evaluated 19 LLMs across three experimental con-
figurations to investigate if the integration of multi-agent
collaboration (ACT) with run-time execution debugging (De-
bugger) yields substantially better functional accuracy than
either method independently. The configurations included: (1)
combined ACT + Debug, (2) ACT only, and (3) Debug only.
We used the HumanEval benchmark for this assessment, while
HumanEval+ was reserved for evaluating code rigorousness.
In HumanEval, the combined approach achieved 64.82% mean
accuracy, compared to 57.16% for ACT alone and 63.86% for
Debug alone (comprehensive results in Table I). We tested two
hypotheses using one-tailed paired t-tests:

V. I MPLICATIONS FOR AI-D RIVEN SOFTWARE
ENGINEERING
AI’s role in software engineering is undergoing a major
shift. Previously, AI was primarily an analytical tool, used
to predict system stability [2], detect design defects [14], and
optimize software architecture [1, 4]. Now, with generative
Large Language Models (LLMs), AI is evolving into a co-
creator that directly writes and refines code. This shift impacts
the core development and testing phases, aligning with recent
findings that AI tools significantly improve practices in soft-
ware construction![8]. Our framework reinforces this by using
multi-agent collaboration and runtime debugging to enhance
the functional accuracy of AI-generated code. Despite this
progress, overcoming key challenges in complexity, efficiency,

VI. C ONCLUSION
Our study investigated the integration of multi-agent col-
laborative approaches with runtime debugging techniques in
LLM-based code generation, testing across 19 language mod-
els and 2 datasets. Key findings reveal that our combined ap-
proach outperforms the basic approach and the individual ACT
approach. We also find that the success of integrating both
ACT and debugger strategies depends on their performance
disparity. When debugging significantly outperforms agentic
approaches, combining them introduces unnecessary complex-
ity. However, a simple two-agent (Analyst-Coder) workflow
with debugging yields a small but meaningful accuracy im-
provement over debugging alone, across both HumanEval
and HumanEval+, while preserving code rigor and latency,
suggesting this as the optimal configuration.
These insights have critical implications for production AI
systems, where even modest accuracy improvements yield
significant value at scale. Organizations should prioritize
simple agentic systems with debugging over complex multi-
agent architectures for cost-effective, reliable code generation.
Future research should investigate broader programming do-
mains, explore combining more code-specific inference-time
strategies, incorporate comprehensive code quality metrics
beyond functional accuracy, and develop adaptive combination
