ABSTRACT The advent of Large Language Model (LLM)-based agent systems represents a significant
paradigm shift in Artificial Intelligence, enabling unprecedented capabilities in autonomous reasoning,
planning, and interaction. However, the transformative potential of these agents is fundamentally constrained
by a critical operational challenge: high response latency. This latency, which impairs usability, restricts
real-time applicability, and challenges economic viability, is a paramount barrier to their widespread
adoption in complex, real-world scenarios. This survey provides a comprehensive and structured analysis
of the multifaceted latency problem in LLM-based agent systems. We present a structured taxonomy that
deconstructs end-to-end latency into its constituent sources, offering a holistic view of the entire agent
stack. Our review spans four primary layers of optimization: 1) Core LLM Inference, covering techniques
to accelerate the foundational model, including quantization, pruning, efficient attention mechanisms, and
speculative decoding; 2) Agent-Level Frameworks, detailing strategies to refine the agent’s cognitive loop,
such as accelerating planning cycles, optimizing tool use, and implementing latency-aware memory man-
agement; 3) System-Level and Infrastructure, encompassing optimizations for the underlying deployment
environment, including advanced serving systems, hardware acceleration, dynamic resource allocation,
and distributed architectures; and 4) Multi-Agent Systems, addressing specialized methods for mitigating
communication and coordination overhead in collaborative agent ensembles. We identify key unresolved
challenges and outline promising future research directions—including hardware-software co-design, novel
agent architectures, and AI-driven system orchestration—to guide the ongoing quest for ultra-low latency
intelligent systems.

leverage LLMs as their core cognitive engine, mark a sig-
nificant departure from traditional AI agents often limited
by brittle, domain-specific algorithms [4], [5]. However, this

LLM-based agent systems distinguish themselves from
traditional AI by employing LLMs as the central processing
unit for cognitive tasks previously handled by disparate, often
hand-engineered modules [2], [9]. This architectural shift
introduces novel capabilities but simultaneously creates intri-
cate operational pathways where latency can accumulate. Key
differentiators that contribute to both enhanced functionality
and potential delays include: (1) Natural Language as the
Primary Interface, enabling intuitive interaction but requiring
LLM processing for understanding and generation [10], [11];
(2) Inherent Knowledge and Reasoning, where LLMs pro-
vide vast world knowledge and emergent reasoning, reducing
explicit programming but involving computationally inten-
sive inference [1], [12]; and (3) Generalized Planning and
Decision-Making, allowing flexible task decomposition and
execution based on LLM capabilities, but often entailing
iterative model consultations [13], [14]. To realize these func-
tions, LLM-based agents typically integrate an LLM Core
(the cognitive engine), Memory Modules (for context and
learning, often involving retrieval from external stores) [15],
[16], Planning Capabilities (for task decomposition and strat-
egy formulation) [13], [17], and Tool Utilization mechanisms
(for interacting with external systems and APIs) [11], [18].
Each component and its interactions within the agent’s oper-
ational loop—perceiving, thinking, and acting—represent a
potential source of latency, making the system’s architecture
a critical determinant of overall responsiveness.
The architectural arrangement of an LLM-based agent’s
core components fundamentally shapes its operational
workflow and, consequently, its latency profile, whether
configured as a single entity or a complex multi-agent
system (MAS) [11], [19]. Simpler Single-Agent Archi-
tectures utilize a solitary LLM to orchestrate perception,
planning, memory access, and tool use [20]. While suitable
for many tasks, latency in these systems arises from the
sequential or iterative execution of LLM inference, mem-
ory retrieval, and tool interactions [21], [22]. In contrast,
Multi-Agent Architectures distribute cognitive load across
multiple LLMs, often specialized for distinct roles (e.g.,
planning, execution, critique) or collaborating hierarchically
or as peers to tackle more complex problems [23], [24],
[25], [26]. While enabling sophisticated capabilities like
simulated social dynamics or large-scale problem decomposi-
tion [27], [28], [29], these architectures introduce significant
inter-agent communication overhead and synchronization
challenges as new latency sources [30]. Regardless of the
paradigm, these architectures empower agents to engage in
complex problem-solving, interact with dynamic environ-
ments (e.g., websites, operating systems) [31], [32], and even
process multi-modal inputs [33]. However, each architectural
choice dictates a unique sequence of operations—LLM calls,
memory operations, tool invocations, and potentially inter-
agent messaging—that collectively contribute to the system’s
end-to-end latency, highlighting the need for targeted opti-
mization strategies.
Response latency in LLM-based agent systems, broadly
defined as the total time from an initial trigger to the agent’s
final output or action, is a critical performance character-
istic whose minimization is paramount for practical utility.
It manifests in various forms, including End-to-End Task
Latency (total time to complete a goal [34]), Time-To-First-
Token (TTFT) (delay until response generation begins [35]),
and Time-Per-Output-Token (TPOT) (speed of subsequent
token generation [35]). High latency across these metrics
profoundly degrades system performance and viability in
several key dimensions:
• Usability and user experience (UX): Slow responses
lead to unnatural interactions, user frustration, and
reduced engagement, hindering adoption even if the
final output is high quality [36], [37], [38].
• Real-time applicability: Many envisioned applica-
tions in robotics, autonomous systems, gaming, and
time-sensitive decision support are fundamentally con-
strained by latency, rendering slow agents ineffective or
unsafe [39], [40], [41].
• Task efficiency and throughput: Agents performing
multi-step reasoning, planning, or iterative refinement
suffer from accumulated delays, significantly extend-
ing task completion times and reducing overall system
throughput [42], [43].
• Economic viability and scalability: Prolonged compu-
tational resource occupancy (e.g., GPUs) due to high
latency translates directly to increased operational costs
and reduced capacity to serve multiple users or tasks
affordably [8], [44].
These pervasive negative impacts elevate latency from a mere
inconvenience to a fundamental barrier, making its mitiga-
tion a primary research and engineering imperative for the
successful deployment of LLM-based agent systems.
Effectively mitigating response latency requires a deep
understanding of its diverse origins within the LLM-based
agent system’s architecture and operational flow. Total
response latency (L total) is not monolithic but rather a com-
posite of delays stemming from various stages of agent
operation. Ltotal in an LLM-based agent system is primar-
ily a function of latencies arising from: (a) Core LLM
Inference (L LLM )), encompassing prompt prefill and autore-
gressive token decoding [45], [46]; (b) Agent Framework
Overhead (Lframework)), including internal logic for planning,
reasoning, memory management, and tool selection [1], [11];
(c) Communication Delays (L comm), involving data transfer
within distributed inference setups, network calls to external
tools/APIs, or inter-agent messaging in MASs [23], [47]; and
(d) System-Level Bottlenecks (Lsystem), such as request queu-
ing, scheduling inefficiencies, resource contention (GPU,
CPU, memory bandwidth), and I/O operations [6], [48].
This multi-faceted nature, where delays can originate from
the foundational model to the supporting infrastructure,

A. SURVEY METHODOLOGY
To ensure a comprehensive and structured review, we con-
ducted a thorough literature search across major academic
databases, including Google Scholar, arXiv, ACM Digital
Library, and IEEE Xplore. Our search strategy employed
a combination of keywords such as ‘‘LLM agent latency,’’
‘‘large language model performance,’’ ‘‘agent system opti-
mization,’’ ‘‘speculative decoding,’’ ‘‘KV cache optimiza-
tion,’’ ‘‘multi-agent communication overhead,’’ and ‘‘LLM
serving systems.’’ We primarily focused on peer-reviewed
conference and journal articles, as well as influential
pre-prints published from 2022 to the present, to capture
the rapidly evolving state-of-the-art. The selection process
involved an initial screening of titles and abstracts, fol-
lowed by a full-text review to include studies that directly
address latency reduction in LLM-based agent systems.
Papers focusing exclusively on LLM training, non-agent sys-
tems, or theoretical aspects without practical performance
implications were excluded. The selected literature was then
categorized and synthesized into the four-layer taxonomy
presented in this survey: Core LLM Inference, Agent-
Level Frameworks, System-Level and Infrastructure, and
Multi-Agent Systems.
This survey provides a comprehensive analysis of state-
of-the-art techniques to minimize response latency in
LLM-based agent systems, offering unique contributions to
guide research and practice in this critical area. The primary
objective is to identify, categorize, and review strategies for
latency reduction across all facets of agent operation, from
core model execution to complex multi-agent interactions.
The scope encompasses optimizations at the level of: (1)
Core LLM inference (e.g., compression, efficient architec-
tures, decoding algorithms) [6], [49]; (2) Agent-level logic
(e.g., planning, tool use, memory management) [13], [15];
(3) System infrastructure (e.g., serving systems, hardware
acceleration, resource management) [50], [51]; and (4) MASs
(e.g., communication, coordination) [23]. This survey makes
the following key contributions: it offers a consolidated
knowledge base for a rapidly evolving and critical problem;
it presents a structured taxonomy of latency sources and mit-
igation techniques spanning the full agent stack; it provides
experimental validation of core optimization techniques; and
it identifies significant unresolved challenges and promis-
ing future research directions towards achieving ultra-low
latency.
The practical significance of this challenge extends far
beyond technical benchmarks: LLM-based systems are
increasingly deployed across diverse real-world domains
that directly affect everyday life. These include clinical
decision support, automated educational assessment using
zero-shot LLM inference [52], mental health monitoring
through social media analysis [53], multimodal disaster iden-
tification in low-resource settings [54], and misinformation
detection [55]. In such applications, response latency directly
impacts user safety, decision quality, and operational cost—
for instance, a healthcare agent that takes minutes to respond
may compromise patient outcomes, while a disaster-response
agent must process multimodal inputs in near real-time to be
actionable. These practical demands underscore the critical
importance of the optimization techniques surveyed in this
work.
To ground our discussion, we will use a running example
throughout this survey: a ‘Healthcare Diagnostic Agent’. This
agent’s task is to respond to a user query like, ‘Evaluate my
symptoms.’ The agent must understand the request, decom-
pose it (e.g., 1. Check Guidelines, 2. Find Appointments,
3. V erify Drug Interactions), interact with multiple external
tools (e.g., a medical DB API, a hospital API, and a phar-
macy API), synthesize the results, and generate a coherent
care plan. The end-to-end latency of this process—from the
user’s query to the final care plan—is a critical determinant
of its usability, especially in time-sensitive health inquiries.
A delay of many minutes would render such an agent imprac-
tical and potentially unsafe. This example will illustrate the
various sources of latency and the impact of optimization
strategies at each layer of the agent stack.

II. CHARACTERIZING AND DECONSTRUCTING LATENCY
IN LLM AGENT SYSTEMS
To effectively minimize latency in LLM-based agent sys-
tems, a precise understanding of its constituent components
is essential, as optimizing isolated parts may yield subopti-
mal overall improvements if primary bottlenecks elsewhere
in the agentic workflow are ignored. This section decon-
structs the end-to-end response latency by defining its
scope and then analyzing it into five primary source cat-
egories: core LLM inference, agent framework overhead,
tool and API interactions, broader communication delays,
and system-level bottlenecks. Table 1 summarizes these key
components, their definitions, and their primary influencing
factors. Figure 1 illustrates the general operational loop and
the interplay of these abstract latency components. To make
these abstract components concrete, we will use our run-

the targeted optimization strategies discussed in subsequent

A. DEFINING THE SCOPE: END-TO-END LATENCY IN
AGENT SYSTEMS
End-to-end response latency in LLM-based agent systems
encompasses the total duration from an initial trigger—
such as a user request or environmental change—to the
agent’s final response or completed action [11]. This holis-
tic metric is critical as it reflects the true user-perceived
delay and overall system efficiency, unlike isolated LLM
inference time. Latency accumulates throughout a typical
agent interaction flow, which generally involves: (1) request
reception and parsing; (2) an initial cognitive cycle, often
involving LLM calls for goal understanding and high-level
planning [13], [18]; (3) iterative loops of detailed plan-
ning, task decomposition [17], [56], memory operations
(retrieval/storage) [15], [16], tool selection and execu-
tion [28], [57], information synthesis, and reflection [58],
[59]; and finally, (4) response generation or final action exe-
cution. Understanding this comprehensive operational lifecy-
cle, where delays compound across multiple computational
and interactional stages, is fundamental for identifying and
addressing the most significant contributors to overall agent
latency.

C. AGENT FRAMEWORK OVERHEAD: THE COST OF
AUTONOMY
Beyond core LLM inference, the agent’s internal operational
logic—its framework for planning, memory management,
and tool handling—introduces significant computational
overhead, termed the ‘‘cost of autonomy’’ (L framework) [3].
This latency arises from several key activities: (1) Task plan-
ning and reasoning cycles, which involve decomposing goals,
formulating strategies using heuristics or dedicated LLM
calls, iterative refinement, reflection, and self-correction[67],
[68], [69], [70]; (2) Memory management operations, includ-
ing context window maintenance through summarization
or selective retrieval from short-term and long-term mem-
ory stores (e.g., vector databases), and state updates [15],
[71]; and (3) Tool selection and parameter determination,
where the agent identifies appropriate external tools, possibly
via LLM consultation, and prepares necessary inputs [9],
[42], [72]. These internal framework computations, occurring
between or alongside LLM calls, contribute substantially
to end-to-end latency and require specific optimization
strategies. For the Healthcare Agent, Lframework represents the
time spent between API calls, where the agent’s logic decides
which tool to use next (e.g., choosing ‘Appointment search’
after ‘Clinical guide’) and processes the results from the
previous step (Figure 2).
D. TOOL USE AND EXTERNAL API INTERACTION LATENCY
Interactions with external tools and Application Program-
ming Interfaces (APIs) are vital for LLM agents to ground
their actions and access specialized functionalities [32],
[73], but these introduce distinct latency components ( Ltool).
This overall tool interaction latency comprises three main
parts: (1) Network delay, characterized by the Round-Trip
Time (RTT) for the API request and response, influenced
by factors like distance and network congestion [74], [75],
[76]; (2) Tool/API execution time, which is the dura-
tion the external service takes to process the request,
varying widely with tool complexity and workload [77],
[78]; and (3) Framework overhead for interaction man-
agement, encompassing local processing for request mar-
shalling/serialization, response parsing/deserialization, and
robust error handling [32]. The cumulative impact of these
delays can be substantial, particularly for agents heavily
reliant on sequential or frequent tool invocations, making
optimization of the entire tool-use cycle crucial for respon-
sive performance. Healthcare Agent’s Ltool is the sum of the
time spent waiting for external APIs to return clinical guide-
lines, hospital appointments, and drug interaction results
(Figure 2).
E. COMMUNICATION DELA YS: NETWORKING AND DATA
TRANSFER
Communication overheads (L comm), distinct from API call
RTTs, arise from the movement of data within the agent sys-
tem’s infrastructure and between its distributed components,
significantly impacting latency. These delays manifest in
three primary contexts: (1) Internal data transfer in distributed
LLM inference, where transferring model parameters, acti-
vations, and KV cache states across multiple GPUs or nodes
via interconnects (e.g., NVLink, InfiniBand) introduces sub-
stantial overhead, especially for large models [46], [80], [81];
(2) External data transfer with tools/APIs, where latency is
incurred from serializing/deserializing large data payloads
exchanged with external services, compounding network
transit times [82], [83]; and (3) Inter-agent communication in
MAS, where message passing between collaborating agents
over networks introduces delays due to protocol inefficiency,
message volume, and synchronization requirements [23],
[84], [85]. Optimizing these diverse data transfer pathways
is essential for mitigating communication-induced latency
across the agent system. If the Healthcare Agent’s inference
is distributed across multiple GPUs, Lcomm would be the time
taken to transfer KV cache states between them during the
final response generation (Figure 2).
F. SYSTEM-LEVEL BOTTLENECKS: SCHEDULING,
CONTENTION, AND INFRASTRUCTURE
The underlying system-level infrastructure introduces criti-
cal latency bottlenecks (L system) related to request handling,
resource allocation, and hardware limitations, often defining
the practical ceiling for agent responsiveness. Key con-
tributors include: (1) Request handling inefficiencies, such
as queuing delays before processing begins and subopti-
mal scheduling algorithms (e.g., FIFO causing head-of-line
blocking) that fail to prioritize latency-sensitive agent
tasks [47], [50]; (2) Resource contention, where concurrent
agent requests compete for limited GPU compute, CPU
cycles, or memory bandwidth, leading to increased execution
times [6], [51], [86]; (3) I/O limitations, particularly the
overhead of offloading or swapping large KV caches between
GPU HBM and slower CPU memory or storage during long
interactions [6], [87]; and (4) Power management constraints,
which can trigger thermal throttling and reduce hardware
clock speeds under heavy load, directly increasing task
latency [86]. Addressing these system-level factors through
careful infrastructure design, advanced resource manage-
ment, and optimized scheduling is crucial for building truly
low-latency LLM agent systems. If multiple users submit
health queries simultaneously, our agent’s request might wait
in a queue, contributing to Lsystem before processing even
begins (Figure 2).

A. QUANTIZATION TECHNIQUES FOR REDUCED
PRECISION INFERENCE
Quantization reduces the numerical precision of an LLM’s
weights, activations, and KV cache, typically converting from
16/32-bit floating-point formats to lower-bit integers (e.g.,
INT8, INT4) or specialized floating-point formats (e.g., FP8).
This reduction in data size yields significant latency benefits
by: (1) decreasing the memory footprint, crucial for large
models and long contexts; (2) lowering memory bandwidth
requirements, which directly accelerates the memory-bound
decoding phase (reducing TPOT); and (3) enabling faster
computations on hardware with native low-precision sup-
port. Common methodologies include Post-Training Quan-
tization (PTQ), which is simpler to implement but may
incur accuracy loss, especially at very low bit-widths; and
Quantization-Aware Training (QA T), which integrates quan-
tization into training to better preserve accuracy at the cost
of retraining complexity. Strategic application to weights,
activations, or the KV cache offers varying degrees of
speedup, with KV cache quantization being particularly
effective for TPOT reduction. Advanced techniques like
mixed-precision, blockwise (e.g., GPTQ [79], AWQ [88]),
or hardware-aware quantization offer further refinements,
though all quantization approaches involve a fundamen-
tal trade-off between efficiency gains and potential model
quality degradation that necessitates careful evaluation. The
latency benefits of quantization are significant. As shown in
Table 2, for example, applying 3-bit GPTQ to the OPT-175B
model reduces the average per-token latency from 230 ms to
71 ms. This speedup is especially impactful as it also enables
a massive reduction in hardware requirements, running on
a single NVIDIA A100 GPU compared to the five required
for the FP16 baseline. In practice, tools like AutoGPTQ [89]
and bitsandbytes [90] provide ready-to-use implementations
of these quantization methods with seamless integration
into the HuggingFace Transformers ecosystem [91], signif-
icantly lowering the barrier to deploying quantized models in
production agent systems.
However, the trade-off between efficiency and model
quality necessitates a careful, context-aware application of
quantization. For agents primarily focused on tasks with high
factual precision or complex reasoning (e.g., a legal analysis
agent), aggressive quantization like INT4 could degrade the
nuanced capabilities of the foundational model, leading to
incorrect or unreliable outputs. In such scenarios, a more
conservative approach like bfloat16, or hybrid strategies that
apply stronger quantization only to less sensitive parts of
the model, may be a more prudent choice to balance latency
reduction with task-critical accuracy.

REDUCTION
Pruning and sparsity techniques reduce the number of LLM
parameters by removing redundant or less important weights,
leading to smaller and faster models. This reduction directly
lowers inference latency by decreasing memory bandwidth
usage (fewer parameters to load) and reducing the number of

pression with task performance, often necessitating hardware
co-design.
C. KNOWLEDGE DISTILLATION FOR MODEL
COMPRESSION
Knowledge Distillation (KD) transfers capabilities from a
large ‘‘teacher’’ LLM to a smaller, more efficient ‘‘student’’
model, aiming to reduce size and computational requirements
for lower inference latency [6]. The student model is trained
to mimic the teacher’s output distributions (logits) or internal
representations, capturing ‘‘dark knowledge’’ beyond simple
label supervision. Successful KD yields significantly smaller
student models, leading to: (1) reduced memory footprint for
weights and KV cache, beneficial for resource-constrained
deployment [92]; (2) lower computational cost (FLOPs);
and (3) consequently, reduced TTFT and TPOT [6]. For
agents, this accelerates the entire operational loop. While
KD often involves a trade-off between compression and stu-
dent performance—as students rarely perfectly match teacher
capabilities—it can be combined with quantization and prun-
ing for further gains [6], offering a valuable path to faster,
deployable agent systems.
Beyond computational efficiency, KD also offers advan-
tages for learning under data constraints. The principles of
knowledge distillation also connect to broader research on
learning with low-resource data [93], where techniques like
active sampling and PAC generalization theory provide theo-
retical foundations for achieving efficient learning under data
scarcity—a scenario increasingly relevant for agent systems
that must adapt to new domains with limited fine-tuning
data. These connections suggest potential synergies between
distillation-based compression and low-resource adaptation
strategies, particularly for deploying efficient agents in spe-
cialized domains where training data is scarce.
D. EFFICIENT MODEL ARCHITECTURES AND ATTENTION
VARIANTS
Optimizing the LLM’s inherent architecture offers another
path to reduced latency by lowering computational load
or memory bandwidth requirements during inference.
Mixture-of-Experts (MoE) architectures replace dense
feed-forward layers with multiple specialized ‘‘expert’’ sub-
networks and a gating mechanism that routes each token
to a small subset of experts. This conditional computation
reduces FLOPs per token, scaling inference cost with active
expert size rather than total parameters, thus lowering latency,
though MoE models have large total parameter counts and
introduce system complexities like load balancing. A second
critical area involves optimizing the attention mechanism,
a primary bottleneck due to KV cache demands. Multi-
Query Attention (MQA) drastically reduces KV cache size
and memory bandwidth by having all attention heads share
a single Key and V alue projection, significantly improving
TPOT but potentially impacting model quality. Grouped-
Query Attention (GQA) offers a balance, grouping heads to
share K/V projections, yielding substantial TPOT improve-
ments over standard Multi-Head Attention (MHA) while
often preserving more quality than MQA. These architectural
innovations, particularly MQA/GQA, are crucial for acceler-
ating token generation in agent tasks requiring long outputs.
E. FASTER DECODING ALGORITHMS: SPECULATIVE AND
PARALLEL APPROACHES
To overcome the inherent sequential bottleneck of autore-
gressive decoding, especially for long outputs common in
agent systems [94], advanced decoding algorithms aim to
generate multiple tokens concurrently. Speculative decoding
is a prominent ‘‘draft-then-verify’’ strategy: a smaller, faster
‘‘draft’’ model proposes candidate future tokens, which are
then verified in parallel by the larger target LLM; if validated,
multiple tokens are accepted in a single step, accelerating
generation [94].
Figure 4 contrasts this ‘‘draft-then-verify’’ approach with
standard autoregressive decoding. For our Healthcare Agent
(Figure 2), when generating the final care plan, a draft model
could propose common phrases like ‘Base on your symptoms,
the clinical guideline suggests. . . ’ or ‘A potential interaction
was found. . . ’ which the main LLM can then quickly verify.
Effectiveness hinges on draft model accuracy, with frame-
works like Chimera optimizing draft model creation [95].
Self-speculative decoding variants reduce overhead by using
components of the target LLM itself for drafting, such
as intermediate layer representations or early-layer hid-
den states [96], [97]. More advanced methods like staged
speculative decoding or blockwise parallel decoding further
refine parallel token generation [94], [98]. These tech-
niques significantly reduce wall-clock generation time, often
losslessly [95], [98], and are vital for interactive agent respon-
siveness.
The effectiveness of speculative decoding is fundamen-
tally tied to the predictability of the generation task. While
it yields significant speedups in scenarios with structured
or repetitive outputs (e.g., code generation, data entry),
its utility can diminish for agents requiring high degrees
of creativity or navigating open-ended dialogues. In these

F. EARL Y EXIT AND LA YER SKIPPING STRATEGIES
Early exit and layer skipping strategies reduce average
latency per token by dynamically adjusting the computa-
tional effort within each decoding step based on perceived
input complexity [49]. Early exit mechanisms incorporate
auxiliary prediction heads at intermediate LLM layers; if
an intermediate prediction meets a confidence threshold,
computation exits early, bypassing subsequent layers and
reducing latency for ‘‘simpler’’ tokens [6]. Layer skipping
dynamically bypasses specific layers or blocks, conditioned
on intermediate states or static profiling, thereby reducing
FLOPs per step [86]. Both approaches lower the average
computational cost per token, enhancing agent responsive-
ness, but require careful calibration of exit/skipping criteria
to balance speed gains against potential degradation in output
quality due to shallower processing. These methods primar-
ily address computational cost, complementing techniques
focused on memory overhead.

H. KV CACHE OPTIMIZATION: EVICTION AND
COMPRESSION
KV Cache Eviction policies selectively discard entries when
the cache approaches size limits, aiming to remove the least
critical information. Simple recency-based eviction (e.g.,
FIFO, sliding window) discards the oldest entries but may
lose vital early context. More sophisticated importance-based
eviction attempts to estimate entry relevance using signals
like past attention scores, token importance heuristics (e.g.,
‘‘Heavy Hitters’’) [99], [100], or structural properties of
attention heads, thereby minimizing impact on generation
quality [101].
KV Cache Compression techniques reduce the storage
size of each retained KV entry, decreasing overall memory
footprint and bandwidth usage. Quantization (Section III-A)
lowers the numerical precision of cached tensors (e.g.,
to INT8/INT4) [102]. Other methods exploit structural redun-
dancy, using online clustering of keys (e.g., SubGen [103]),
sentinel/anchor tokens for context summarization [104],
[105], or prefix sharing for common histories in batched
requests (e.g., ChunkAttention [106], RelayAttention [107]).
Among production serving systems, vLLM [64] exempli-
fies effective KV cache optimization through its PagedAt-
tention mechanism, which virtualizes the KV cache into
non-contiguous memory blocks, nearly eliminating fragmen-
tation. This open-source serving framework has become
widely adopted in practice due to its substantial perfor-
mance improvements (as shown in Table 2) and ease of
integration with standard HuggingFace models [91]. Lossless
compression algorithms, like LoMA [108], train models to
operate on compressed cache representations. These evic-
tion and compression strategies, often complementary, are
vital for enabling LLM agents to efficiently handle long
sequences with lower TPOT, though they may require careful
tuning or accept quality trade-offs. The impact of efficient

Beyond optimizing the core LLM inference, substantial

C. ADAPTIVE AND LATENCY-AWARE CONTEXT AND
MEMORY MANAGEMENT
Efficiently managing an agent’s internal memory and
the LLM’s context window is critical for minimizing
LLLM (specifically prefill latency, which scales with input
length [6]) and Lframework associated with memory oper-
ations. Naively appending history to the context window
leads to escalating prefill costs and exceeding context lim-
its [113]. Beyond conventional rule-based summarization
and similarity-based retrieval, recent research has introduced
sophisticated learned techniques—including reinforcement
learning-based memory prioritization and neural architecture
search for context compression—that explicitly optimize the
latency-quality trade-off in memory management. We first
discuss these emerging advanced techniques before covering
foundational strategies.
1) ADVANCED MEMORY MANAGEMENT TECHNIQUES:
LEARNED OPTIMIZATION
Recent advances in agent memory systems have moved
beyond static heuristics to leverage machine learning for
dynamic optimization of memory selection and compres-
sion. Two particularly promising directions are reinforcement
learning-based memory prioritization and neural architecture
search for context compression, both of which explicitly
model and optimize the trade-off between context length
(which determines LLLM ) and downstream task performance.
2) REINFORCEMENT LEARNING-BASED MEMORY
PRIORITIZATION
Traditional memory retrieval systems typically rely on static
similarity metrics (e.g., embedding cosine similarity) or sim-
ple recency heuristics to decide which memories to inject into
the LLM’s context window. However, these approaches treat
all memories with similar embeddings as equally important
and do not account for the dynamic relevance of information
across different stages of task execution or the downstream
impact on agent performance.
Reinforcement learning-based memory prioritization
addresses these limitations by learning a parameterized policy
that assigns importance scores to memory entries based on
their expected utility for future agent actions [15], [16]. The
general framework operates as follows:
• State representation: At each decision point, the agent’s
current task state, goal, and a set of candidate memory
entries (retrieved via initial filtering, e.g., semantic sim-
ilarity) are encoded into a state representation.
• Learned scoring model: A lightweight neural network
(the ‘‘memory scorer’’) takes this state representation
along with features of each candidate memory (e.g.,
recency, access frequency, embedding similarity to cur-
rent context, metadata) and outputs a scalar importance
score for each memory entry.
• Memory selection: The top-k memories with highest
scores are selected for inclusion in the LLM’s context
window, where k is chosen to satisfy a context length
budget.
• Reinforcement learning training: The memory scorer is
trained via reinforcement learning, where the reward
signal combines two components: (a) task success met-
rics (e.g., goal achievement, output quality), which
incentivize selecting useful memories, and (b) latency
penalties proportional to context length, which incen-
tivize compact memory selection. This multi-objective
reward encourages the model to learn which memories
are truly essential for task performance and which can
be safely omitted to reduce LLLM .
The latency benefits are substantial. By learning to identify
and select only the most task-critical memories, RL-based
prioritization can reduce context length by 30–50% compared
to naive top-k similarity retrieval while maintaining or even
improving task performance, as the learned policy adapts
to the specific requirements of different task phases [15].
The computational overhead of the scoring model itself is
typically negligible (a few milliseconds for a small neural
network) compared to the prefill latency savings from shorter
contexts (which can be hundreds of milliseconds to seconds
for very long contexts).
3) NEURAL ARCHITECTURE SEARCH (NAS) FOR CONTEXT
COMPRESSION
An orthogonal approach to managing long contexts is to
learn a compression function that encodes extensive historical
information into a compact, information-dense representation
that can be efficiently processed by the LLM. Neural Archi-
tecture Search methods have been applied to automatically
discover optimal architectures for such context compression
models [71].
The NAS-based compression paradigm works as follows:
• Compression model architecture space: A search space
of possible encoder architectures is defined, including
choices such as: number and type of layers (e.g., trans-
former blocks, convolutional layers), attention mecha-
nisms and their configurations, bottleneck dimensions
for the compressed representation, and the number of
output ‘‘summary tokens’’ that will represent the com-
pressed context.
• Architecture search process: The NAS algorithm
(e.g., evolutionary search, reinforcement learning-based
search, or differentiable architecture search) explores
this space by training and evaluating numerous can-
didate architectures on a validation set of agent tasks.
Each candidate is assessed on two criteria: (a) the qual-
ity of the compressed representation, measured by the
LLM’s downstream task performance when using the

[[page 14]]
G. Park et al.: Minimizing Response Latency in LLM-Based Agent Systems: A Comprehensive Survey
compressed context, and (b) the size of the compressed
representation and the inference latency of the compres-
sion model itself.
• Deployment: Once an optimal compression architec-
ture is identified, it is trained on a large corpus of
agent interaction histories. During inference, the agent
first processes long-context information (e.g., extensive
conversation history, retrieved documents) through this
learned compression model to produce a compact rep-
resentation (e.g., 50–100 summary tokens instead of
5,000–10,000 original tokens), which is then fed to the
LLM for reasoning and generation.
The latency implications are significant for agents deal-
ing with very long contexts. While the compression
step introduces some overhead (an Lframework of typically
50–200 ms for a well-optimized compression model), this
is far outweighed by the reduction in LLM prefill latency
when contexts are very long. For instance, compressing a
10,000-token context to 100 tokens could reduce prefill time
from∼2 seconds to∼20 ms on a high-end GPU, yielding a
net latency reduction of over 90% even after accounting for
compression overhead. The compression model can often be
implemented as a smaller, distilled encoder network, further
minimizing its latency contribution.
4) PRACTICAL CONSIDERATIONS AND CURRENT
LIMITATIONS
Both RL-based prioritization and NAS-based compression
represent cutting-edge research directions with substantial
potential but also important practical considerations:
• Implementation complexity: RL-based methods require
careful design of reward functions, training infrastruc-
ture, and exploration strategies. NAS methods demand
significant computational resources for architecture
search (though this is a one-time offline cost).
• Scenario dependence: These techniques provide the
greatest benefits for agents handling very long contexts
(> 4K tokens) or with access to large-scale memory
stores. For simpler tasks or shorter interactions, tra-
ditional summarization and selective retrieval remain
more practical and cost-effective.
• Generalization: Learned memory management models
may require domain-specific training or fine-tuning to
generalize effectively across different task types, though
recent work suggests that memory prioritization poli-
cies can transfer reasonably well within broad task
families [16].
• Emerging research stage: While the conceptual frame-
works and initial implementations exist in the research
literature (particularly for RL-based approaches [15]),
widespread production deployment is still emerging.
We expect that as the field matures, pre-trained, reusable
memory management models—analogous to pre-trained
LLMs—will become available, significantly lowering
the barrier to adoption.
These advanced learned techniques represent the fron-
tier of memory optimization research and complement the
foundational strategies discussed in the following para-
graphs, offering additional sophisticated levers for optimiz-
ing the latency-quality trade-off in memory-intensive agent
applications.
5) FOUNDATIONAL MEMORY MANAGEMENT STRATEGIES
Dynamic context summarization, where agents condense
older or less relevant information using LLMs (potentially
smaller ones) or rule-based methods, reduces token count for
subsequent LLM calls, thereby lowering prefill latency while
aiming to preserve essential information. Selective informa-
tion retrieval from external short-term or long-term memory
stores (e.g., vector databases [15]) injects only relevant infor-
mation into the prompt, avoiding the processing of overly
long, irrelevant contexts; techniques like interactive reading
enable agents to query structured representations of large
contexts (e.g., summary trees [71]) to optimize for relevance
and latency. Hierarchical memory systems, balancing access
speed and storage capacity, further structure these retrieval
strategies. Minimizing latency in accessing, updating, and
switching internal agent states is also vital, with OS-inspired
frameworks like AIOS focusing on efficient lifecycle and
memory management [50]. Such adaptive strategies directly
reduce the data burden on the LLM and the overhead of
memory access within the agent.
These memory management strategies share conceptual
foundations with low-resource learning paradigms [93],
where efficient utilization of limited data parallels the chal-
lenge of managing constrained context windows. Techniques
such as LLM-powered optimization under data scarcity and
active sampling can inform more sophisticated memory
prioritization strategies that maximize information utility
while minimizing latency overhead. The theoretical insights
from PAC generalization bounds, which characterize learning
efficiency under data constraints, may similarly guide the
development of principled approaches for selecting which
context elements to retain when window capacity is limited.

E. STREAMLINING AGENT EXECUTION FLOWS AND
ADAPTIVE CONTROL
For complex problems requiring multi-step execution
sequences involving planning, action, observation, and
refinement, streamlining the entire dynamic operational flow
is critical to reduce cumulative latency. This involves optimiz-
ing action sequencing, feedback integration, and adaptation
mechanisms. Efficient action sequencing and paralleliza-
tion, such as decomposing tasks into parallelizable sub-tasks
managed by specialized agents [68] or decoupling abstract
reasoning from tool calls (e.g., Chain-of-Abstraction [116]),
can reduce the critical path length. Rapid incorporation of
feedback and plan adaptation is essential to avoid costly
full replanning cycles; AdaPlanner, for instance, enables
LLM agents to refine plans based on environmental feedback
through in-plan or out-of-plan adjustments using efficient
code-style prompts [109]. For significant deviations, adaptive
replanning frameworks like Reasoning via Planning (RAP),
which use the LLM as a world model and MCTS for strate-
gic exploration, can efficiently find alternative high-reward
action paths [117]. Minimizing latency in iterative refine-
ment and self-correction loops is also vital; techniques like
learning internalized utility judgments (e.g., RadAgent[118])
or reusing successful past plans (‘‘skills’’ [109], [119]) can
shortcut these cycles. These strategies collectively reduce
accumulated delays in complex, multi-step agent operations
by making the execution flow more efficient and adaptive.
F. LATENCY-OPTIMIZED AGENT ARCHITECTURES AND
FRAMEWORKS
The overarching architectural design of an agent system and
its development framework provides the structural founda-
tion for implementing responsive behaviors and mitigating
bottlenecks from complex control flows and resource con-
tention. Architectures balancing reactivity and deliberation
(akin to ‘‘thinking fast and slow’’) optimize average-case
latency by using fast, reflexive pathways for routine actions
and reserving sophisticated LLM deliberation for complex
tasks. Modular design principles, such as representing agent
workflows as optimizable computational graphs (e.g., GPT-
SW ARM[120]), facilitate parallel execution of sub-tasks and
targeted node-level or edge-level optimizations. Decompos-
ing capabilities into specialized functional units, potentially
handled by different or smaller LLM instances[28], enhances
parallelism and efficiency. Operating system-like frameworks
(e.g., AIOS [50]) directly address latency by providing
mechanisms for optimal scheduling of agent requests to
LLMs, efficient resource allocation, and streamlined context
switching. Distributed multi-agent architectures, supported
by platforms for asynchronous interaction [121] or opti-
mized orchestration [122], can reduce latency for large-scale
problems by distributing workload and enabling parallel
problem-solving. Well-designed development and evalua-
tion frameworks further support latency optimization by
simplifying construction and enabling detailed performance
profiling [123], [124]. These architectural choices and frame-
works are pivotal in creating a system capable of realizing the
benefits of other agent-level latency reduction strategies.
V. SYSTEM-LEVEL AND INFRASTRUCTURE
OPTIMIZATIONS FOR LOW-LATENCY DEPLOYMENT
Effective minimization of end-to-end latency in LLM-based
agent systems extends beyond model-centric (Section III)
and agent-logic (Section IV) optimizations to encompass
the underlying system-level infrastructure. This infrastruc-
ture, responsible for hosting, managing, and orchestrating
agent operations, significantly influences overall responsive-
ness by introducing ‘‘System-Level Bottlenecks’’ (L system)
and ‘‘Communication Delays’’ (L comm). This section sur-
veys critical system-level and infrastructure optimizations,
including advanced LLM serving techniques, hardware
acceleration, dynamic resource management, distributed
deployment architectures, network-level enhancements, and
scalable deployment frameworks, all crucial for achieving
consistently low latency in practical agent deployments.
A. ADVANCED LLM SERVING SYSTEMS AND REQUEST
MANAGEMENT
Sophisticated LLM serving systems are crucial for managing
the highly variable and often interactive workloads gener-
ated by agent systems [2], [11], directly mitigating Lsystem
components like queuing delays and scheduling inefficien-

requests at a finer granularity than static batching, dynam-

hardware (e.g., GPU) utilization and improve throughput,
thereby reducing average latency [35], [48]. For instance,
if many users are using the Healthcare Agent simultaneously,
a serving system with continuous batching can process their
various requests (some diagnosing symptoms, some booking
appointments) more efficiently than waiting to form a static
batch (Figure 2).
Optimized request scheduling algorithms, employing pre-
emption or Quality-of-Service (QoS) prioritization, ensure
responsiveness for critical agent functions by managing
diverse demands more effectively than simple FIFO sched-
ulers [44], [47]. Efficient KV cache management at the

B. HARDWARE ACCELERATION AND CO-DESIGN FOR
AGENT SYSTEMS
The raw speed of underlying hardware executing LLM
requests and agent logic fundamentally constrains achiev-
able latency, making effective use of specialized hardware
paramount. GPUs and TPUs, with their massively parallel
architectures, excel at accelerating the prefill and decod-
ing phases of LLM inference (L LLM ) [43], [64]. Emerg-
ing AI accelerators like NPUs for power-efficient edge
inference [125] and reconfigurable FPGAs for customized
computations offer further avenues for latency reduction.
Critically, hardware-software co-design, tailoring software
(LLM architecture, compilers, runtimes) to exploit spe-
cific hardware features (e.g., native low-precision arithmetic
for quantization [88], [126], [127], conditional computa-
tion for MoE models), unlocks an ‘‘acceleration efficiency
boost’’. This co-design extends beyond core LLM inference
to accelerate peripheral agent tasks such as data pre/post-
processing or tool interaction marshalling [128], thereby
reducing Lframework and Ltool. High-performance memory
systems and interconnects are also vital, as memory band-
width and data transfer speeds directly impact overall agent
system latency, especially for large models or distributed
multi-agent interactions [129].
C. DYNAMIC RESOURCE ALLOCATION, PROVISIONING,
AND LOAD BALANCING
Efficiently managing computational and memory resources
is essential for consistent low-latency performance, partic-
ularly given the unpredictable workloads of agent systems.
Dynamic resource allocation strategies enhance ‘‘resource
management efficiency’’ by adapting to fluctuating demands,
thereby mitigating Lsystem from resource contention and
queuing. Predictive auto-scaling anticipates future resource
needs based on workload patterns or request characteristics,
proactively adjusting agent instances or GPU allocations to
absorb traffic bursts [130]. Fine-grained resource allocation
addresses the heterogeneous requirements of agent compo-
nents (e.g., GPU-heavy LLM inference, CPU-intensive plan-
ning), potentially disaggregating prefill/decode phases onto
specialized resources or dynamically allocating resources
based on predicted task needs [35], [131], [132]. Intelli-
gent load balancing distributes requests efficiently across
available resources, considering server load, network latency,
and task characteristics, using techniques from history-based
methods to adaptive learning algorithms [133], [134], [135].
Effective QoS management, through resource isolation and
prioritization, ensures that high-priority agent interactions
meet latency targets even under heavy system load [44], [47].
D. DISTRIBUTED AND HYBRID DEPLOYMENT
ARCHITECTURES (CLOUD, FOG, EDGE)
Strategically deploying agent systems across the compute
continuum, such as cloud, fog, and edge, offers ‘‘deploy-
ment flexibility’’ to minimize network latency (L comm) and
improve responsiveness by placing computation closer to
users or data sources. Centralized cloud deployments offer
abundant resources but can incur high network latency for
remote interactions [76]. Edge-centric deployments, often
using smaller on-device models, minimize local network
latency for real-time applications like robotics but face
resource constraints [38], [92], [136]. Edge deployments
often face additional constraints related to limited training
data for domain adaptation. Recent advances in low-resource
learning [93] provide complementary strategies for effi-
cient adaptation, including few-shot prompting techniques
that align well with the latency and resource constraints of
edge environments. The intersection of low-resource learn-
ing theory with edge-optimized inference presents promising
opportunities for developing agent systems that can rapidly
adapt to new deployment contexts without requiring exten-
sive fine-tuning data or computational resources. Hybrid
and hierarchical architectures, strategically combining cloud,
fog, and edge resources (e.g., complex tasks in the cloud,
latency-critical functions at the edge [111]), often provide the

most effective balance. Realizing these benefits depends on
intelligent placement and dynamic offloading of agent com-

and computational needs, often managed by coordination
frameworks [137], [138]. Managing data consistency and
locality across distributed tiers, through efficient synchro-

E. NETWORK-LEVEL OPTIMIZATIONS AND EFFICIENT
DATA COMMUNICATION
The efficiency of communication pathways between dis-
tributed agent components is paramount for minimizing
Lcomm, as network bottlenecks can negate other optimiza-
tions. ‘‘Communication efficiency maximization’’ involves
several strategies: (1) Minimizing data volume through
efficient serialization formats (e.g., Protocol Buffers) and
data compression, reducing transmission time, especially
over bandwidth-constrained edge links. (2) Optimizing
transport protocols, using modern options like gRPC or
QUIC for inter-service communication, and leveraging
hardware-accelerated technologies like RDMA or GPUDi-
rect RDMA for high-performance data transfer between
nodes, significantly reducing internal communication latency
in distributed inference [80]. (3) Employing latency-
aware routing, potentially via Software-Defined Network-
ing (SDN), to configure optimal network paths based on
real-time conditions and application needs, avoiding con-
gestion. (4) Strategic caching of frequently accessed data
(e.g., tool API responses, common LLM queries) at locations
closer to the agent (edge/fog nodes) to reduce repeated data
transfers and backend load [152]. These network-level opti-
mizations are crucial for realizing the low-latency potential
of distributed agent systems.
F. CONTAINERIZATION, ORCHESTRATION, AND SCALABLE
DEPLOYMENT FRAMEWORKS
‘‘Deployment automation and scalability’’ are key to main-
taining low latency in operational agent systems, especially
under dynamic loads and across distributed environments.
Containerization technologies like Docker and WebAssem-
bly (Wasm) encapsulate agent components into portable
units, simplifying deployment and dependency management.
Orchestration platforms such as Kubernetes automate the
deployment, scaling, and management of these container-
ized applications, directly impacting latency by managing
resource allocation, load balancing, and high availabil-
ity [86], [153]. Adopting a microservice architecture, where
agent functionalities (planning, memory, tool use) are decom-
posed into independently deployable services [28], [120],
aligns well with orchestration capabilities, allowing targeted
scaling and optimized resource utilization, thereby reducing
contention and Lsystem. Automated horizontal scaling, a core
orchestrator feature, ensures responsiveness during peak
demand by adjusting service instances based on monitored
metrics. Orchestrators also provide service discovery and
health monitoring, crucial for reliable inter-component com-
munication in complex agent operations. Lightweight orches-
tration platforms (e.g., K3s, KubeEdge) extend these capa-
bilities to resource-constrained edge devices, supporting
latency-sensitive distributed deployments.

VI. MANAGING LATENCY IN MULTI-AGENT LLM
SYSTEMS
MASs built with LLMs introduce unique latency chal-
lenges beyond those in single-agent setups, primarily due
to the overheads of inter-agent interaction and coordina-
tion [23], [155]. While MASs offer benefits like parallel
execution and specialized capabilities, the communication
and synchronization required for collaboration can become
significant bottlenecks, compounding core LLM and indi-
vidual agent framework latencies. This section characterizes
these MAS-specific latency sources and surveys strategies to
mitigate them, focusing on efficient communication, latency-
aware coordination, optimized parallel execution, responsive
architectures, and management of heterogeneity. Table 10
succinctly maps these unique latency challenges in MAS to
their corresponding mitigation strategies, which are elabo-
rated upon in the following subsections.
A. CHARACTERIZING LATENCY SOURCES IN
MUL TI-AGENT INTERACTIONS
The shift to multi-agent architectures introduces distinct
collaborative latency components that can dominate overall
system response time. Key sources include: (1) Inter-
Agent Communication Round Trips (RTTs), encompass-
ing network latency, message serialization/deserialization,
and LLM-based message processing [30], [156]; (2) Syn-
chronization Overhead, where agents idle while awaiting
information, consensus, or coordinated actions [30], [85];
(3) Coordination Protocol Delays, stemming from the compu-
tational cost of algorithms for distributed planning, strategy
formation, or conflict resolution, often involving multiple
LLM calls [156], [157]; (4) Cascading Delays in Depen-
dent Tasks, where delays in one agent propagate through
sequential dependencies, especially in hierarchical struc-
tures [13], [28], [111]; and (5) Agent Heterogeneity and
Stragglers, where agents with varying capabilities or pro-
cessing speeds (due to different LLMs or hardware) create
bottlenecks, particularly in synchronized operations [158].
Effectively managing these interaction-based delays is crucial
for responsive collaborative intelligence. As we will demon-
strate empirically in our MetaGPT case study (Section VI-G),
these interaction-based delays can account for a significant
portion of overall system latency, with architectural choices
in communication protocols and coordination mechanisms
yielding 29% reduction in end-to-end task completion time
compared to baseline multi-agent systems [26]. Through-
out this section, we provide empirical evidence from recent
multi-agent systems research to ground our discussion of
optimization strategies.
Revisiting our Healthcare Diagnostic Agent (Figure 2),
if we re-architect it as a MAS, new latency sources
emerge. For instance, a ‘Diagnostic’ agent might hand
off a request to an ‘Appointments’ agent. The time
taken for the ‘Appointments’ agent to receive, under-
stand, and acknowledge the request from the ‘Diag-
nostic’ agent contributes to inter-agent communica-
tion RTTs. If the ‘Appointments’ agent must wait for
the ‘Diagnostic’ agent to finalize the symptom anal-
ysis before it can search, this creates synchronization
overhead.
B. EFFICIENT INTER-AGENT COMMUNICATION
PROTOCOLS AND STRATEGIES
Optimizing the exchange of information between agents is
fundamental to reducing collaborative latency, particularly
given that LLM-based communication can be verbose and
computationally intensive [155], [159]. ‘‘Communication
efficiency optimization’’ involves: (1) Optimized message
formats, such as structured schemas (e.g., JSON, function
arguments) to reduce parsing overhead and ambiguity com-
pared to natural language, or LLM-condensed updates [160];
(2) Efficient routing strategies, balancing the bottleneck risks
of centralized coordinators against the potential inefficiencies
of decentralized peer-to-peer networks, with hybrid or hierar-
chical models often offering better scalability [129], [161];
and (3) Minimized communication frequency and volume,
through selective protocols (sharing only critical information
guided by roles or events [26]), importance-aware messag-
ing [84], asynchronous patterns to reduce blocking [162], and
efficient group communication mechanisms [163]. Managing
bandwidth constraints through adaptive rates and message
prioritization is also key, especially in networked environ-
ments [139], [164]. These strategies collectively aim to
reduce the time and resources consumed by inter-agent
information exchange. Empirical studies demonstrate sub-
stantial benefits of structured communication design: the
MetaGPT framework [26], which enforces structured mes-
sage formats through standardized document schemas (e.g.,
Product Requirements Documents, System Design specifi-
cations), achieves 29% faster end-to-end task completion
compared to systems using unstructured natural language
exchanges (Section VI-G. This improvement stems from
multiple factors: (1) reduced parsing ambiguity—structured
outputs eliminate the need for LLMs to interpret free-form
text, reducing both framework overhead (L framework) and
potential re-query cycles from miscommunication; (2) more
efficient context utilization—predefined schemas ensure that
only necessary information is transmitted, reducing mes-
sage payload size and associated serialization costs; and (3)
improved caching effectiveness—structured formats enable
better prefix sharing and reuse of common message tem-
plates. Similarly, selective communication protocols that
employ publish-subscribe mechanisms (where agents sub-
scribe only to relevant message types based on their roles)
have demonstrated substantial reductions in unnecessary
message traffic in distributed agent systems, though the mag-
nitude of improvement varies significantly with task structure
and coordination requirements [164]. These quantitative and

C. LATENCY-AWARE COORDINATION AND
SYNCHRONIZATION MECHANISMS
Beyond efficient communication, the mechanisms govern-
ing how agents coordinate actions and synchronize states
are critical for ‘‘coordination efficiency enhancement’’ in
MAS. Synchronous execution models, while simplifying
logic, often introduce idle time as faster agents await slower
ones [159]. Asynchronous models offer greater parallelism
and latency reduction by allowing independent agent pro-
cessing [165], but require careful management of state
consistency and potential message delays [164]. Lightweight
consensus protocols that minimize communication rounds
or use implicit agreement are preferred for reaching shared
understanding efficiently [166]. Dynamic role allocation and
adaptive team structuring, assigning sub-tasks to the most
suitable or available agent based on capabilities, work-
load, or importance scores, minimize execution time and
avoid bottlenecks, often managed by orchestration frame-
works [84], [122], [129]. Minimizing agent waiting time is
further achieved through Just-In-Time (JIT) scheduling of
communication or actions [167] and delay-aware communi-
cation models that allow agents to proceed with potentially
incomplete information [164]. Such mechanisms are vital for
responsive collaborative problem-solving. Quantitative eval-
uations demonstrate the impact of synchronization choices:
asynchronous execution models—where agents operate inde-
pendently and synchronize only at critical coordination
points—can achieve substantial throughput improvements
compared to synchronous approaches that require lock-
step execution. The magnitude of improvement depends
on task parallelizability: for highly decomposable tasks
(e.g., the software development workflow in MetaGPT [26],
where design, implementation, and testing phases have lim-
ited inter-dependencies), asynchronous coordination enables
near-linear scaling with the number of agents, contributing
to the observed 29% end-to-end latency reduction. In con-
trast, tasks with frequent synchronization requirements see
diminished benefits, as agents spend more time idle waiting
for coordination. Lightweight consensus protocols that min-
imize communication rounds—such as implicit agreement
mechanisms based on timeout thresholds rather than explicit
multi-round voting—have been shown to significantly reduce
coordination overhead in distributed agent systems, particu-
larly for scenarios where strong consistency guarantees are
not required [166]. These measurements confirm that coor-
dination mechanism design is a first-order determinant of
multi-agent system responsiveness.
D. TASK DECOMPOSITION AND PARALLEL EXECUTION
OPTIMIZATION
Effective task decomposition and optimized parallel exe-
cution across agents are fundamental to shortening the
critical path latency in MAS [85]. ‘‘Parallel processing
efficiency’’ is achieved through: (1) Strategic task decom-
position, breaking complex goals into manageable sub-tasks
(hierarchically or by functional specialization) of appro-
priate granularity to balance parallelism benefits against
communication overhead [111], [168]; (2) Efficient task
allocation, using centralized schedulers, decentralized nego-
tiation, or market-based mechanisms to assign sub-tasks,
considering agent heterogeneity (speeds, capabilities), work-
loads, and communication costs [137], [169], [170]; (3)
Dependency management, identifying and scheduling inter-
dependent sub-tasks to maximize concurrency while respect-
ing ordering constraints [169], [171]; and (4) Effective load
balancing, distributing workload evenly to prevent agent
idling or overload, potentially through dynamic re-balancing
based on performance feedback [77], [168]. Simulating these
interactions in specialized environments like TimeArena [34]
helps refine these strategies for optimal parallel execution and
latency reduction. Empirical evaluations of task decomposi-
tion strategies reveal significant performance variations: hier-
archical decomposition with appropriate granularity (sub-
tasks requiring 10–30 seconds of execution time) achieves
50–70% reductions in critical path latency compared to flat
task structures in software development benchmarks [26].
Dynamic load balancing that redistributes tasks based on
real-time agent performance monitoring has shown 20–40%
improvements in overall throughput in heterogeneous multi-
agent systems [168]. These findings underscore that effective
parallel execution optimization requires careful co-design of
task decomposition, allocation policies, and load balancing
mechanisms.
E. SCALABLE AND RESPONSIVE MAS ARCHITECTURES
The architectural design of a MAS fundamentally dictates its
ability to implement parallel execution, manage communica-
tion, and scale responsively [23]. Centralized architectures,
with a single coordinator, simplify control but risk bot-
tlenecks and single points of failure [68]. Decentralized
architectures distribute control, enhancing fault tolerance and
scalability but complicating coordination and dependency
management. Hierarchical architectures organize agents into
levels, naturally supporting hierarchical task decomposi-
tion and potentially reducing communication traffic, though
high-level managers can become bottlenecks [28]. Hybrid
architectures combine elements of these patterns to bal-
ance scalability, fault tolerance, and coordination efficiency.

Dynamic network architectures, where interaction struc-
tures and roles adapt at runtime (e.g., DyLAN [84]), offer
optimal configuration for the current context but add man-
agement complexity. The choice of architecture critically
impacts communication pathways and the system’s capac-
ity for low-latency parallel processing, demanding careful
evaluation against expected workloads and responsiveness
goals [85].

F. MANAGING HETEROGENEITY AND ASYNCHRONY IN
MUL TI-AGENT TEAMS
The diversity in agent capabilities (heterogeneity) and
operational timing (asynchrony) within MASs introduces
significant challenges for ‘‘heterogeneity management effi-
ciency’’ and overall latency. Heterogeneity in LLM back-
bones, toolsets, or processing speeds [23], [122] can lead
to ‘‘straggler’’ problems, where slower agents dominate task
completion time. Asynchronous operations, while enabling
concurrency [121], [162], complicate state management and
synchronization, risking rework if agents operate on stale
information. Mitigating these issues involves: (1) Adaptive
scheduling and resource allocation, dynamically assign-
ing tasks based on real-time monitoring of agent load,
capabilities, and predicted completion times [50], [51];
(2) Asynchronous communication protocols and architec-
tures designed for non-blocking operations [121], [162];
(3) Explicit straggler mitigation, such as speculative execu-
tion or redundancy for critical sub-tasks; and (4) Modular and
flexible architectures that leverage heterogeneity by assign-
ing specialized roles to diverse agents, often managed by
dynamic team composition and orchestration layers [28],
[84]. Context-aware coordination, informed by each agent’s
state and capabilities, further enhances performance in such
dynamic settings [172].
G. CASE STUDY: LATENCY ANAL YSIS OF THE METAGPT
FRAMEWORK
To provide a concrete analysis of latency in real-world
multi-agent systems and empirically validate the architec-
tural tradeoffs discussed in Section VI-E, we examine the
MetaGPT framework. This case study directly addresses the
comparison of different architectural paradigms and their
impact on end-to-end latency. Architectural Classification:
MetaGPT replaces conventional unstructured chat with a
structured workflow based on Standardized Operating Proce-
dures (SOPs), where agents with specialized roles (Product
Manager, Architect, Project Manager, Engineer, QA Engi-
neer) communicate via structured document outputs rather
than free-form natural language dialogue [26]. As discussed
in Section VI-E and illustrated in Figure 7, multi-agent sys-
tems can be organized along a spectrum from centralized to
decentralized to hierarchical architectures. MetaGPT imple-
ments a hierarchical, assembly-line architecture (analogous
to Figure 7 (c)), where agents are organized into sequen-
tial roles with predetermined handoff sequences. Each agent
produces structured artifacts (e.g., Product Requirements
Documents, System Design Specifications, Code Files) that
flow through the pipeline in a fixed order. Agents commu-
nicate via a shared message pool with a publish-subscribe
mechanism, allowing downstream agents to directly consume
the outputs of upstream agents without iterative negotiation.
In contrast, ChatDev [173], our baseline system, employs
a chat-based multi-agent approach where agents engage in
synchronous natural language dialogues to reach consensus
on design decisions and coordinate task execution. While

1) QUANTITATIVE ANALYSIS
The data in Table 11 reveals that MetaGPT completes
complex software development tasks in significantly less

reduction in end-to-end latency [26]. To understand the
sources of this improvement, we analyze the key architectural
differences:
• Structured communication eliminates parsing overhead:
MetaGPT enforces structured communication through
predefined document schemas with standardized sec-

for PRDs; File Lists, Data Structures, Interface Def-

well-defined artifact that subsequent agents can parse
deterministically, eliminating the ambiguity inherent in
natural language dialogue. ChatDev’s free-form chat
requires agents to repeatedly exchange messages to
clarify intent and establish shared understanding, intro-
ducing both computational overhead and opportunities
for miscommunication.
• Predetermined workflow reduces coordination delays:
The SOP-based assembly line establishes clear role
sequences and dependencies upfront. Agents know
exactly what inputs to expect and what outputs to
produce, eliminating the need for dynamic task nego-
tiation. This reduces both the number of LLM calls
required for coordination and the synchronization delays
that occur when agents must iteratively align on next
steps—a common bottleneck in dialogue-driven systems
where coordination itself becomes a deliberation process
involving multiple conversational rounds.
• Elimination of redundant reasoning cycles: MetaGPT’s
structured handoffs prevent the repetitive deliberation
cycles common in chat-based systems. In dialogue-
driven coordination, agents may revisit previously
discussed decisions when new information emerges,
triggering cascading re-evaluation. MetaGPT’s rigid
workflow enforces forward progress through the devel-
opment pipeline, though this comes at the cost of
reduced adaptability—a tradeoff inherent in hierarchical
architectures, as discussed in Section VI-E.
2) RELIABILITY AND HIDDEN LATENCY
Beyond direct execution time, Table 11reveals that MetaGPT

what we term hidden latency—the additional time spent
debugging, fixing errors, and reworking outputs in production
systems. A score of 3.75 indicates that MetaGPT’s outputs
are ‘‘nearly perfect’’ to ‘‘flawless,’’ while ChatDev’s score
of 2.25 reflects ‘‘runnable but imperfect’’ code requiring
substantial manual intervention. The structured communi-
cation and clear role definitions in MetaGPT’s hierarchical
architecture produce more consistent outputs, reducing total
time-to-working-software even when accounting for post-
generation corrections. This empirically validates that archi-
tecture choices impact not only runtime latency but also the
reliability and maintainability of multi-agent system outputs.
3) ARCHITECTURAL TRADEOFFS AND DOMAIN ALIGNMENT
While MetaGPT’s hierarchical, SOP-based architecture
demonstrates clear latency advantages for well-defined,
structured tasks, it is important to acknowledge the tradeoffs
discussed in Section VI-E. The rigid workflow may be less
suitable for highly dynamic or exploratory problem spaces
where the optimal sequence of actions is not known a priori.
ChatDev’s chat-based approach, despite higher latency, offers
greater flexibility to adapt to unexpected requirements or
pivot based on intermediate findings. However, for the soft-
ware development domain—a domain with well-established
engineering workflows where SOPs are the norm in human
practice—MetaGPT’s structured approach aligns naturally
with the task structure, yielding substantial efficiency gains.

VII. OPEN CHALLENGES AND FUTURE RESEARCH
DIRECTIONS
Despite significant progress in optimizing individual com-
ponents, the pursuit of consistently ultra-low latency in
LLM-based agent systems is far from complete. Achieving
responsiveness that enables seamless real-time interaction,
especially as agents tackle increasingly complex and dynamic
tasks, requires overcoming several fundamental challenges.
This section first details the key unresolved hurdles related to
scalability, performance trade-offs, and dynamic adaptation.
It then outlines promising future research directions, from
foundational hardware-software co-design to novel agent
architectures and intelligent orchestration, that are essential
for pushing the boundaries of agent speed and capability.
A. KEY UNRESOL VED CHALLENGES
Several formidable challenges currently hinder the realiza-
tion of ultra-low latency LLM agents, demanding innovative
solutions across the entire system stack. A paramount chal-
lenge lies in the scalability of low-latency techniques and
the management of escalating complexity as agent systems
grow. Latency reduction methods that are effective for smaller
models often face diminishing returns or prohibitive overhead
when applied to larger models, extensive context windows,
intricate multi-step tasks, or large-scale MAS where coor-
dination itself becomes a bottleneck [6], [15], [23], [32],
[85]. The combinatorial explosion of states and interactions in
complex scenarios makes efficient, low-latency planning and
decision-making exceptionally difficult, demanding more
sophisticated search and guidance strategies [67], [69], [174].
This scalability issue across model size, context length, and
task intricacy is a primary barrier to deploying responsive
agents in demanding, real-world applications.
A second critical challenge involves navigating the inher-
ent trade-off between reducing latency and maintaining high
task performance, output quality, and system safety. Table 12
illustrates this trade-off by outlining several optimization
strategies alongside their latency benefits and potential risks
to quality and safety. Aggressive optimization strategies—
such as severe model compression, simplified reasoning
cycles, or speculative decoding—can degrade an agent’s core
capabilities, leading to reduced accuracy, factual inconsis-
tency, or failure to adhere to safety constraints [21], [73],
[115]. This ‘‘latency-quality-safety nexus’’ is particularly
acute in high-stakes domains where a faster but less reliable
or robust response could have severe consequences, making
it essential to avoid optimizations that render agent behavior
unpredictable or unsafe [175], [176], [177]. Developing a
principled approach to manage these trade-offs, ensuring that
speed does not compromise the agent’s fundamental utility
and trustworthiness, remains a significant open problem.
A third significant hurdle is enabling robust dynamic
adaptation and real-time resource management to cope
with fluctuating operational conditions. The optimal
latency-reduction strategy is not static; it varies with chang-
ing user requirements, system loads, network conditions,
and available hardware resources, such as in hybrid edge-
cloud deployments [77], [138], [161]. Designing systems
that can monitor these variables and dynamically adjust
their optimization configurations—for instance, by altering
scheduling priorities, modifying planning depth, or switching
decoding strategies—is crucial for maintaining consistent
performance [47], [84]. However, achieving this adaptability
without introducing performance jitter or compromising pre-
dictability is extremely challenging, requiring sophisticated
control mechanisms that can make fast, stable decisions based
on real-time system state and task characteristics[114], [178].
A fourth challenge, which cuts across the preceding
three, is the absence of systematic comparative evaluation
across the optimization categories surveyed in this work.
Current literature predominantly evaluates techniques in
isolation—quantization is benchmarked independently of KV
cache optimization, agent-level planning improvements are
assessed without considering system-level serving strategies,
and multi-agent coordination mechanisms are rarely eval-
uated against single-agent baselines under controlled con-
ditions. This fragmented evaluation landscape obscures the
relative contribution of each optimization layer and makes it
difficult for practitioners to prioritize investments. Moreover,
the shortcomings of individual approaches differ qualita-
tively: model compression techniques (Section III) primarily
risk quality degradation, agent-level strategies (Section IV)
face scalability limitations as task complexity grows, system-
level optimizations (Section V) are often hardware-specific
and non-portable, and multi-agent methods (Section VI)
introduce coordination overhead that can negate parallelism
benefits for tightly coupled tasks. Establishing unified bench-
marking protocols that evaluate cross-layer optimization
combinations under realistic agent workloads is essential for
advancing the field beyond isolated improvements toward
holistic latency reduction.
B. FUTURE RESEARCH DIRECTIONS
To overcome the aforementioned challenges, future research
should pursue several promising and synergistic directions
aimed at holistically reducing agent latency. A foundational
research direction is the pursuit of holistic hardware-software
co-design, moving beyond accelerating core LLM inference.
Future work should explore the concept of an ‘Agent-
Aware Operating System’ (AgentOS). As this survey has
deconstructed, an agent’s operational loop is a complex
computational graph involving not just LLM inference but
also planning, tool-use, and memory management (e.g.,
Lframework, Ltool). A dedicated AgentOS could possess prim-
itives to understand this entire graph, enabling intelligent,
cross-layer scheduling. For instance, it could pre-fetch data
for an anticipated tool call while the LLM is still in its plan-
ning phase, or dynamically allocate heterogeneous memory
to minimize the data movement between CPU-intensive logic

In addition to hardware advancements, another vital direc-
tion involves fundamentally rethinking agent design through
novel agent architectures and communication paradigms.
Research into compositional, modular, or hierarchical agent
designs can unlock significant latency reductions through
parallelism and specialization, allowing complex tasks to be
decomposed and handled by multiple, concurrently operat-
ing specialist agents [28], [30], [68], [179]. Simultaneously,
innovating inter-agent communication beyond verbose natu-
ral language—by developing more efficient protocols based
on semantic meaning, compressed state representations,
or emergent, task-specific languages—is critical for minimiz-
ing coordination overhead in MAS [156], [157], [180], [181].
These architectural and communicational innovations aim to
enhance intrinsic speed by optimizing the agent’s high-level
logic and interaction patterns.
An increasingly important research frontier is the extension
of latency-optimized agent systems to diverse, real-world
application domains beyond traditional natural language pro-
cessing benchmarks. Recent work demonstrates that LLM
and transformer-based systems are beingdeployed for mul-
timodal disaster identification in low-resource linguistic
contexts [54], multimodal misinformation detection across
under-resourced languages [55], zero-shot automated evalu-
ation in educational settings [52], and mental health moni-
toring through social media analysis [53]. These applications
impose stringent latency requirements while simultaneously
demanding multimodal processing and cross-lingual gener-
alization, creating optimization challenges that go beyond
the primarily English-centric, text-only scenarios prevalent
in current latency research. Developing agent systems that
maintain low latency while processing heterogeneous inputs
across diverse linguistic and cultural contexts represents a
critical direction for ensuring the broad societal impact of the
optimization techniques surveyed in this work.
Leveraging advanced AI and Machine Learning (ML)
for system-level orchestration presents a powerful avenue
for enabling the intelligent, adaptive control required for
dynamic environments. This includes applying ML models
for fine-grained latency prediction of agent tasks, which
can inform more effective scheduling and resource alloca-
tion decisions [114], [182], [183]. Furthermore, developing
learned scheduling policies, adaptive caching strategies that
go beyond the KV cache, and intelligent resource manage-
ment algorithms can create control systems that dynamically
optimize the latency-quality trade-off based on real-time con-
ditions and application-specific goals [43], [184], [185]. This
AI-driven orchestration is key to managing the complexity
of modern agent systems and ensuring their responsiveness
under variable workloads.
Finally, integrating energy efficiency as a first-class design
objective is essential for creating sustainable low-latency
agent systems. This is particularly critical for agents deployed
on resource-constrained edge devices and for managing the
operational costs of large-scale systems [38], [92]. This
direction involves creating energy-aware performance met-
rics, algorithms, and resource management strategies, as well
as pursuing hardware-software co-design approaches that
explicitly optimize for performance-per-watt [78], [138],
[186]. A focus on sustainability ensures that the pursuit of
speed is both technologically advanced and economically and
environmentally viable.
VIII. CONCLUSION
Minimizing response latency is a cornerstone for unlocking
the transformative potential of LLM-based agent systems,
as high latency severely impairs usability, real-time applica-
bility, task efficiency, and economic viability. This survey has
provided a comprehensive analysis of this critical challenge,
deconstructing the multifaceted sources of latency—from
core LLM inference and agent framework overhead to tool
interactions and system-level bottlenecks. We have detailed a
holistic suite of optimization techniques that span the entire
agent stack, including core model acceleration, agent-level
algorithmic refinements inspired by cognitive science, system
and infrastructure enhancements, and specialized strategies
for multi-agent collaboration. This structured exploration,

and enabling dynamic adaptation. Overcoming these hur-
dles will require sustained, multi-disciplinary innovation
across key research frontiers, including hardware-software
co-design, novel agent architectures, AI-driven orchestration,

to evolve LLM agents into the seamless, intelligent, and

problems and reshaping how we interact with technology.
