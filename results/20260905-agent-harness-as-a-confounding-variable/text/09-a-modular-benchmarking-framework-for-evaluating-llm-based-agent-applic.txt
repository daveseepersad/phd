ABSTRACT 
Large Language Model (LLM) based agent applications integrate reasoning, 
retrieval, tool invocation, and multi -turn interaction to solve complex tasks. While 
recent advances have enabled rapid adoption of agentic systems in production, 
evaluation methodologies have largely remained model-centric, focusing on single-turn 
accuracy or preference -based scoring. These approaches fail to capture agent -level 
behavior such as contextual grounding, conversational fidelity, tool effectiveness, and 
safety characteristics. 
This paper introduces a modular benchmarking framework for evaluating LLM -
based agent applications across models, agent architectures, and execution strategies. 
The framework decouples datasets, agents, models, and metrics, enabling systematic 
and reproducible evaluation. We define a multi-dimensional metric taxonomy spanning 
output quality, contextual grounding, conversational relevance, and safety, and 
combine it with trace -aware execution to support fine-grained analysis of agent 
behavior. 
Using representative synthetic benchmarks derived from real -world agent 
workloads, we demonstrate that agent design choices —particularly retrieval

results highlight the need for holistic evaluation frameworks that move beyond

systems.

1. Introduction 
LLM-based agents have emerged as a powerful paradigm for building intelligent 
applications that go beyond static text generation. By combining large language models with 
external tools, retrieval systems, and structured reasoning patterns, agents can execute complex 
workflows such as multi-step question answering, information synthesis, and decision support. 
Despite their growing adoption, evaluating LLM -based agent applications remains an 
open challenge. Traditional benchmarks emphasize single -turn correctness or human 
preference judgments, which are insufficient for capturing agent -level behavior in realisti c 
deployments. In practice, an agent’s effectiveness depends not only on the final answer it 
produces, but also on how it retrieves and uses external context, how it maintains coherence 
across turns, and how safely it operates under uncertainty. 
Existing evaluation approaches suffer from three key limitations. First, they conflate 
model quality with agent performance, obscuring the impact of agent orchestration logic, 
retrieval strategies, and tool invocation. Second, they lack visibility into intermediate execution 
traces, making failure analysis and debugging difficult. Third, they do not provide a unified 
metric framework capable of assessing grounding, conversational dynamics, and safety 
alongside output correctness. 
To address these challenges, this paper proposes a modular benchmarking framework 
designed specifically for LLM -based agent applications. The proposed framework treats 
agents, models, datasets, and metrics as interchangeable components, enabling controlled 
comparison across configurations. By combining trace -level execution data with a multi -

2. Related Work 
2.1 LLM Evaluation Benchmarks 
Evaluation of large language models has traditionally focused on single-turn tasks such 
as question answering, summarization, and reasoning. Popular benchmarks emphasize 
accuracy against reference answers, multiple -choice performance, or human preference 
judgments. While effective for comparing base model capability, these benchmarks largely 
ignore execution context, intermediate reasoning, and external knowledge usage. 
Recent work has explored automated evaluators that leverage LLMs themselves to 
score responses for qualities such as helpfulness, coherence, and faithfulness. Although these 
approaches improve scalability, they remain primarily response -centric and do not explicitly 
evaluate agent behavior such as tool invocation quality or context utilization patterns. 
As a result, existing LLM benchmarks provide limited insight into how models perform 
once embedded within complex agent workflows. In particular, they fail to capture how errors 
accumulate across multi -step execution or how retrieval and tool interactions influence final 
outcomes. 
2.2 Retrieval-Augmented Generation Evaluation 
Retrieval-augmented generation (RAG) has motivated evaluation methods that consider 
the relationship between retrieved documents and model outputs. Metrics such as retrieval 
precision, recall, and faithfulness attempt to quantify grounding and context usage. 
However, most RAG evaluation frameworks treat retrieval as a single, static step 
preceding generation. In agentic systems, retrieval is often invoked repeatedly across multiple 
steps, conditioned on prior outputs and tool results. 
Existing metrics fail to capture how context quality evolves over time or how retrieval 
decisions affect downstream agent behavior in longer execution traces. 
2.3 Agentic AI Systems 
LLM-based agents extend retrieval -augmented generation by incorporating explicit 
reasoning, tool invocation, and multi -step planning. Agent frameworks enable models to 
interact with external systems such as search APIs, databases, and computational tools, 
significantly expanding their functional scope. 
Despite rapid progress in agent design, evaluation methodologies have lagged behind. 
Many agent studies rely on coarse task success rates or qualitative examples, making systematic

comparison difficult. In addition, agent performance is often tightly coupled to implementation 
details, including prompt structure, tool schemas, and orchestration logic, obscuring the relative 
contributions of models versus agents. 
Several recent efforts evaluate agents using end-task completion or human-in-the-loop 
scoring. While informative, these approaches do not scale well and provide limited diagnostic 
insight into failure modes such as incorrect retrieval, tool misuse, or compounding errors across 
multi-step execution. 
2.4 Evaluation Gaps and Challenges 
Across existing evaluation approaches, three persistent challenges remain. First, current 
benchmarks conflate model quality with agent architecture, limiting interpretability and 
reproducibility. Second, they lack trace -level visibility into intermediate a gent execution, 
preventing fine -grained diagnosis of failures and regressions. Third, they do not provide a 
unified framework capable of jointly evaluating output quality, contextual grounding, 
conversational dynamics, and safety. 
These challenges are amplified in production settings, where agents operate over 
evolving knowledge sources and invoke multiple tools per interaction. The absence of a 
holistic, composable evaluation framework makes it difficult to reason about trade -offs or to 
compare agent designs in a principled and reproducible manner. 
3. Benchmarking Framework Overview 
The proposed benchmarking framework evaluates LLM -based agent applications in a 
modular, reproducible, and diagnostic manner. Rather than treating evaluation as a monolithic 
process, it decomposes assessment into configurable components that can be indepen dently 
executed and analyzed. 
The framework supports systematic comparison across models, agent orchestration 
patterns, retrieval strategies, and tool -use policies without coupling evaluation logic to any 
specific agent implementation. 
3.1 Design Principles 
• Model agnosticism: Decouples evaluation from specific LLMs. 
• Agent modularity: Orchestration, tools, and retrieval are swappable. 
• Metric composability: Mix-and-match metrics by task needs. 
• Trace awareness: Captures prompts, context, tools, and outputs.

3.2 Evaluation Stack 
The framework uses three metric groups: (i) generic response metrics (accuracy, 
relevance, completeness, coherence and clarity), (ii) RAG grounding metrics using RAGAS -
style measures (document relevance; contextual precision, recall, relevance), and (iii) Eval 
metrics computed via LLM -as-judge rubrics (correctness, conciseness, bias, toxicity). 
Together, these scores cover outcomes, grounding, and safety. 
3.3 System Architecture 
The framework is organized into four layers: configuration, execution, evaluation, and 
analysis. Configuration defines dataset selection, metric selection, score directionality, and the 
compared variants. Execution runs the agent while capturing traces (prompts, retrieved context, 
tool calls, intermediate outputs, final response). Evaluation applies the metric suite to 
responses, context, and traces. Analysis aggregates results and supports comparative 
visualization across runs. 
3.4 Comparative Positioning 
Existing benchmarks provide useful baselines for task success and response quality, but 
often under-emphasize trace-grounded diagnosis for retrieval-centric agents. The contribution 
here is a unified evaluation surface that combines RAGAS-style grounding metrics, Eval 
(LLM-as-judge) rubrics, and generic metrics, all anchored to explicit execution traces. This 
enables controlled ablations, regression detection, and attribution of failures to retrieval versus 
orchestration.

4. System Context 
LLM-based agent applications operate under constraints that differ substantially from 
model-only generation workflows. Agents may invoke retrieval and tools repeatedly within a 
single interaction, combining intermediate reasoning steps with external tool outputs. As a

[[page 7]]
Karthik Perikala 
https://iaeme.com/Home/journal/IJRCAIT 6 editor@iaeme.com 
result, latency and failure risk compound across multi -step execution, making predictable 
performance and traceability primary operational requirements. 
In production settings, agent behavior is shaped by orchestration logic —including 
routing policies, tool schemas, retrieval strategies, and memory mechanisms —that evolve 
independently from the underlying model. Evaluation must therefore isolate the contrib ution 
of each component rather than collapsing performance into a single model score. 
Design Constraints 
• Component decoupling: Agents, models, datasets, and metrics evolve independently 
and must be benchmarked in a composable manner. 
• Repeated invocation: Retrieval and tool calls may be invoked conditionally across 
multiple reasoning phases. 
• Trace-first evaluation: Intermediate prompts, retrieved context, and tool outputs are 
required for diagnosis and regression detection. 
• Multi-dimensional objectives: Correctness must be evaluated alongside grounding, 
conversational fidelity, and safety.

both outputs and traces, enabling response -level and agent-level evaluation. Results are

6. Metric Taxonomy 
A central goal of the framework is to evaluate agent applications beyond single -turn 
correctness. Agent outputs are shaped by retrieval quality, tool invocation behavior, multi-turn 
context, and safety constraints. To capture these dimensions, we define a modular metric 
taxonomy where each metric can be enabled, disabled, or weighted based on the evaluation 
objective. 
The taxonomy is organized into four categories: (i) output quality metrics that score the 
final response, (ii) contextual grounding metrics that measure how well responses are supported 
by retrieved evidence, (iii) conversational dynamics metrics that assess multi -turn alignment, 
and (iv) safety and trust metrics that capture harmful or biased behavior. 
Metric Design Principles 
• Composability: Metrics are independently computed and can be combined into task-
specific scorecards. 
• Trace dependence: Metrics may consume execution traces (e.g., retrieved context and 
tool outputs) rather than only final answers. 
• Directionality: Each metric explicitly encodes whether higher or lower values are 
preferred. 
• Reproducibility: Metric computation operates over persisted artifacts to enable 
regression detection and controlled ablations. 
This structure supports consistent comparison across agent and model variants while 
enabling domain-specific customization through metric selection and weights.

7. Scoring and Normalization 
To make multi -dimensional evaluation actionable, the framework uses a standardized 
ordinal scoring scheme. Each metric is scored on a bounded scale (e.g., 0 –3), where scores 
correspond to rubric-defined quality levels. This supports aggregation and visualization without 
requiring metrics to share native units. 
Ordinal Scale 
• 0: unacceptable / failure 
• 1: weak / partially correct 
• 2: acceptable / mostly correct 
• 3: strong / fully correct 
Directionality 
Metrics encode directionality to support consistent aggregation: higher -is-better (e.g., 
accuracy, relevance, grounding) and lower-is-better (e.g., toxicity, bias). When aggregating, 
the framework applies a directionality transform so that normalized scores are comparable.

11. Conversation, Trace, and Safety Metrics 
Production agent evaluations must capture multi -turn alignment, trace completeness, 
and safety behavior in addition to correctness and grounding. These metrics are computed using 
the same LLM-as-judge rubric approach, scoring the agent response and trace artifacts on a 0–
3 scale. 
Conversation 
Conversation metrics evaluate whether the agent maintains the user’s intent across 
turns, uses prior context appropriately, and avoids contradictions. In multi -turn flows, failures 
often present as correct standalone answers that do not address the current turn or ignore 
constraints established earlier. 
Trace Completeness 
Trace metrics validate auditability and debugging readiness. A complete trace captures 
prompts, retrieved context, tool calls, and intermediate outputs so that regressions can be 
attributed to specific changes in retrieval settings, tool behavior, or orche stration logic rather 
than being treated as opaque model variance. 
Safety 
Safety metrics evaluate harmful content and policy misbehavior. Directionality is 
configured as lower -is-better for toxicity and bias, and these metrics can be used as gating 
signals to block promotion of agent versions that improve accuracy but degrade safety. 
12 Experimental Setup 
We evaluate agent applications under a controlled benchmark configuration by holding 
the dataset and judge settings fixed while varying a single factor per experiment. All 
experiments use the same rubric scale (0 –3), the same metric suite selection, and co nsistent 
directionality configuration to ensure comparability. 
Compared Variants 
To avoid coupling results to proprietary implementations, variants are described functionally: 
• Variant-A (RAG-only): Retrieves context once and generates a final answer. 
• Variant-B (Tool-augmented): Uses retrieval and structured tool calls before answering. 
• Variant-C (Multi-step agent): Plans, retrieves/tool-calls iteratively, then answers. 
Controlled Factors 
• Dataset : Fixed benchmark dataset (Dataset-A). 
• Judge: Fixed LLM-as-judge configuration for a given comparison. 
• Retrieval settings: Fixed top-k, chunk policy, and metadata filters per experiment.

Key Findings 
Across variants, retrieval relevance remains strong, but agent strategy determines 
whether evidence is used effectively. Multi -step execution improves contextual recall and 
precision, translating into higher accuracy and completeness. Tool-augmented variants improve 
completeness but may reduce conciseness due to additional procedural detail. 
14 Limitations 
The framework uses rubric-based LLM-as-judge evaluation for multiple metrics. While 
this enables scalable scoring for open -ended agent tasks, judge models can exhibit systematic 
effects (e.g., verbosity sensitivity, position effects, or style preference) that shift scores without

[[page 14]]

https://iaeme.com/Home/journal/IJRCAIT 13 editor@iaeme.com 
matching user -perceived quality. Mitigating these effects requires calibration and periodic 
audits. 
A second limitation is that trace -aware evaluation depends on consistent 
instrumentation. If prompts, retrieved context, tool calls, or intermediate outputs are not 
captured reliably, grounding and trace metrics become less diagnostic. Uniform trace schemas 
across agent implementations are therefore a prerequisite for fair comparison. 
Finally, the empirical results are reported using anonymized variants and normalized 
scores to avoid dependence on proprietary systems. This improves shareability but can reduce 
interpretability compared to task-specific, publicly reproducible benchmarks. 
15 Future Directions 
Future work will expand empirical depth through systematic ablations across agent 
designs and retrieval settings (e.g., top-k, reranking, tool-use policy), and will report effect sizes 
using consistent metric directionality and aggregation. 
We will also improve evaluator robustness through calibrated judging: multiple judge 
passes, disagreement analysis, and selective human review to anchor rubric interpretation. For 
retrieval-centric agents, we plan to extend trace-level checks that detect unsupported claims, 
missing evidence usage, and tool failure recovery patterns. 
Comparative positioning will be strengthened by mapping evaluation dimensions to 
existing benchmarks (agent task suites and LLM judging frameworks) while keeping the metric 
stack centered on RAGAS -style grounding, Eval (LLM-as-judge), and generic response 
metrics. 
16 Conclusion 
This paper introduced a modular benchmarking framework for evaluating LLM -based 
agent applications using trace -aware instrumentation and a combined metric stack: generic 
response metrics, RAGAS-style grounding metrics, and Eval rubrics computed via an LLM -
as-judge. By separating configuration, execution, trace capture, and evaluation, the framework 
supports controlled comparisons and root-cause attribution when performance changes. 
The resulting evaluation surface makes it possible to distinguish retrieval failures from 
orchestration and response construction failures, enabling repeatable regression testing and 
evidence-grounded iteration for agentic RAG systems.
