Abstract - Large Language Model (LLM) agents have gained 
popularity for constructing complex coding pipeline s that 
incorporate multiple tools, iterative processes, an d advanced 
libraries such as LlamaIndex and LangChain. Recogni zing the 
critical need for observability, we emphasize techn iques to 
monitor and control the process, costs, frequency o f model calls, 
prompt usage, and overall logging. While contempora ry agent 
libraries offer foundational classes for these purp oses, many 
online examples and articles still rely on default implementations 
with ChatGPT models, allowing agents to invoke gene rative AI 
methods without robust flow control, prompt managem ent, or 
detailed application logging. In our research, we i dentified 
effective ways to implement essential observability methods for 
popular frameworks, including LlamaIndex, LangChain , and 
CreAI. Our approach introduces workflows, custom model calls, 
comprehensive logging, and enhanced observability, which 
improve the reliability, controllability, predictab ility, and 
efficiency of LLM agents in software development ap plications. 
Through this methodology, we enhanced the architect ure and 
structure of the evolving agentic framework for cod e generation, 
achieving a notable 98% accuracy in solving challen ging coding 
tasks via specified workflows. 
Keywords - LLM agents, observability, AI code gener ation, 
LangChain, LangGraph, llama-index, CrewAI, Cursor 
I. INTRODUCTION 
The rapid pace of innovation in Generative AI is en abling 
many corporations to accelerate their code developm ent 
processes [16]. Prompt - completion (request - resp onse) code 
generation has become standard among innovative developers, 
allowing them to produce code snippets using a single prompt to 
describe the task. However, the agentic approach [14, 15] offers 
even greater potential benefits by enabling multi - step code 
creation pipelines. This method allows for the refi nement of 
prompts, integration of specialized tools or expert agents for 
specific tasks, verification of code correctness, a nd even 
potential code execution. 
Despite the popularity of agent-based methods, ther e are 
currently no established standards or best practices. Many data 
scientists attempt to implement solutions without t horough 
testing or the application of essential practices s uch as 
observability. Our work addresses this gap, refining the agentic 
approach for code generation and establishing a fra mework of 
best practices to enhance its effectiveness and reliability. Using 
LLM agents in a controllable and reliable manner is essential for 
ensuring consistent, efficient, and cost - effective performance, 
especially in production environments. Without proper control 
and reliability mechanisms, agents can exhibit unpr edictable 
behavior, leading to high operational costs, potent ial security 
risks, and performance degradation. 
II. LLM AGENTS 
A. LLM model selection 
Selecting the appropriate generative and embedding models 
is one of the most fundamental tasks in AI developm ent. Most 
existing frameworks assume the use of OpenAI ChatGP T 
models with an API key to proceed, but we recommend a more 
flexible approach that allows users to choose their model 
provider and log all model - related activities. Ideally, codebases 
should centralize model calls to enable additional operations 
such as logging, observability, cost control, and more. 
It is well known that different models can signific antly 
impact application performance, and there is no "one - size - fits 
- all" solution in Generative AI. Often, models need to be fine - 
tuned for specific datasets, or certain applications may prioritize 
quick response times, favoring smaller models over higher - 
quality, resource - intensive ones for optimal performance. 
With each new flagship model release, there tends t o be 
considerable excitement about a supposedly “better” model. 
However, users should be mindful of pricing. For instance, the 
OpenAI 4 - turbo preview costs $60 per 1 million output tokens 
[1], which is six times the cost of the standard OpenAI 4o model, 
and the newer “reasoning” model is also slower. While vendors 
may encourage users to adopt more expensive models, savvy 
data scientists should carefully evaluate costs and performance 
trade - offs to make informed choices.

should be tailored to meet those needs. As models a re rapidly 
becoming commodities, with new options released weekly, it’s 
advantageous to adopt a setup that enables seamless model 
switching with minimal code changes.

C. Agentic approach 
LLM agents extend beyond simple question - answer 
models; they are designed to autonomously perform c omplex 
workflows. Their capabilities include: 
• Interpreting Commands or Requests: They 
understand natural language instructions from users 
and can even correct or refine these inputs before 
sending them to a model. 
• Planning and Executing Tasks: Agents can break 
down tasks into smaller steps, query databases or 
APIs, perform calculations, interact with external 
systems, and synthesize information. 
• Interacting with External Tools or Environments: 
They integrate with APIs, databases, web browsers, or 
software applications to exchange data, making them 
highly useful for automation. 
• Reasoning and Improving Performance Over 
Time: Some agents learn from feedback or previous 
interactions, enhancing task efficiency and decisio n - 
making. 
Agents support multi - step processes, which can be 
particularly valuable for code generation, where th e software 
development life cycle (SDLC) can be emulated. For instance, 
agents could be set up to perform roles similar to those of a 
business analyst, architect, developer, tester, verifier, and release 
engineer, collaborating to generate functional, efficient code. 
Given that agents make numerous autonomous decisions, it 
is essential to ensure that these align with our expectations. This 
makes observability crucial in agent applications, enabling 
control over model calls, costs, workflow monitorin g, and 
logging. By integrating observability, developers can effectively 
track and analyze the agents' behaviors, making it easier to 
debug and optimize performance. Moreover, enhanced 
oversight helps in maintaining compliance with regulatory and 
ethical standards, especially when agents interact with sensitive 
data or critical systems. Our approach integrates o bservability 
into the agentic code generation process for severa l popular 
frameworks, providing greater transparency and control. 
III. IMPLEMENTATION 
A. Agent Objectives 
The most popular agent libraries today include LangChain, 
LlamaIndex, and CreAI. All of these can be easily i ntegrated 
with the ChatGPT model by simply providing an OpenA I API 
key - often requiring just a single line of code. However, we have 
identified several limitations with this standard approach: 
• LLM Invocation Control: Data scientists often lack 
control over the calling and integration code, whic h 
makes it difficult to add debugging or logging 
statements. This limits their ability to verify pro mpt 
content, monitor the frequency of model calls, or 
measure execution timing. 
• Flow Control : Users frequently know more about 
how to guide tool interactions than the model itsel f, 
yet these libraries do not always allow for customized 
control flow between tools based on specific 
parameters. 
• Prompt Control: Many agent libraries conceal the 
actual prompts passed to LLMs, relying on complex, 
often opaque prompts (Fig. 1), and making decisions 
based on tool function comments and argument types 
in ReAct agents. 
• Cost Control : Generative models are invoked by 
agents without transparency, making it difficult to 
track the number of calls per execution and manage 
associated costs. 
• Logging: Workflow data is often not logged in a 
structured way, making it challenging to query or 
understand the flow of actions within the agent. 
• LLM Model Selection : Different tools, agents, or 
steps within a workflow may require specific models 
with tailored parameters, yet most libraries lack 
flexibility in model selection. 
• State Management: Passing data between tools or 
agents in a standardized, uniform way remains a 
challenge, often resulting in inconsistencies. 
Our research has addressed these concerns, resulting in LLM 
agents that are more robust, flexible, reliable, an d cost - 
effective. This approach empowers data scientists w ith full 
control over agent workflows, enhancing customizati on, 
observability, and transparency.

4) Agentic Flow control for Coding 
The Software Development Lifecycle (SDLC) has evolv ed 
significantly over the past several years. Today, m ultiple 
stakeholders - including designers, analysts, archi tects, testers, 
developers, reviewers, and deployment teams - activ ely 
participate in the process. Control flow often circ ulates among 
these roles; for example, after code development, i t is handed 
over to testers. If the test cases fail, the code r eturns to the 
developer for revisions; if successful, it proceeds to production. 
Fig. 1. ReAct Coding agent complex prompt 
Code development is a complex process that goes bey ond 
simple validation methods like cosine similarity or ROUGE 
scores [7], which are often used for text. Comparing, validating, 
and executing generated code introduces unique challenges, as 
demonstrated by extensive research with great results, including 
[5] and [6], on multi - step iterative development and testing 
workflows. Unlike simple prompt - completion tasks, code 
development requires an iterative flow that include s several 
stages to refine and validate the results. 
In our agentic workflow, we aimed to replicate a re al - life 
SDLC process for developing and testing Python code. 
5) Tools (agent steps or functions) 
Agent tool represent a single step, that needs to be executed. 
For our coding agent we have been using the followi ng four 
tools taking care of different aspect of software development and 
handling various errors and redirections. 
• Analyzer: This tool verifies if a task is a coding - 
related one. If it is, it directs the task to the Developer; 
if not, it responds with a generic answer. 
• Developer: Responsible for designing and 
implementing Python code to solve the task. It also 
generates test cases and code to execute them. When 
all tests pass, the tool outputs “All tests passed.” 
• Evaluator: Acts as a code reviewer, validating the 
code, making necessary corrections, and adding 
comments for clarity. 
• Executor (Tester): Runs the code and checks for the 
presence of the phrase “All tests passed” in the output. 
If successful, it returns the result; otherwise, it sends 
the task back to the Developer with detected errors.

7) LangGraph flow implementation 
The LangGraph library [8] within LangChain provides a 
robust infrastructure for structuring and orchestra ting complex 
workflows, which is particularly valuable in applic ations 
involving multi - step language model tasks. By lev eraging a 
graph - based approach, LangGraph enables the desig n of 
workflows where tasks are represented as interconnected nodes, 
supporting branching, looping, and conditional flow s. This 
architecture is well - suited for problems requiring multiple steps 
or decision points, such as data ingestion, transformation, model 
inference, and output formatting, all managed as distinct stages 
within the workflow. 
As part of the LangChain ecosystem, LangGraph easil y 
integrates with a wide array of language models and tools, 
enabling users to build sophisticated multi - step pipelines that 
make use of LangChain’s extensive model support. Wh ether 
applied to tasks like summarization, question - ans wering, or 
code generation, LangGraph manages the sequence and 
dependencies between these model invocations, making it ideal 
for workflows that require clear task orchestration, such as multi 
- step reasoning or pipeline processing. 
The interoperability of LangGraph with frameworks l ike 
CrewAI and LlamaIndex further expands its utility, enabling 
diverse applications. For instance, CrewAI facilita tes dynamic 
task assignment, result tracking, and agent - based interactions 
that complement LangGraph’s workflow management, allowing 
for the creation of intelligent and adaptable agent systems. 
Similarly, LlamaIndex’s focus on indexing and retrieval - based 
generation is valuable for document - centric applications where 
LangGraph can coordinate the retrieval, processing, and 
synthesis of information across multiple steps, sea mlessly 
integrating retrieval and generative capabilities t o produce 
coherent and relevant outputs from large text corpora. 
LangGraph also incorporates built - in mechanisms for error 
handling and retries, which are essential for mainta ining 
workflow robustness, especially in scenarios where multiple 
LLM calls or interactions with external data source s are 
involved. These features ensure that workflows conti nue to 
completion even if individual steps encounter errors, enhancing 
reliability and efficiency in complex task sequences. 
The scalable and flexible design of LangGraph makes it 
adaptable to evolving project requirements, allowin g for 
incremental workflow modifications as application needs grow. 
This adaptability is particularly beneficial for it erating quickly 
in response to changing demands. Overall, LangGraph excels at 
enabling complex problem - solving workflows that i nvolve 
decision trees, conditional logic, and interdepende nt tasks, 
making it a valuable tool for orchestrating advance d language 
model applications across various domains, and visualizing the 
flows. 
In our AI agent implementation, we crafted precise prompts 
tailored to each tool, ensuring the models perform as intended. 
Additionally, we configured the system to pass an LLM model 
to each tool at every step through the agent’s stat e, enabling 
seamless control and state - sharing throughout the generation 
process. We implemented a structured iterative workflow agent 
(see Fig. 2), which provides process control and ma intains 
shared state across tools throughout the entire generation flow. 
A retry mechanism was also incorporated, allowing to configure 
code - generation attempts (a state parameter) to e ffectively 
manage unsuccessful outputs. This structure is clea r, intuitive, 
and closely mirrors a human - driven software devel opment 
lifecycle (SDLC).

LLM calling code into popular agent frameworks, whi le also

D. LLM Model Selection and Cost 
Selecting large language models is a very challengi ng 
process. Over last several years, new models (comme rcial and 
open source) were released weekly by leading resear chers, 
innovators, and corporations. When OpenAI releases a new 
better version (for example, GPT - 4o1 - preview) m any 
publications are praising it, detailing its advanta ges over other 
models, avoiding discussions about cost. However, the price and 
execution time are very important factors for many companies. 
In our example, o1 - preview costs $15.00 / 1M inpu t tokens, 
while its predecessor gpt - 4o - $2.50 / 1M input tokens [9], or 
6 times more expensive. On top of that, the new “re asoning” 
model is substantially slower than its predecessor is. 
We should always distinguish between user needs and 
system requirements and avoid relying solely on ven dor 
marketing materials, which may aim to justify higher costs. It's 
essential to test a model with our specific dataset to achieve 
optimal results, as no single LLM is universally suitable for all 
tasks and datasets. Often, models that perform well in one 
context may fall short in others, emphasizing the n eed for 
customized testing and evaluation. By rigorously assessing each 
model’s performance on our unique dataset, we can select or fine 
- tune models that deliver the most relevant and ef fective 
outcomes, rather than defaulting to potentially ove rhyped or 
generalized solutions. 
In our research, we selected well - established, hi gh - 
performing models with reasonable costs. Our findin gs 
demonstrate that achieving strong results does not require the 
most expensive models, highlighting the effectivene ss of 
thoughtful, cost - efficient model selection..

IV. DATASET 
The LeetCode dataset [15] is an extensive collectio n of 
programming problems designed to challenge develope rs' 
understanding of algorithms, data structures, and p roblem - 
solving strategies. Each problem in the dataset is crafted to test 
specific skills, such as array manipulation, dynami c 
programming, recursion, graph traversal, and string 
manipulation, among others. The variety and breadth of tasks 
within the dataset make it highly valuable for both beginner and 
advanced programmers who wish to hone their technic al 
abilities and deepen their understanding of compute r science 
concepts. Each problem is also categorized by diffi culty level 
(easy, medium, and hard), allowing users to gradually progress 
from simpler exercises to more complex challenges. 
What makes the LeetCode dataset particularly interesting is 
the complexity and depth of the harder problems, wh ich often 
require sophisticated solutions involving advanced algorithms 
and optimal performance considerations. These tasks are more 
than just exercises; they are often designed to mirror real - world 
coding scenarios, where efficiency, readability, an d scalability 
of the solution are crucial. For instance, problems involving 
dynamic programming may require carefully designed recursive 
solutions with memorization, while graph - related problems can 
demand deep knowledge of graph traversal algorithms like 
Dijkstra’s or BFS. These tasks not only test the LL M agent’s 
technical knowledge but also encourage strategic th inking and 
creativity, as many problems can be solved in multi ple ways, 
each with different trade - offs in terms of time a nd space 
complexity. Consequently, the LeetCode dataset serves as both 
a learning tool and a benchmarking platform for pro grammers 
to tackle complex, practical coding challenges. Lee tCode 
problems are frequently used as a core part of preparation for top 
IT companies interviews, helping candidates practi ce the 
algorithmic and problem - solving skills essential for success in 
technical rounds. We have been using LeetCode tasks as input 
to our agent.

VI. CONCLUSION 
 Large Language Models are revolutionizing software 
development. There are many coding tools including Amazon Q 
or Github Copilot that help developers to write cod e faster. 
However, these tools utilize “human in the loop” ap proach. 
Agentic approach helps us to automate the whole SDLC coding 
pipeline, specify the workflow and choose models for each actor 
(coder, tester, architect, analyst, etc.) It is ver y important to 
maintain the flow control, and we have accomplished it with 
LangGraph, tools and custom LLM class wrappers for the most 
popular Generative AI frameworks. Our implementatio n 
includes full observability stack, including AWS cl oud 
integration, logging and cloud Watch alarms, and ti mestamps. 
One important lesson we have learned – it is important to make 
sure the LLM follows certain workflow and if possible we need 
to control flow, iteration parameters, data exchang es, model 
arguments, and LLM prompts rather than relying on models to 
figure it our autonomously. 
 We were able to solve many interesting problems an d 
benchmark our agent for various moderately priced m odels, 
achieving up to 98% accuracy. Prompt engineering is also a very 
important aspect of agentic approach. Instead of relying on agent 
to communicate with the model, we could tailor each tool’s 
specific prompt to achieve the best results managing the process. 
A prime example of LLM-powered orchestration in practice 
is Cursor, a purpose-built, AI-native code editor that has rapidly 
become a benchmark for agentic coding tools. Cursor 
distinguishes itself from traditional IDEs and AI p lugins by 
deeply integrating state-of-the-art models - includ ing GPT-4 
Turbo, Claude Opus 4, Sonnet 4, and Gemini 2.5 Pro - right at 
the core of the developer experience. Its architect ure not only 
supports seamless code completion and refactoring b ut also 
allows for agent-driven workflows, automated bug fixes, in-line 
explanations, and codebase-scale search and reasoning. 
Cursor’s “Auto Mode” dynamically selects the most 
appropriate LLM for each coding task, balancing con text, 
latency, and cost, while “Max Mode” leverages massive context 
windows to enable holistic codebase understanding. The editor’s 
extensibility and its robust plugin ecosystem encou rage the 
development of bespoke agents - test writers, docum entation 
generators, and code reviewers - that operate auton omously 
within the developer’s workflow. According to recen t user 
engagement statistics, Cursor surpassed 500,000 active users by 
mid-2025, with studies showing an average 35% reduc tion in 
boilerplate and debugging time for professional dev elopers. 
These numbers signal not just rapid adoption but a shift toward 
LLM-centric development environments where agentic models 
and observability infrastructure are first-class citizens. 
Meanwhile, Claude Code - Anthropic’s specialized coding 
assistant - exemplifies the power of conversational LLM agents 
designed for the entire software development lifecycle. Built on 
the latest Claude 4 models (Opus 4 and Sonnet 4), Claude Code 
brings advanced long-context reasoning, hybrid step -by-step 
execution, and contextual awareness to code underst anding, 
modification, and review. Its agentic CLI interface enables 
developers to not only generate and edit code, but also perform 
deep codebase navigation, automated testing, and ev en multi-
file refactoring through natural language conversations. 
Enterprise trials report that over 70% of developer s using 
Claude Code experienced faster resolution of techni cal 
challenges, with notable improvements in code quali ty and 
onboarding efficiency. Public engagement figures indicate that 
within weeks of launch, Claude Code had attracted over 100,000 
users, becoming a staple in both startups and large enterprise 
workflows. The platform’s ability to directly manip ulate files,
