Set-shifting Behavioral Test for Harnessed Agents
Ye Ziwei
yeziwei.ml@gmail.com
Abstract
What happens to an LLM agent’s tool choice when the reliable tool silently
changes within an ongoing session? We borrow the notion of set-shifting
from cognitive psychology to study how well agents adapt to hidden
reliability shifts. Our cognitive test for LLM agents mounts libraries of
redundant tools and skills, in which many tools solve the same task but
differ in hidden reliability. Using a branching schedule, we shift the reliable
tool group in the environment and compare it with a stable control, allowing
us to isolate the effect of each shift on the agent’s behavior. We conduct our
study on a panel of LLMs equipped with harnesses and show that the same
set of shifts results in distinct behaviors across models: some latch onto
a fixed routine within a few turns, whereas others continue to vary. Less
capable models often omit the reliable tool group, while frontier models
keep calling it alongside the other groups. We introduce a suite of measures
to quantify agent behavior after reliability shifts. While policy prompting
substantially alters behavior in some tested models, our findings highlight
agents’ brittleness when changes occur in indirectly observable context.
1 Introduction
Humans who repeatedly solve similar problems form habits that simplify future decisions
but can persist past their usefulness. The Einstellung effect captures how people persist
with a learned solution when a better one is available (Luchins, 1942). The Wisconsin Card
Sorting Test (WCST) makes the challenge more difficult by changing the sorting rule without
warning mid-task (Grant & Berg, 1948; Heaton et al., 1993). Meanwhile, reversal learning
paradigms apply hidden changes to value-based choice (Izquierdo et al., 2017). Recent work
ports these cognitive tests to LLMs in textual or visual sorting tasks (Li et al., 2025b; Hao
et al., 2025; Li et al., 2025a).
Modern LLM agents reside in agentic harnesses in which each call to the model arrives
with prior context. These segmented context blocks include tool calls and results, skills and
tool schemas, and system prompts, so the agent never starts from a blank slate. In such
a rich environment, a mounted library of skills and tools may contain several nominally
equivalent capabilities, each calling different APIs and backend services. As with humans,
repeated tool use recorded within the harness context lets the agent converge on a preferred
subset of skills and tools. An agent’s tool preference may outlive an unannounced backend
change, leaving the agent using failing toolsets. To test agent set-shifting, we ask: Can an
agent revise its action route when the reliable tool group changes silently?
We make the following contributions: (i) A behavioral test for harnessed agents based on
redundant tool-skill sets1, libraries of many functionally equivalent tools where the working
subset silently shifts mid-trajectory. (ii) A descriptive framework that characterizes post-shift
behavior as two routing profiles, concentration and retention. (iii) A case study applying
our experimental protocol to a panel of both open-weight and closed-weight LLMs, with
a structuralset framingintervention and an instructionalpolicyapplied across the panel.
Together, these contributions point to a capability-linked pattern in behavior (Figure 6).

2 Behavioral Test
2.1 Tool-Skill Sets and Taxonomy
Definitions.In the agentic harness environment, atoolconsists of a callable function
along with associated metadata and a schema specifying its input and output types. When
invoked, the function either returns a value of the schema-specified output type or returns a
failure message. We definetool groupsas sets of functionally equivalent tools with the same
schema and backend operation but different names and descriptions. Askillis a procedure
paired with one tool group, and the agent learns when and how to invoke tools through a
skill’s instructions. We mount these asredundant tool-skill sets(Figure 1), so that entries for
the same task family differ only in description and hidden reliability.
Cue neutrality.For our pure WCST-like experiments, we use neutral textual descriptions
for all skills, tools, and tasks. User simulations and templates use task-relevant and neutral
vocabulary while varying subject and setting details. Following WCST, there is no lexical cue
toward any specific tool group, and agents discover the active tool group by learning from
binary tool feedback. We vary the surface wording of descriptions to keep agents’ choice of
active tool group from simply tracking the wording of the template. Appendix A.3 reports
an audit for signs of evaluation awareness that may result from modern LLM post-training.
Interventions against neutrality.Furthermore, we perform multiple interventions that
depart from the pure set-shifting paradigm. In the first setup, we vary the cueing with
set framing, altering skill descriptions to cast the groups relative to one another as either
competing providers or a complementary stack. In an alternate setup, we apply a more
instructionalpolicy promptto see if the agent adapts accordingly. We detail both setups in
§4.3 and §4.4.

2.2 Domains and Dataset Construction
We instantiate our test in three domains: scheduling and coordination (3 groups× 5 tools),
DevOps incident triage (4 groups× 5 tools), and multi-cloud storage (5 groups× 2 tools).
Tools in our tests are simulated, with side-effect actions implemented as mocks, and each
mounted set instantiates every relation from Table 1. Scheduling maintains neutral cueing
throughout. We build both framings over the same toolset to form the matched pairs used
in §4.3 for the DevOps and multi-cloud domains.
Each domain mounts one skill per tool group, with the skills loaded simultaneously. Names
within a group draw from a single theme and the naming is parallel across groups. Each
domain also includes a support tool group and side-effect tools, which the verifier blocks
unless the user explicitly asks for that action. Appendix A.2 documents the framework
construction in more detail and Appendix A.4 provides an example of a generated tool-skill
set.
3 Study Design and Evaluation
3.1 Harness and Environment
Setup.We use Hermes Agent (v0.16.0) (Nous Research, 2026), an open-source agentic
harness with an extensive skill and tool mechanism. The study focuses on four models of
varying sizes and capacity. We use two open-weight models, mimo-v2.5 (LLM-Core Xiaomi,
2026) and deepseek-v4-pro (DeepSeek-AI, 2026) in combination with three proprietary
models: gemini-3.5-flash-lite (Google DeepMind, 2026), a fast model for agentic use,
and the frontier model gpt-5.5 (OpenAI, 2026). We serve the open-weight models and
gemini-3.5-flash-lite through OpenRouter and gpt-5.5 through the OpenAI API. Every
agent uses the default Hermes system prompt (as of v0.16.0). Appendix A.1 gives the
sampling settings and remaining configuration.

and is never reliable on no-shift control branches.
We also annotate each target with aprior use role, based on the order in which they first
appear in the run. CA is a reversal target that is reliable early in the prefix and then becomes
unreliable. CB is a reinforced target that remains reliable through the end of the prefix. CC
is a novel target that is never reliable in the prefix. Differences in metrics among groups
should reflect their first appearances in the run. A role-theme permutation ablation confirms
that the differences track prior use rather than the fixed tool group (Appendix C.3).
The tree-based experimental protocol in §4.1, §4.2, and §4.4 uses the scheduling domain
with n= 16 runs. Every domain also supports alinear schedule, a single trajectory with shifts
at fixed turns for cost efficiency. We use this schedule for the set framing intervention on
DevOps and multi-cloud (§4.3) and for the replication on a second harness (§C.1).
Research questions.In this study, we ask the following:
1. When the reliable tool group shifts, does the agent commit to the new tool group,
and how does each prior-use role affect the resulting pattern?
2. Does the depth of an endpoint, or the path taken to reach it, matter beyond the most
recent shift?
3. Does set framing shift which routine the agent settles into?
4. Can an instructional policy prompt affect the lock-in?
3.3 Evaluation metrics
Here we define some metrics over trajectory observations.Set-shifting accuracy Φ measures
whether the agent stays on the reliable group across a trajectory. Per-turnroute-class rates
describe the routing profile at each shift. Thetask-completion rate F records whether the
reliable work is completed, and thesingle-routine ratemeasures rigidity. We use these metrics
to answer the four research questions we pose.

model ordering is unchanged under a turn-normalized share (Appendix B.3).
Task completion.We calculate the proportion of turns that the verifier marks as task-
completing, F. A turn counts when the agent calls at least one tool from the reliable group,
uses every required support tool group, and invokes no side-effect tools. A turn that mixes
the reliable group with unreliable groups still counts as complete.
Single-routine rate.A trajectory holds asingle routinewhen it calls the same set of tool
groups on every route-bearing turn of a post-shift window, and the single-routine rate is the
fraction of windows for which this holds. We use this metric to measure rigidity.
Uncertainty.All reported Φ values carry bootstrap 95% intervals, with paired permutation
tests for sibling contrasts (Appendix A.1).

4.2 Matched scheduled paths add little beyond the current shift (RQ2)
Endpoint depth adds little beyond the current shift. Because Φ multiplies one share per
window, it decreases with depth by construction. The final window share sk remains stable.
For example,mimoreachess k =0.82 at A B Aands k =0.83 one level deeper at A B A A.
The preceding path also has little effect. The paths A→ B→ A→ Band A→ B→ C→ Breach
the same reinforced target through different intermediate groups. Across the tested models,
their final shares differ by at most 0.06.
We find that the current shift has a larger effect: for deepseek, shifting away from the
reinforced target reduces Φ by approximately 0.40 relative to the matched no-shift control.2
Behavior therefore depends more on the current shift than on endpoint depth or the path.
4.3 Set framing shifts routine occupancy (RQ3)
Setup.We vary set framing in the DevOps ( M= 4) and multi-cloud (M= 5) domains,
using 15 turns per phase under the linear schedule. Each domain uses a matched pair over
the same toolset that differs only in framing (Appendix A.3). The complementary condition
presents the groups as parts of one service, each returning its own fields. The competing
condition presents them as rival providers whose reports share one identifier. We measure
routine width ¯w, the mean number of distinct tool groups called per turn.
Results.Competing framing narrows the routine for every model in both domains (Ta-
ble 3). Complementary framing invites a mixed routine spanning all M groups, whereas
competing framing invites commitment to one. In 53 of the 64 matched pairs, the com-
peting side is narrower (sign test p= 1.0× 10−7). The effect is sharpest for gpt-5.5,
whose multi-cloud routine contracts from all five groups to about one. It also appears for
gemini-3.5-flash-liteon multi-cloud (3.5→1.2).
Narrowing the routine does not always improve set-shifting.deepseek-v4-pro,mimo-v2.5,
and gpt-5.5 commit toward the reliable group. Competing framing therefore raises both
their target share and set-shifting accuracy. For example, deepseek’s DevOps Φ rises from
0.02 to 0.26. gemini also narrows sharply on multi-cloud, but it selects a non-target group
and its Φ remains near zero. Framing therefore changescommitment, which improves
accuracy only when the model commits to the target.

4.4 An adaptive prompt mitigates the lock-in (RQ4)
Setup.We append a trajectory-local policy prompt that instructs the agent to reuse the
most recently successful tool and to switch groups after a failure (Appendix A.4). We
evaluate the prompt across the panel. We then compare prompt response with the Artificial
Analysis Intelligence Index, which we use as a coarse capability proxy (Artificial Analysis,
2026).
Results.The adaptive prompt substantially improves set-shifting for gpt-5.5 and
deepseek-v4-pro, but has little effect on mimo-v2.5 and gemini-3.5-flash-lite (Table 4).
Mean accuracy rises from 0.14 to 0.86 for gpt-5.5 and from 0.38 to 0.74 for deepseek-v4-pro.
Novel-window off-target routing falls to zero for both. On deepseek, the prompt also over-
rides the bimodality of §4.1. The regular assistant leaves 9 of 16 ABAC trajectories at s≤ 0.2,
whereas no adaptive trajectory remains in that low mode.
The same prompt barely changes set-shifting accuracy for the other two models and off-
target routing persists. On mimo, the prompt increases novel-window R∗. Within our
panel, model capability coincides both with the observed routing profile and with prompt
response (Figure 6). These models may require stronger prompting, external control, or a
training-based intervention. We leave those alternatives to future work.
5 Related Work
Tool-use benchmarks and redundant tools.Single-session tool-use benchmarks evaluate
tool selection and execution (Yao et al., 2025; Barres et al., 2025; Huang et al., 2024; Patil
et al., 2024; 2025; Qin et al., 2024; Liu et al., 2024). Separate bias studies report fixation
(Blankenstein et al., 2026; Wei et al., 2024), and Faghih et al. (2025) show that for two
tools with identical arguments, description edits alone shift selection. Concurrent work
explore adjacent axes: Liu et al. (2026b) merge and filter redundant tool inventories, Liu
et al. (2026a) evaluate replanning under dynamic tool failures and costs, and Chen et al.
(2026) study failure to update multi-turn reasoning and correct it with single-turn-anchored
reinforcement learning. We differ by combiningwithin-sessionshifts of group reliability
with resumed, branched session state on top of an agentic harness (Yao et al., 2023; Schick
et al., 2023; Shinn et al., 2023; Park et al., 2023; Wang et al., 2024; Packer et al., 2023). The
reinforcement-learning remedy of Chen et al. (2026) is a candidate training-based fix for the
models that resist our prompt, such asmimo.
Path dependence and policy effects.Lee (2026) documents path dependence within a
trajectory, where one off-route call raises the next call’s off-route probability. We extend
this to runs with multiple shifts that separate perseveration from adaptation to the new
reliable tool group. The exploration deficits documented by Krishnamurthy et al. (2024)
predict the failure we observe on mimo. Cao et al. (2026) document agentic degradation
under persona/policy cues, but do not measure perseveration over time.
Choice perseveration and continual learning.The WCST decomposes set-shifting failure
into perseverative errors and failure-to-maintain set (Heaton et al., 1993), formalized as a
framework called Value-Plus-Perseveration (Worthy et al., 2013). Functional fixedness is
the spatial analog of Einstellung’s procedural rigidity (Duncker, 1945). The same construct
surfaces in continual learning as primacy bias (Nikishin et al., 2022) and loss of plasticity
(Dohare et al., 2024). In this work, we import the change protocol into an LLM agent harness.
Cognitive tests on LLMs.The closest cognitive tests for LLMs (Li et al., 2025b; Hao et al.,
2025; Li et al., 2025a) port WCST and set-shifting probes into multimodal settings, but these
works evaluate raw model behavior without context. We close this gap by testing the agentic
version, where the “cards” are functionally callable tools and the branched tree of resumed
sessions carries the harness state these works omit.

completes the task.
Which routing profile is right for a de-
ployed agent?In actual agent use, tar-
get omission may introduce completion
risk from backend drift, with agents re-
taining their previous routes when they
are no longer appropriate (Wang et al.,
2025). While target-retaining breadth pre-
serves coverage, it increases the call footprint, potentially causing higher latency and rate
limit pressure (Liu et al., 2026a). When the reliability of the results is not guaranteed, redun-
dant calls provide fault tolerance (Avizienis, 1985; Dean & Barroso, 2013). The preferred
profile then depends on an agent application’s reliability and latency. Evaluations should
report completion, target retention, and route breadth separately, and maximal focus on the
reliable group is not always desirable.
Can a prompt intervention alter both profiles?Set framing and the policy prompt help
the two capable models but barely move the weaker two. A durable fix likely has to act at
training time rather than through prompting. Multi-turn tool-use RL (Singh et al., 2025) is a
natural candidate for the models that resist our prompt, and continual learning remedies
for primacy bias and loss of plasticity (Nikishin et al., 2022; Dohare et al., 2024) target the
same lock-in. We leave these training-based methods to future work.
What does robust adaptation require?An off-target return to the group that was reliable
just before the shift counts as perseveration only when the agent had actually settled on
that group first. Other off-target trajectories may instead mean the agent never settled on
a single group, or is still exploring older ones (Cohen et al., 2007). In retentive routes, the
agent found the working route but keeps calling alternatives alongside it from lingering
uncertainty and hedging. Robust adaptation entails shifting to the newly reliable route
and inhibiting the alternatives once the evidence turns against them (Miyake et al., 2000;
Diamond, 2013).
7 Conclusion
We introduce a longitudinal behavioral test of set-shifting in which the reliable tool group
changes silently with a matched no-shift control at every shift. Across the panel, agents
adopt a small number of recurring routines and separate into multiple routing profiles.
Future work could explore the potential of making tool reliability stochastic so that no single
outcome marks a shift, and study how memory affects routing over longer trajectories for
more realistic agent use.

A.1 Experimental setup and statistical reporting
Sampling.We use temperature 0.7, top- p 0.95, and medium reasoning effort for all models
if possible. When a serving path does not expose one of these controls, we use the provider
default. All remaining settings use the Hermes Agent defaults.
Uncertainty.We report a non-parametric bootstrap 95% interval for every cell mean of Φ.
For count proportions, we report Wilson 95% intervals. We consider a cell-to-cell difference
supported when the two intervals are disjoint. For paired sibling contrasts, we also report
permutation tests on∆Φ.
The prefix is the resampling unit and corresponds to one branched tree per seed. The
bootstrap samples prefixes with replacement. The permutation test swaps sibling endpoints
within each prefix.
A.2 Schedule construction, session resumption, and verifier
Schedule construction.To keep tool order from determining which group an agent learns
first, we randomize tool presentation across prefixes in two ways. First, we cyclically rotate
the display order of the tool groups. Second, we use the prefix seed to permute the tools
within each group. Within a prefix, both orders remain fixed across all resumed branches.
For each prefix, we save the root session state and recursively resume it for every branch.
Sibling branches begin from the same parent state. For cross-branch comparisons, we use
the nearest common ancestor as the pairing factor.
Redundant tool-skill relations.Each mounted toolset instantiates the three tool-layer
relations in Table 1.Description variantsshare a schema and execution but use different
names. Aquality gradientallows the schedule to shift the active tool group across phases. A

block the wrong action.

following rule. No model participates in verification.

A.3 Cue neutrality, evaluation awareness, and set framing

Evaluation awareness.We find little evidence that the models recognize the evaluation

0.05 over 5 informative-feedback trajectories.
deepseek-v4-pro likewise sticks with its early choice. Two of four replicates reach Φ≈ 0
under both feedback conditions, and its mean barely moves (0.36 versus 0.34,n=4 each).
Thus, an explicit ”backend unavailable” message does not reliably cause either model to
leave the failed group. Sparse feedback alone does not explain the observed rigidity.
Call weighting does not change the model ordering.The primary target share sk pools
all route calls, so turns with more calls receive more weight. To test sensitivity to this
choice, we recompute a turn-normalized share by averaging the target fraction within each
route-bearing turn (Table 7).
Turn normalization raises every model’s share by 0.10 to 0.17, but preserves the comparison
of interest. deepseek-v4-pro remains highest and mimo-v2.5 remains lowest under both
definitions. The other three models remain grouped between them. Thus, the model
comparison does not depend on call weighting.

C.3 Prior use versus tool-group identity
Setup.Each prior-use role maps to a fixed tool group: A is reversal, B is reinforced,

descriptions rather than its history. To separate these explanations, we rerun the tier 1 subset
of shifts on gpt-5.5 under two cyclic remappings of the physical groups to roles. The tools,
skills, and schedule remain unchanged, withn=2 prefixes per mapping.
Results.The role ordering holds under both remappings (Table 10). The novel role retains
the lowest target share. Off-target routing remains near zero, and departures remain breadth-
dominant. Thus the effects track prior use rather than tool-group identity.
