ABSTRACT Tool-using large language model (LLM) agents fail when external interfaces evolve, yet most
evaluations emphasize static competence rather than adaptation under drift. We studied this problem with
controlled schema, policy, and toolset perturbations derived from tau2-bench retail tasks and distinguished
between a reference-guided replay benchmark and reference-free adaptation. In a reference-guided exact-
trajectory setting, GPT-4o mini reached 0.708 task success over 216 trials, establishing that the benchmark
contains recoverable structure. We then evaluated five OpenRouter-served models—GPT-4o mini, GPT-4o,
Kimi K2, DeepSeek V3, and Qwen3-32B—under a reference-free protocol scoring end-state task completion
across 270 trials per model-condition cell (30 scenarios × 3 episodes× 3 drift families). Static baselines
range from 0.130 to 0.432 across models. Blind replay consistently degrades reference-free task success
relative to static for four of five models; Kimi K2 is the exception, for which both blind replay and rules-only
significantly improve over the static baseline. Rules-only shows model-dependent effects, significantly
improving for Kimi K2 and Qwen3-32B while showing no significant difference for the remaining three
models. A normalization-ablation condition confirms that the drift-inversion layer is load-bearing for toolset
drift; schema-obedience determines whether this layer is effective. Within the three evaluated drift types and
controller conditions, the reference-guided replay advantage does not transfer to reference-free task success,
and the primary barriers are hidden-state reconstruction and branch selection across multiple candidate orders
and products.

I. INTRODUCTION
Large language model (LLM) systems are increasingly
deployed as agents that plan, invoke tools, retain useful
experience, and improve behavior over time. In that setting,
learning is not only a training-stage concept; it is an
operational requirement. A useful agent must adapt when
tasks recur, when feedback accumulates, and when the
environment no longer matches the assumptions baked into
its tool definitions. Dedicated surveys on continual learning

This broader problem is naturally framed as continual

and reusing experience under changing conditions [5], [6],

Tool-using agents expose this gap sharply. In real deploy-
ments, tool-facing environments drift through argument-
schema changes, policy-anchor requirements, and tool
renaming. Empirical studies show that even modest perturba-
tions to tool names, parameter names, and response schemas
substantially degrade agent reliability, revealing that current
models overfit to surface metadata rather than underlying
tool semantics [11], [12]. At the same time, realistic tool-use
benchmarks show that end-to-end reliability remains low and
that headline capability claims can be distorted by benchmark
and API instability [13], [14]. The practical importance of
this problem is therefore larger than a narrow tool-calling
bug: if LLM agents are to function as learning agents in
production, they must adapt to interface drift in ways that are
measurable, reproducible, and stronger than static prompting
or hand-written repair rules.
This study targets that gap with a controlled protocol
designed around drift robustness rather than static benchmark
score maximization. We evaluate three research questions.
RQ1 asks how much performance a reference-guided replay
condition can recover under matched schema, policy, and
toolset drift. RQ2 asks whether memory-based controllers
still improve outcomes once evaluation-time reference access
is removed and success is measured on the upstream environ-
ment rather than by exact trajectory imitation. RQ3 asks what
failure modes persist across the three evaluated reference-free
controller conditions and what the normalization-ablation
condition reveals about the drift-inversion layer’s contribu-
tion to toolset recovery.
Our contributions are threefold. First, we introduce a
controlled drift benchmark that isolates three mechanically
verifiable drift types and separates a reference-guided upper-
bound condition from a reference-free adaptation regime—
providing a diagnostic decomposition framework rather than
a new algorithm. Second, we provide a reference-free task-
success evaluation path on the upstream tau2 retail envi-
ronment that executes drift-normalized tool calls and scores
end-state task completion, enabling reproducible comparison
of controller conditions without requiring reference trajec-
tories. Third, we report empirical results from five models
across three drift families showing that reference-guided
replay performance does not transfer to the reference-free
regime under the three evaluated controller conditions, that
blind replay consistently degrades performance for four of
five models while rules-only shows model-dependent effects,
and that hidden-state reconstruction and branch selection are
the key barriers for deployable drift adaptation within this
evaluation scope.
II. RELATED WORK
Prior work establishes that realistic tool-use reliability
remains low when evaluation moves beyond single-turn invo-
cation toward multi-step interactive sessions. WildToolBench
reports that no evaluated model exceeds 15% session accu-
racy under multi-turn, multi-task conditions with implicit
user intent and instruction transitions [13]. In adjacent
interactive environments, WebArena, OSWorld, and Web-
V oyager similarly report substantial end-to-end gaps under
long-horizon web and operating-system tasks [15], [16], [17].
StableToolBench adds an evaluation-stability perspective by
showing that tool availability and API drift can materially
change observed performance, motivating controlled and
repeatable tool-evaluation infrastructure [14]. Together, these
studies motivate treating tool-use performance as a robustness
and adaptation problem rather than a static capability score.
The three drift operators evaluated here—argument-key
renaming (schema drift), tool-name remapping (toolset drift),
and prerequisite-step insertion (policy drift)—correspond to
the most common breaking-change categories documented
in API evolution studies: parameter renaming, endpoint
renaming, and new mandatory preconditions. API stability
analyses of publicly available interfaces consistently find
that breaking changes of these types appear frequently
across version histories and that clients without explicit
adaptation logic fail silently or with misleading errors [14].
Our controlled-injection protocol differs from empirical API
evolution studies in a key respect: rather than observing
naturally occurring drift in production systems, we inject
precisely specified, bijective drift under a known inversion
manifest, enabling causal isolation of the adaptation problem
independent of drift-detection overhead. This design makes
the evaluation analytically tractable but explicitly scopes
our findings to the subproblem of adapting to drift once
it has been detected and inverted—a simplification we
acknowledge in Section VI.
Each drift operator maps onto a realistic deployment ana-
log. Schema key rename corresponds to versioned REST API
field renames—a common breaking change in API evolution
where a renamed request parameter invalidates all prior client
integrations that do not explicitly handle the new key. Policy
step prepend corresponds to newly mandated consent flows
or two-factor authentication gates introduced by regulatory
or compliance changes, where an agent that was previously
effective must now issue an additional confirmation action
before any task-relevant call. Tool-name remap corresponds
to service consolidation or vendor switching, where an
endpoint is migrated to a new provider with a different
naming convention while preserving the underlying argument
schema and semantics. These real-world analogs establish
that the three controlled drift operators are not arbitrary
synthetic perturbations but representative instantiations of
the most common categories of breaking interface change
encountered in production deployments.

Two evaluation frameworks closely aligned with our
end-state scoring approach are Agent-Diff [19] and MCP-
Bench [20]. Agent-Diff benchmarks LLM agents on enter-
prise API tasks (Slack, Box, Linear, Google Calendar) by
defining task success as whether the expected state-difference
(1S) was applied to a sandboxed environment, closely
analogous to our binary DB-state match; the key distinction is
that Agent-Diff targets closed-world invariants in stable API
settings, while our protocol introduces programmatic drift on
a fixed environment. MCP-Bench evaluates tool use across
28 live MCP servers spanning 250 tools, stressing cross-tool
coordination, schema compliance, and tool disambiguation
under fuzzy instructions without explicit tool names; its focus
on multi-server orchestration and naming inconsistencies
bears directly on our schema and toolset drift families. For
the hidden-state reconstruction bottleneck identified in this
paper, Y ang et al. propose STITCH—structured indexing
of trajectory steps with a contextual intent cue comprising
the latent goal, action type, and salient entity types,
enabling intent-compatible memory retrieval and coreference
suppression [21]; a STITCH-like belief store could directly
target the order/product disambiguation failures observed
in this study. Finally, RDumb ++ [22] extends continual
test-time adaptation with entropy-based and KL-divergence
drift detectors that trigger principled model resets, replacing
fixed periodic schedules; integrating such mechanisms would
remove the manifest-drift assumption (the requirement that
the drift bijection be known in advance) and increase
ecological realism in our evaluation protocol.
Continual-learning research provides the main techni-
cal basis for replay as an adaptation mechanism. Online
Continual Learning with Maximally Interfered Retrieval
shows that replay improves retention when memory sampling
prioritizes examples most vulnerable to interference [8].
Subsequent work studies replay selection and stability-
plasticity trade-offs under different resource and drift
regimes, including abrupt representation-change control,
adaptive memory replay, dual-branch online continual learn-
ing, robust self-adjusting ensembles for drifting streams,
and adaptive memory realignment for concept drift [9],
[23], [24], [25], [26]. These findings consistently indicate
that replay quality, not only replay existence, governs
adaptation outcomes. However, most evidence is derived
from classification-style continual-learning streams, leaving
open whether replay can transfer to tool-calling agents
where failure is dominated by structured action errors and
interface-level drift.
Recent studies on agentic-system design broaden context
but also highlight gaps in explicit drift adaptation. A health-
care agent survey with seven-dimensional taxonomy reports
that adaptation-oriented capabilities such as drift detection
and mitigation are rarely implemented, despite growing
use of planning and tool-using agents [4]. The deployment
momentum of agentic systems in consequential real-world
settings establishes that agents face these interface-change
challenges in practice—yet no prior controlled evaluation iso-
lates the causal contribution of replay under matched schema,
policy, and toolset drift. The present study addresses that
gap with a replay-centered protocol and explicit static/rules
baselines under matched holdout conditions.
Several complementary threads further contextualize the
reference-free adaptation problem. Reasoning with Language
Model is Planning with World Model (RAP) [27] demon-
strates LLM-based planning with explicit world-model
rollouts, showing gains within stable interfaces; our results
suggest that interface drift can break stored plan templates
regardless of planning quality. Gorilla [28] evaluates LLM
tool-call faithfulness at scale and finds that hallucinated or
misformatted tool calls remain a persistent failure mode even
without drift—a baseline difficulty that our drift conditions
compound. WebRL [29] closes end-to-end gaps in web
agents via self-evolving curriculum reinforcement learning;
translating this to our setting would require an online RL
signal from the upstream environment evaluator, which
is a promising but substantially more resource-intensive
direction than the replay-based controllers evaluated here.
In continual-learning settings, Aljundi et al. [30] show that
gradient-based sample selection—framed as minimizing
interference constraints—improves replay quality in online
continual learning, reinforcing that replay quality governs
adaptation outcomes more than replay quantity. WILDS [31]
provides a multi-domain benchmark for distribution shift that
shares the ethos of our controlled-drift protocol; our study
differs by targeting structured, programmatic interface drift
rather than covariate shift in model inputs.
Planning and memory agents provide relevant prior art
for the memory-based controllers evaluated here. ReAct [32]
interleaves chain-of-thought reasoning with action gener-
ation, demonstrating that structured reasoning traces can
improve tool-call accuracy in multi-step tasks. Reflexion[33]
extends this approach by adding verbal reinforcement
over episode transcripts—a form of experience replay
analogous to our memory-cue retrieval, but operating over
self-generated critique rather than stored action templates.
V oyager[34] demonstrates open-ended skill accumulation
in embodied environments through a curriculum over stored
skill programs, motivating the idea that replay quality
and retrieval structure matter for long-horizon agents. The
contrast between these planning-memory agents and our
reference-free results is instructive: prior gains from replay
and reflection typically operate within a fixed interface,
whereas our evaluation exposes the additional challenge
posed by interface drift that breaks stored action templates
at the call-structure level. This contrast motivates treating
interface-level drift adaptation as a distinct evaluation
problem rather than an extension of in-context memory or
reflection.

We evaluated adaptation under controlled tool drift on
a retail-domain task set adapted from tau2-bench [35].

experiment’s compute budget: two OpenAI models spanning
that provider’s frontier range, and three Chinese frontier
models from distinct providers (Moonshot AI, DeepSeek,

across diverse model families; the omission of Anthropic
frontier models (Claude Opus, Claude Sonnet) is noted
as a limitation in Section VI. All model calls used
greedy decoding (temperature = 0) with no nucleus
sampling; the scenario-shuffle random seed was fixed at
20260310 for reproducibility. No additional system prompt
was used beyond the per-scenario task description and
tool definitions provided by the tau2 retail environment.
We injected three drift families at inference time. Schema
drift renames one or more required argument keys in the
tool schema while preserving semantics (e.g., order_id
→ order_ref). Policy drift requires that a designated
policy-confirmation tool call be issued as the first action
of any episode; any other tool call issued before this
confirmation is rejected by the upstream environment
with an error response, effectively blocking progress until
the agent issues the confirmation. Toolset drift remaps
tool names to new identifiers (e.g., cancel_order→
terminate_order) while preserving argument schemas
and semantics. Train and eval sets were disjoint by scenario
ID while remaining in the same retail-domain pool and using
the same drift operators.
Figure 1 provides an overview of both evaluation paths.
This study separates two evaluation regimes. The first is
a reference-guided upper-bound condition designed as a
deterministic upper-bound comparator. In that setting, replay
memory stores train-derived signatures and, after retrieval,
activates deterministic replay against the scenario reference
trajectory; success is measured by exact-trajectory imitation.
This regime establishes that the benchmark contains recover-
able structure: under reference-guided deterministic replay,
GPT-4o mini reached 0.7083 task success over 216 eval
trials (95% CI [0.6428, 0.7680], Clopper–Pearson). The
216 eval trials for the reference-guided condition come
from a separate reference-guided evaluation run of 24 eval
scenarios × 3 drift families × 3 episodes, using the
exact-trajectory imitation evaluator; this run is independent
of the reference-free evaluation (30 eval scenarios × 3 drift
families× 3 episodes = 270) reported in the remainder
of this section. The reference-guided condition is not a
deployable reference-free adaptation setting, and the two
evaluators are incommensurable—exact-trajectory imitation
versus end-state task completion—so no direct subtraction
across regimes is warranted.
The second regime is the main evaluation for this paper:
reference-free task success on the upstream tau2 retail envi-
ronment. In this regime, drifted tool names and argument keys
are normalized back to the upstream API by a deterministic,
rule-based mapping layer. Drift operators applied during
injection are bijective: each drifted name or key has exactly
one upstream counterpart specified in the drift manifest.
The normalization layer inverts this mapping before each
tool call is dispatched to the upstream environment, so the
environment evaluator always receives calls in the canonical
upstream schema. Normalization failures can occur when an
agent produces a tool name or key that was not part of the drift
manifest (e.g., a hallucinated tool name); in such cases, the
call is passed through unchanged and typically produces an
upstream error. In the primary reference-free evaluation runs,
the normalization failure rate was zero: no agent produced a
tool name or argument key outside the drift manifest across
any of the up to 270 eval trials per model-condition cell and
across all three controller conditions (static, rules-only, and
blind replay). This indicates that normalization failures are
not a source of noise in the reported success rates under
the current drift protocol. These pass-through failures are
included in the task-failure count and thus conservatively
penalize the agent. The normalization layer itself is not a
source of agent capability: it does not repair malformed
argument values, does not infer missing required fields, and
does not select among multiple plausible branches. Model
tool calls are executed against the real environment, and
success is scored by the upstream environment evaluator
using end-state task completion rather than exact imitation
of one gold sequence. The toolset-drift results reported
in Section IV should be interpreted within the scope of
this bijective-scaffold assumption: the evaluation isolates
adaptation difficulty under known-manifest inversion and
does not measure the combined problem of autonomous drift
detection plus adaptation. The upstream evaluator computes
a binary reward via database-state match: after all agent tool
calls are executed, the final database state (order records,
product inventory, user account fields) is compared against
the expected post-task ground-truth state. A trial is scored

Replay memory in the reference-free setting used keyed
retrieval over task-pattern signatures and drift type. Each
memory entry was indexed by three fields: task type (the
top-level retail action, e.g., exchange, return, cancel), drift
family (the injected drift operator: schema, policy, or toolset),
and source scenario identifier (the train scenario from
which the entry was derived). Retrieval used exact matching
on task type and drift family; source scenario identifier
served as a tiebreaker when multiple entries matched.
We did not experiment with dense semantic encodings or
embedding-based approximate retrieval; template-signature
matching was chosen to isolate the effect of structured
drift-type cues from unstructured similarity search.
Controller stack. Three reference-free controller condi-
tions share the same base LLM call and differ only in which
repair stages are active at each step. Given a scenario, drift
metadata, memory store M, enabled rule set R, and step
hints H , each episode step proceeds as follows:
1) LLM call: invoke the model with current messages and
tools at temperature= 0, obtaining predicted actionˆat .
2) Memory-cue repair (active in the blind-replay condi-
tion when H [t] exists): overwrite or augment ˆat with
the step-t hint retrieved from M.
3) Rule repair (active when R̸=∅): apply deterministic,
drift-type-specific fixes toˆat . For schema drift : remap
any drifted argument key to its canonical form. For
policy drift : prepend the required policy-confirmation
call if the agent’s first action omits it. For toolset drift :
rewrite the predicted tool name if it matches a known
remapped form.
4) Execute the (possibly repaired) action against the
upstream environment; update the state cache from the
returned observation.
Static uses step 1 only. Rules-only uses steps 1 and 3. Blind
replay uses steps 1 and 2 (hint at step 0 only), reflecting that
retrieval is attempted without access to reference trajectories.
None of these controllers was allowed to access evaluation
reference trajectories. More elaborate controller variants—
multi-step memory cues, observation-based argument repair,
and planning-augmented disambiguation—are discussed in
Section V as candidate directions for future evaluation; they
were not evaluated in this study and their mechanistic descrip-
tions are omitted from this section. Adaptation in this study
refers to pre-episode context augmentation (memory cues and
repair rules); within-episode error-driven adaptation—where
the agent revises its behaviour in response to environment
error messages during execution—is outside the scope
of the current evaluation. No updated documentation is
provided to the agent during the drift phase: the drifted tool
schema is presented as authoritative, and the normalization
layer silently inverts drift mappings before dispatch without
informing the agent that any interface change has occurred.
The primary estimand in the reference-free regime was
mean binary task success on eval trials under the upstream
environment reward. Secondary diagnostics included average
matched steps and memory-activation counts. We report the
reference-guided replay result as motivating evidence for
the two-regime evaluation design and treat the reference-
free task-success results as the main causal evaluation for
adaptation claims.
With n= 270 binary trials per model-condition cell and a
two-tailed test at α= 0.05, the design achieves 80% power
to detect a difference in success rates of approximately 0.12
(12 percentage points). The primary finding—blind replay
consistently underperforming static—involves observed dif-
ferences ranging from 0.06 to 0.26 across models, all above
this detection threshold. Rules-only effects are smaller and
model-dependent (ranging from −0.09 to+0.08 relative to
static); the design is adequately powered to detect or rule
out effects at this scale, though individual between-model
comparisons at smaller effect sizes remain underpowered.
The two evaluation regimes serve as complementary ana-
lytical lenses rather than competing measurement conditions.
The reference-guided condition establishes that recoverable
structure exists in the benchmark: when a complete repair
trajectory is provided, high task success is achievable—
the upper-bound ceiling exists. The reference-free con-
dition establishes whether in-context adaptation strategies
can close the gap under operational conditions without
reference access. The contrast between the two regimes is
a decomposition argument, not a direct score comparison:
incommensurable evaluators preclude direct subtraction, but
the gap motivates the conclusion that the binding bottleneck
is hidden-state reconstruction and branch selection, not
execution of a known repair.

V. DISCUSSION
The main finding is diagnostic rather than algorithmi-
cally novel: once evaluation-time reference trajectories
are removed and success is defined by real environment
completion, the reference-guided replay advantage does not
transfer to the reference-free regime. Static baselines span a
wide range across the five models—from 0.130 (Kimi K2)
to 0.432 (Qwen3-32B). Blind replay consistently degrades
performance relative to static for four of five models; Kimi
K2 is the exception, for which blind replay is significantly
better than static. Rules-only shows model-dependent effects,
significantly improving over static for Kimi K2 and Qwen3-
32B while showing no significant difference for GPT-4o
and DeepSeek V3. These outcomes establish that reference-
guided replay should be interpreted as an upper-bound bench-
mark condition, not as evidence that reference-free adaptation
under drift is solved within the evaluated controller set.
The cross-model pattern is consistent with the hypothesis
that the binding bottleneck has shifted from ‘‘can the
system remember a previous action template?’’ to ‘‘can
the system reconstruct the right hidden state and choose
the correct branch among multiple plausible orders, products,
and variants?’’ Blind replay—the strongest memory signal
available in these experiments—did not improve outcomes
for four of five models; for Kimi K2, where blind replay
was effective, the improvement was uniform across all
three drift families rather than drift-type specific, suggesting
model-level retrieval coherence rather than drift-specific
reasoning. This hypothesis is consistent with the observed
data but not confirmed mechanistically; the failure-mode
evidence described below provides supporting but indirect
evidence.
A mechanistic account of why blind replay degrades
performance is as follows. The blind replay controller
retrieves a step-0 hint derived from a training episode, which
encodes a specific entity identifier—an order ID, product
variant, or customer record—from the training task. Under
drift, the model incorporates this entity into its tool call not
because it misunderstands the task structure, but because the
retrieved hint presents a plausible-looking action cue that
the model cannot distinguish from the current task’s target
without access to the full hidden state. The result is that the
agent operates on the wrong branch (wrong order, wrong
product) and either terminates with an incorrect database
state (premature termination) or exhausts its step budget
searching for a consistent sequence (step-limit exhaustion).
This mechanism is specific to replay-as-implemented-in-
this-design—a single step-0 hint retrieved by task type and
drift family, without trajectory-level context or intent-cue
indexing—and does not constitute a claim about replay as a
category of adaptation strategy. More sophisticated retrieval
mechanisms, such as STITCH-like intent-cue indexing with
latent goal and salient entity encoding [21], might avoid the
branch-confusion failure while still employing a replay-based
design; the negative result here is therefore scoped to shallow,
single-step hint retrieval under the current protocol.
Disaggregating the 270 eval trials by drift family reveals
modest per-drift variation. For GPT-4o mini static, schema-
drift yielded 37/90 (0.411), policy-drift 39/90 (0.433), and
toolset-drift 31/90 (0.344)—a spread of 0.089, with toolset

that drift type is not the primary driver of task difficulty
for these models. Kimi K2 similarly shows near-uniform
static performance across drift families (schema 13/90 =

deployed models are schema-obedient; models that fall

Examining episode-level failure records provides behav-

all conditions, invalid-tool-call rates are effectively zero,

within budget). In the GPT-4o mini static condition, 136 of

model, this distribution shifts markedly: 92 of 209 failures

the model to search longer but does not provide the
hidden-state disambiguation needed to select the correct

A representative schema-drift case study illustrates the
branch-selection mechanism directly. In the static condition,
the agent receives the current task description and tool
schema, with the drifted argument key (e.g., order_ref)
transparently mapped back to order_id by the drift-
inversion layer. The agent issues a single-step tool call
to the correct order record and the environment returns
db_match=True. In the blind replay condition, the same
model additionally receives a memory cue derived from a
training episode for the same task type; the cue references a
specific order identifier from the training record. The agent
incorporates this identifier into its tool call—selecting the
training-set order rather than the current task’s target order—
and terminates having modified the wrong database record
(db_match=False). The model had the correct tool format
and action type, but the memory cue introduced a plausible
yet incorrect identifier that the agent could not distinguish
from the current task’s target without access to the full hidden
state.
The bijective normalization layer is an analytical isolation
mechanism rather than a deployable adaptation strategy.
By specifying the drift inversion in advance and applying
it transparently at the environment boundary, the evaluation
separates ‘‘can the agent adapt its behavior once the interface
change is known?’’ from ‘‘can the agent autonomously
detect that an interface has changed?’’ This decomposition
isolates adaptation difficulty—branch selection and hidden-
state reconstruction—independently of drift-detection over-
head, making the evaluation tractable and reproducible.
It deliberately defers the harder problem: in production
deployments, agents must detect interface changes and infer
new schemas without a pre-specified manifest. Studying
agents that must both detect and repair schema changes
without such a manifest is an important open problem, noted
further in Section VI.
A low-cost alternative hypothesis for the model-dependent
effects in rules-only conditions is that a drift-aware meta-
prompt—a task-level prompt explicitly informing the model
about expected interface changes—could achieve similar
or better results without an online rule-injection infras-
tructure. Testing this hypothesis is an important future-
work direction, particularly for the models where rules-only
shows positive effects. More elaborate controller variants—
multi-step memory cues, observation-based argument repair

Two additional evaluation directions are highlighted
by the current findings. First, within-episode error-driven
adaptation—where the agent uses tool-call rejection signals
or database-mismatch feedback to update its approach mid-
episode—was not evaluated here. Error signals are available
in the environment, and a credible future direction is
whether error-driven within-episode adaptation can close the
branch-selection gap without requiring cross-episode mem-
ory. Second, a documented-but-ambiguous drift condition—
where the agent is provided a changelog indicating that
interface drift occurred but without a complete inversion
manifest—represents an intermediate setting between the
bijective-inversion protocol studied here and full unsuper-
vised drift detection. Studying agent performance under
partial specification is a natural extension of the current
evaluation framework.
The retail domain was selected because tau2-bench pro-
vides reproducible multi-step transaction tasks with observ-
able database state, making success verification tractable.
All conclusions in this paper are scoped to this domain and
evaluation; external validity to other tool-use environments
remains to be established. More structured domains—SQL-
based enterprise query interfaces, medical record APIs,
industrial control systems—are likely to exhibit distinct
drift sensitivity patterns and adaptation challenges, and
empirical evaluation across domains is needed to assess
generalizability.
The hidden-state reconstruction problem maps naturally
onto partially observable Markov decision process (POMDP)
formulations of sequential decision-making [37]. In a
POMDP framing, the agent maintains a belief state over latent
environment variables (order identifiers, product variants,
payment and address records) and must select actions that
are robust to belief uncertainty. The reference-free controllers
evaluated here lacked any explicit belief-state representation:
they committed to write actions without first resolving
ambiguity over which order or product branch was relevant,
leading to the branch-selection failures that account for the
majority of task failures. A credible adaptation gain will
likely require explicit state reconstruction, better candidate-
branch scoring, or environment-aware planners that can
query for missing latent variables before committing to write
actions—belief-tracking approaches such as entity stores,
order-state graphs, or schema-aligned world models represent
principled directions for closing the adaptation gap identified
in this study. STITCH-style structured intent tuples [21] and
entity-type indexes represent a concrete instantiation of this
direction that could be adapted to the tau2 retail domain.
VI. LIMITATIONS
Several limitations constrain interpretation. All conclusions
in this paper are explicitly scoped to the three evaluated
drift types (schema key rename, tool-name remap, policy
step prepend), the 30-scenario retail-domain evaluation set,
and the three reference-free controller conditions (static,
blind replay, rules-only). Findings may not generalize to
other drift types, domains, or controllers without additional
experimental validation.
First, the three evaluated drift types represent a narrow and
controlled slice of real-world interface drift. More complex
forms—type changes and argument removal (schema drift),
multi-step policy reordering (policy drift), and partial depre-
cation with fallback (toolset drift)—raise distinct evaluation
challenges and are identified as priority extensions. Second,
all evaluated tasks are domain-specific to the tau2 retail
environment; external validity to other tool ecosystems is not
established.
Third, the reference-free evaluation used 30 eval scenarios
and 3 episodes per condition, yielding 270 trials per cell.
Individual pairwise comparisons at small effect sizes remain
statistically underpowered, as noted in Section IV; the
inferential claims rest on the cross-model and cross-condition
pattern rather than any specific pairwise difference. Fourth,
the controller comparison is limited to three conditions;
multi-step memory cues, observation-based argument repair,
and planning-augmented variants were not evaluated. The
evaluation therefore cannot confirm whether more elabo-
rate controllers would show a different pattern. Fifth, the
upper-bound and reference-free task-success evaluators are
incommensurable by design: the former is exact-trajectory
imitation, the latter is end-state task completion; the upper
bound should not be read as a directly comparable deployable
condition.
Sixth, the bijective normalization layer defers the drift-
detection subproblem: in production deployments, agents
must autonomously detect interface changes and infer new
schemas without a pre-specified inversion manifest. The
current protocol isolates adaptation difficulty under known-
drift conditions; studying agents that must both detect and
repair schema changes without a manifest is an important
open problem discussed in Section V. Seventh, token-level
cost and latency were not instrumented; precise per-episode
token counts and wall-clock latency were not logged, and
future evaluations should instrument these metrics to quantify
the overhead of more elaborate controllers relative to static
prompting.
Eighth, all five models were accessed via OpenRouter
during a defined experiment window (2026-03-10) using
the identifiers recorded in Section VIII. OpenRouter model
providers may silently update underlying weights without
changing the version identifier string; exact reproduction at
a later date is therefore not guaranteed despite the detailed
episode-level archive. Ninth, the evaluated model set does
not include Anthropic frontier models (Claude Opus, Claude
Sonnet), which are widely used as agent-task benchmarks.
Their omission is a genuine gap; including them would

Tenth, within-episode error-driven adaptation—where the

reference-free evaluation settings.
VII. CONCLUSION
This study contributes a controlled-drift benchmark and two-
regime evaluation methodology for tool-using LLM agents,
separating a reference-guided upper-bound condition from
a reference-free adaptation regime across three mechan-
ically verifiable drift types. The primary contribution is
methodological and diagnostic rather than algorithmic: the
evaluation framework exposes that reference-guided replay
advantage does not transfer to reference-free task success
within the evaluated controller set. Within the 30-scenario
retail-domain evaluation and three drift types, blind replay
consistently degrades task success relative to static for four
of five models, while rules-only shows model-dependent
effects—significantly improving over static for Kimi K2 and
Qwen3-32B and showing no significant difference for the
remaining three models. A normalization-ablation condition
further shows that the drift-inversion layer is load-bearing
for toolset recovery, with its benefit mediated by schema-
obedience. Within this scope, the primary unsolved problem
is not access to action cues but hidden-state reconstruction
and branch selection across multiple candidate orders and
products. Future work should prioritize environment-aware
state retrieval, error-driven within-episode adaptation, and
broader reference-free benchmarks across domains and drift
types, rather than treating replay alone as sufficient evidence
of solved adaptation.
