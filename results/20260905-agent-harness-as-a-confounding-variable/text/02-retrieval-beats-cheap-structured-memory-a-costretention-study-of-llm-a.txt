Abstract
Large language model (LLM) agents that re-send an expanding conversation history incur token costs
that grow quadratically over a multi-turn task. Many memory designs promise to bound this cost, but
their retention/cost trade-offs are frequently measured only on short or synthetic data. This paper
is a controlled cost–retention study of seven memory strategies—full context, truncation, running
summary, append-only notes, cheap-extractor fact slots, sparse BM25 retrieval, and a slots+retrieval
hybrid—evaluated on real, human-annotated long-conversation benchmarks (LoCoMo and LongMemEval)
with an LLM-as-judge protocol and question-level paired statistics. Three findings emerge. First,
BM25 retrieval is the strongest cheap memory: on LoCoMo ( n=160 questions over conversations
of 369–680 turns) it cuts real input tokens by 98% and cost to 4.8% of full context while holding
retention level with it (39.4% vs. 30.6% point estimates; paired sign test p=0.09, a non-significant trend
whose confirmation a power analysis places at≈360–430 questions), and it is significantly better than
truncation (p<0.001). Second, we report a negative result with a diagnosis: latest-value fact slots written
by a cheap 8B extractor—a structured memory we hypothesized would excel at fact updates—are
the weakest memory method on both benchmarks, including on LongMemEval’s knowledge-update
category (n=72; 37.5% vs. 73.6% for retrieval). An extractor-size ablation isolates the cause: swapping
the 8B extractor for a 70B model raises slot retention by +29.2 points (paired sign test, 23 wins vs. 2
losses, p<10−4), showing the extractor, not the slot representation, is the bottleneck—but the stronger
extractor costs 1.8× full context on these histories, so the cheap-cascade premise itself is what fails.
Third, an error analysis over all 281 LoCoMo multi-hop questions shows sparse retrieval recovers
only∼13% of gold evidence turns, localizing exactly where retrieval-based memory still fails. A
further LongMemEval evaluation over temporal, multi-session, and abstention questions ( n=254)
sharpens the boundary of the claim: on these short-history, dispersed-evidence categories full context
leads, BM25 trails it significantly (−10.2 points, p=0.004), and only the slots+retrieval hybrid stays
statistically indistinguishable from it—so retrieval-based memory is the right trade at long horizons
and point lookups, not universally. We release the full harness, benchmark adapters, judge, and
per-question results.

1. Introduction
Autonomous LLM agents perform multi-step reasoning, tool calls, and context re-stacking,
consuming tens of thousands of tokens per task [ 6,8]. The problem intensifies as conversations
lengthen: if each step re-sends the growing history, the cumulative token cost of a k-turn task grows as
O(k2) rather than linearly, and realistic retry rates and parallel instances multiply the bill [7]. Enlarging
the context window is not a free remedy: long-context models exhibit a “lost in the middle” effect,

where information away from the edges of a long prompt is poorly utilized [ 3], and self-attention
makes each additional token quadratically expensive in compute [1].
A range of mitigations exists—semantic caching [11], history summarization [5], model cascading
[9], prompt compression [2], and hierarchical or virtual memory [1]—but their retention/cost trade-offs
are often evaluated on short dialogues, synthetic planted-fact probes, or self-generated data, and most
summarization pipelines use the same expensive model for both compression and synthesis. Whether
a genuinely cheap memory pipeline preserves the information an agent needs at realistic conversation
lengths is, in our reading, under-measured. Prior work on agent memory likewise calls for structured,
persistent approaches beyond simple summarization [4,6,10], but rarely quantifies what such structure
costs or saves on human-annotated long conversations.
This paper is a controlled empirical study of that question. We compare seven memory strategies
under one harness, one synthesizer, and one judge: (1) full context, (2) truncation, (3) running summary,
(4) append-only extracted notes, (5) a fact-slot memory in which a cheap small model extracts durable
subject–predicate facts into a latest-value table, (6) sparse BM25 retrieval over past turns, and (7)
a slots+retrieval hybrid. Strategy (5) embodies a hypothesis we set out to test: that applying the
model-cascading insight [9] to the memory step—a cheap extractor writes, an expensive model only
synthesizes—yields a structured store that is both cheaper than summarization and better at fact
updates, since a latest-value table overwrites stale values by key.
Concretely, this paper makes the following contributions:
1. A controlled seven-strategy comparison on two real, human-annotated long-conversation bench-
marks (LoCoMo, LongMemEval) with LLM-as-judge scoring, per-category breakdowns, question-
level paired sign tests with bootstrap confidence intervals, and an explicit power analysis stating
which comparisons the sample sizes do and do not support (Sections 5–6).
2. A negative result on cheap structured memory, with an ablation that isolates the cause: fact
slots written by an 8B extractor are the weakest memory method on both benchmarks—including
on LongMemEval’s knowledge-update category, their intended use case—and an extractor-size
ablation shows the extractor, not the representation, is the bottleneck: a 70B extractor recovers
+29.2 points (p<10−4) but erases the cost advantage (Section 6.4).
3. An error analysis of sparse retrieval on multi-hop questions: over all 281 LoCoMo multi-hop
questions, BM25 top-5 recovers only∼13% of gold evidence turns; we identify three structural
failure modes (lexical–semantic gap, evidence fragmentation, inference gap) that motivate dense
and iterative retrieval (Section 6.3).
4. An open-source harness with benchmark adapters, the judge, per-question records, and paired-
analysis scripts (Section 7).
The headline result: at realistic conversation lengths, BM25 retrieval and the slots+retrieval hybrid
cut real input tokens by over 96% and cost to 5–9% of full context while holding retention level with it,
and they are significantly better than truncation (p<0.001). Their point estimates exceed full context
(39.4% and 38.8% vs. 30.6%), but the paired test shows only a non-significant trend (p=0.09–0.12); we
state this scope explicitly rather than overclaim. The largest retrieval gains are on single-hop, open-
domain, and temporal questions; full context retains an edge on multi-hop, and our error analysis
explains why. These results, which reverse an earlier short synthetic pilot of ours, suggest that for
practitioners the strongest cheap lever is retrieval, not structured extraction—unless the extractor itself
is strong.
2. Related Work
Memory optimization for LLM agents has emerged as a critical research area; a recent survey
systematizes the design space of agent memory across short-term context, long-term storage, and the
read/write mechanisms that connect them [4]. We position our study within three adjacent lines of
work: prompt compression, model cascading, and persistent agent memory.

Prompt and context compression. LLMLingua uses a small language model to score and remove
low-information tokens from a prompt in a coarse-to-fine manner, achieving up to 20× compression
with limited performance loss [2]. This validates the premise that a cheap model can identify what
matters, but compression is ephemeral—it rewrites a single prompt and leaves no reusable record
of the conversation. The motivation for compression is reinforced by evidence that models do not
use long contexts uniformly: relevant content placed in the middle of a long prompt is systematically
underused [3].
Model cascading. FrugalGPT demonstrates that routing queries through a cascade of progres-
sively more expensive models can match GPT-4 quality at up to 98 percent lower cost [ 9]. Prior
cascades target the response step rather than the memory step; the fact-slot strategy we test applies the
cascade insight to extraction-and-storage, and our results quantify where that transfer breaks down.
Persistent agent memory. Park et al. introduce Generative Agents, whose memory stream
and retrieval support coherent long-horizon behavior, but their focus is believable simulation rather
than cost [6]. MemoryBank proposes dynamic memory updating but uses a single model without
cascading [10]. MemGPT frames the context window as virtual memory, paging information between
an in-context tier and external storage [ 1]; the fact-slot table we evaluate is a deliberately simpler
realization of the same external-memory idea with writes performed by a cheaper model. Recent
production memory systems such as Mem0 [15] and A-MEM [16] report on the same benchmarks we
use; they combine structured extraction with retrieval, typically using capable extractor models. Our
study complements them by isolating, under a single controlled harness, how much each ingredient
(structure, retrieval, extractor quality) contributes—and by showing that with a genuinely cheap
extractor, structure alone contributes little.

4. Memory Strategies Compared
We evaluate seven strategies under identical conditions. The first three are standard baselines; the
remaining four are the memory designs under study.
4.1. Baselines
1. Full Context: retain the entire conversation history in every prompt.
2. Truncation: keep only the last k=10 messages.
3. Running Summary: maintain an automatically updated summary of earlier turns alongside the
recent window [5].

4.3. Retrieval-Based Memory
(6) Retrieval (BM25) : sparse top- k retrieval over conversation turns, the standard retrieval

used by recent production memory systems [15].
4.4. Models
All strategies share one cascade, run through the Groq inference service: llama-3.1-8b-instant
as the cheap extractor ϕsmall andllama-4-scout-17b-16e-instruct as the synthesizer ϕlarge for every
strategy, including full context. The synthesizer choice is dictated by an operational constraint that is
itself informative: on the free inference tier, a 70B-class model rejects any single request above 12,000
tokens, so full-context prompting of a real 20K-token conversation is not even admissible without a paid
tier. We use the 17B model, whose tier admits the full-context prompts, so that the full-context baseline
can be run at all; the consequences of this choice for absolute accuracy are discussed in Section 8.1. The
architecture itself is model-agnostic: the intended configuration is any cheap extractor paired with a
more capable synthesizer, analogous to FrugalGPT-style cascades [9].
5. Experimental Design
5.1. Datasets
We evaluate on two openly released, human-annotated long-conversation memory benchmarks
rather than on self-generated data. This directly addresses the main threat to validity of an earlier
synthetic pilot of ours (planted-fact strings over short dialogues): the conversations here are multi-
session, span hundreds of turns, and the questions were written and verified by humans.
LoCoMo [13] contains ten very long multi-session conversations (369–680 turns, roughly 10–
20K tokens each) with 1,986 human-annotated question–answer pairs in five categories: single-hop,
multi-hop, temporal, open-domain, and adversarial. Adversarial questions are unanswerable from the
conversation and the correct behavior is to abstain, which makes them a direct probe of hallucination.
We draw a category-balanced sample of up to 20 questions per conversation for the paired comparison.
LongMemEval [14] contains 500 questions over timestamped chat histories. Its categories—
information extraction, multi-session reasoning, knowledge update, temporal reasoning, and abstention—
include the two abilities most relevant to the fact-slot hypothesis: knowledge-update measures whether
a memory returns the current value of a fact changed mid-history, and abstention measures whether
the system declines when the answer is absent. We use the oracle setting, in which histories contain
the evidence sessions; these histories are much shorter than LoCoMo’s, which matters for the cost
numbers (Section 6.4).
Both datasets were constructed with an attribute-controlled, persona-driven generation pipeline
and then human-verified; they are the de-facto benchmarks for this problem and the same suites on
which recent memory systems such as Mem0 [ 15] and A-MEM [16] report. We download them at
evaluation time and do not redistribute them.
5.2. Scoring
Answers are graded by an LLM judge using the official LongMemEval grading prompts [ 14],
with category-specific rubrics (a default containment rubric, an off-by-one-tolerant temporal rubric, a
knowledge-update rubric that credits the corrected value, and an abstention rubric that credits correctly
declining). To keep replication free we serve the judge with a Groq-hostedllama-3.3-70b-versatile
rather than GPT-4o; the harness supports either. As a robustness check we cross-validated this judge
against a second, architecturally distinct judge (gpt-oss-120b) on a labeled 30-question subset: 83.3%
raw agreement, Cohen’s κ = 0.47 (moderate), with neither judge showing a systematic scoring bias.
Judge noise of this magnitude is comparable to some of the effect sizes we test, which is one reason we
report paired statistics and treat close orderings as ties (Section 8.1).

5.3. Metrics
We report: Token Reduction (real), the percentage reduction in per-query input tokens versus full
context, measured from the provider’s usage field (not a tokenizer estimate); Cost (relative), synthesis
token flow priced at provider rates plus extractor or summary maintenance, as a percentage of the
full-context baseline; and Retention, the fraction of questions judged correct, reported overall and per
category. Question-level paired differences versus full context are tested with an exact sign test and
bootstrap confidence intervals.
6. Results
We report results on a category-balanced sample of n=160 LoCoMo questions drawn from eight
of the ten conversations (≈32 questions per category); separate LongMemEval evaluations (knowledge-
update n=72; temporal/multi-session/abstention n=254) follow in Section 6.4.
6.1. Retrieval Holds Retention at 5–9% of Cost
Table 1 contains the headline finding, which we state with its exact scope. What is established at
n=160 is that BM25 retrieval and the slots+retrieval hybrid reduce real input tokens by more than
96% and cost to 4.8% and 9.0% of the full-context baseline without a measurable loss of retention: their
point estimates are above full context (39.4% and 38.8% vs. 30.6%), and against truncation both are
significantly better (hybrid +16.9 points, 95% CI [+8.1, +25.6], p < 0.001). What is not established
is that they truly exceed full context: the paired sign test (Table 3) shows only a non-significant trend
in their favor (BM25 +8.8 points, p = 0.09; hybrid +8.1 points, 95% CI [−0.6, +17.5], p = 0.12), and
the power analysis of Section 6.2 indicates an effect of this size needs roughly 360–430 questions to
confirm.

Full-context retention is itself low (30.6%) for two reasons that must be read together: LoCoMo is
genuinely hard—multi-hop and temporal questions over hundreds of turns—and our 17B synthesizer
(Section 4.4) exhibits the lost-in-the-middle effect [3] on a 20K-token prompt. Retrieval sidesteps the
long prompt by surfacing only relevant turns, which is plausibly why it matches or beats a weak
full-context reader; whether the ordering persists with a stronger synthesizer is an open question
we flag as a limitation, not a settled fact. Directionally, our numbers agree with published results
for production memory systems on LoCoMo, where structured/retrieval memory saves over 90% of
tokens versus full context [15]; absolute retention is not comparable number-for-number because those
systems use substantially stronger synthesizer and extractor models.
Table 2 shows the trade-offs are category-dependent (given≈32 questions per cell, only large
gaps are meaningful). Retrieval and the hybrid dominate single-hop and open-domain questions and
recover temporal accuracy that full context loses to prompt length. Full context retains an edge on multi-
hop questions, which require jointly reasoning over distant turns that single-shot retrieval fragments
(Section 6.3). The adversarial column is a caution: low-context methods (truncation, summary) “win”
by abstaining more often, while full context over-answers and abstains least; the memory methods sit
in between. This is why a single blended retention number is misleading and we report categories
explicitly.

6.2. Statistical Power
Because the retrieval-vs-full-context comparison is the one we most want to make, we quantify
how underpowered it is. The paired sign test depends only on the discordant questions (one method
correct, the other wrong). For BM25 vs. full context there are 58 discordant pairs (36% ofn), 36 favoring
retrieval and 22 favoring full context ( ˆp = 0.62); for the hybrid, 59 discordant pairs, 36 vs. 23 ( ˆp = 0.61).
Using a normal approximation for the sign test at α = 0.05 two-sided and 80% power, an effect of
this size requires about 130–160 discordant pairs, i.e. roughly 360–430 total questions at the observed
∼36% discordance rate. The present n = 160 is therefore adequate to establish the truncation gap
and the cost reduction, but not to declare retrieval superior to full context; that claim needs the full
1,986-question LoCoMo suite and is left for future work.
6.3. Error Analysis: Why Multi-hop Fails
Multi-hop is the category where retrieval most clearly trails full context (Table 2), so we analyzed
all 281 LoCoMo multi-hop questions using their gold evidence annotations. Each multi-hop question
cites on average 2.6 evidence turns. Running the same BM25 retriever, the top-5 results contain on
average only 13% of the gold evidence turns; just 3% of questions have all their evidence retrieved,
while 70% have none. Doubling to top-10 raises coverage only to 20% (6% fully covered), so the failure
is structural, not a matter of k. Reading 18 transcripts, the misses fall into three recurring modes: (i)
lexical–semantic gap—abstract questions (“What is Caroline’s identity?”, “What does Melanie do to
destress?”) share few surface tokens with the concrete evidence (“transgender”, “running”), which
sparse retrieval cannot bridge, including simple morphological variants (“research” vs. “researching”);
(ii) evidence fragmentation—answers such as “pottery, camping, painting, swimming” require aggre-
gating four turns scattered across sessions, so a bounded top-k structurally cannot supply all of them;
and (iii) inference gap—the answer (“single”) is implied (“single parent”) rather than stated. Modes (i)
and (iii) motivate dense [12] or query-rewriting retrieval; mode (ii) motivates iterative or multi-vector
retrieval. This is also why full context, which sees every turn, retains an edge here despite its cost.

To separate the extractor from the representation, we reran the full knowledge-update eval-

the failure mode predicted by the multi-hop error analysis of Section 6.3: temporal and multi-session
questions require jointly reasoning over evidence dispersed across sessions, and a bounded top- k

weak here—retrieval runs at 86% and the hybrid at 97% of full-context cost, versus 4.8% and 9.0% on

any claim beyond the familiar pattern that low-context methods abstain more readily. Taken together
with LoCoMo and knowledge-update, the cross-benchmark picture is that retrieval-based memory is
the right trade atlong horizons and for point-lookup questions, while full context retains a real advantage

6.5. Summary of Findings
• Retrieval is the strongest cheap lever on long real conversations: on LoCoMo and on knowledge-
update, BM25 retrieval holds retention level with full context at a fraction of the cost, by surfacing
query-relevant turns and avoiding lost-in-the-middle degradation. Its boundary is dispersed-
evidence reasoning: on LongMemEval’s temporal and multi-session categories BM25 trails
full context significantly (−10.2 points, p = 0.004) and only the slots+retrieval hybrid remains
statistically indistinguishable from it (Table 6).
• The bottleneck is the extractor, not the representation—but fixing it breaks the economics :
the extractor-size ablation (Table 5) shows a 70B extractor recovers +29.2 points of slot retention

• Knowledge-update questions are mostly recent: the proximity of the updated fact to the end

• Operational feasibility: full-context prompting of real long conversations is rejected above a

• Category sensitivity: a single blended retention number hides large per-category differences

rewarding indiscriminate non-answers.

7. Reference Implementation
To support reproducibility, we release an open-source implementation of the harness and all seven
strategies. It is a small, dependency-light Python package comprising: hierarchical_memory.py
(append-only notes, latest-value fact slots, OpenAI-compatible provider clients, robust extraction
parsing, and context builders); token_utils.py (token accounting); real_datasets.py (LoCoMo
and LongMemEval adapters with category labels and abstention flags);judge.py (the LLM-as-judge
scorer using the official LongMemEval grading prompts, with a containment fallback for offline
use); evaluate.py (a harness running all seven strategies with per-category metrics, per-question
records, per-call failure resilience, and a–resume mode for rate-limited runs);make_figures.py (deter-
ministic figure generation); andscripts/paired_analysis.py plusscripts/summarize_results.py
(question-level paired tests with bootstrap CIs and exact sign tests, and paper-ready table extraction).
The provider interface is abstracted so the small and large models can be backed by any chat-
completions-compatible API; the evaluation in Section 6 was run through an OpenAI-compatible
backend against the Groq inference service. Per-query token counts are taken from the provider’s own
usage accounting rather than estimated with tiktoken, which is an OpenAI tokenizer and mis-counts
other model families. The complete source, benchmark adapters, judge, raw per-question results,
paired-analysis outputs, and generated figures are available at https://github.com/sakul7-stack/
nodemem. The benchmarks are downloaded at evaluation time and not redistributed.
8. Discussion
8.1. Limitations
Ordered by severity:
1. The retrieval-vs-full-context comparison is underpowered.The LoCoMo numbers covern = 160
of 1,986 available questions from eight of the ten conversations; by our own power analysis
(Section 6.2), confirming the observed +8-point retrieval advantage needs 360–430 questions. We
therefore claim parity-at-lower-cost, not superiority. Completing the full suite is the most direct
extension of this work.
2. The synthesizer is a 17B model, which weakens the full-context baseline. Free-tier request caps
forced a 17B synthesizer (Section 4.4); it answers only about a third of LoCoMo questions even
with full context, in part due to lost-in-the-middle degradation on 20K-token prompts. A stronger
synthesizer would raise all rows and could narrow or reverse the retrieval-vs-full-context ordering,
since a capable long-context reader loses less to prompt length. Our claims are comparative at
equal model, and the ordering must be re-tested on a 70B-class or frontier synthesizer before
being treated as general.
3. Judge: we score with a Groq-hosted Llama judge using the LongMemEval prompts rather than
GPT-4o. Cross-validation against a second judge on 30 questions gives κ = 0.47 (moderate)—

agreement noise comparable to some effects we test. The judge is a configuration option in the

4. Retrieval is sparse only: the retrieval baseline is BM25 over turns. A dense-embedding back-
end [12] is implemented but not yet run at scale; the error analysis (Section 6.3) predicts dense
and iterative retrieval would specifically attack the multi-hop failure modes.
5. The extractor ablation covers one benchmark category : the 8B-vs-70B extractor comparison
(Table 5) is on LongMemEval knowledge-update only; its cost conclusion is specific to short
oracle histories, where extraction cannot amortize. The break-even conversation length at which
a strong extractor pays for itself is not yet measured. We also observe +8-point run-to-run drift
on full context between the two runs (judge/synthesizer nondeterminism), which bounds how
finely single-run orderings should be read.
6. LongMemEval cost figures are not representative: the oracle histories are short, so cost savings
there (75–99% of full context) understate what retrieval saves on genuinely long conversations;
the LoCoMo cost numbers (4.8–9.0%) are the representative ones.
7. Sampling and tier constraints : the temporal/multi-session sample is drawn from the oracle
setting rather than the full 500-question suite; the abstention subset ( n = 6) supports no firm
conclusion; cumulative (growth-curve) token counts in the appendix use tiktoken and are
approximate for Llama models.
8.2. Future Work
• Complete the benchmark sweep : all ten LoCoMo conversations and the full 1,986 questions
(which the power analysis shows is sufficient to resolve the retrieval-vs-full-context question),
and the full 500-question LongMemEval suite.
• Extractor break-even length: the ablation shows a 70B extractor fixes slot quality but costs 1.8×
full context on short histories; measure the conversation length at which one-pass extraction
amortizes against repeated full-context reads (LoCoMo-length and beyond), and test mid-sized
extractors (17–30B) for a cheaper operating point.
• Stronger synthesizers: repeat on a 70B-class or proprietary model to test whether the retrieval-vs-
full-context ordering persists as absolute accuracy rises.
• Dense and hybrid retrieval: evaluate embedding-based, query-rewriting, and iterative retrieval
targeted at the three multi-hop failure modes, and graph-structured memory [15,16].
• Sensitivity: sweep recent_k, segment size, slot cap, and retrieval top-k.
• Judge robustness: extend the two-judge cross-validation (currently 30 questions, κ = 0.47) to a
larger labeled subset and add GPT-4o as a third reference judge.
9. Conclusion
This paper reports a controlled cost–retention study of seven memory strategies for LLM agents
on real, human-annotated long conversations. The findings are threefold. First, sparse BM25 retrieval—
the simplest and cheapest memory studied—cuts real input tokens by 98% and cost to under 5%
of full context on LoCoMo while holding retention level with it, and is significantly better than
truncation (p < 0.001); its apparent edge over full context ( +8.8 points) is a non-significant trend
whose confirmation requires roughly 360–430 questions. Second, we report a negative result with
a diagnosis: latest-value fact slots written by a cheap 8B extractor are the weakest memory method
on both benchmarks, including on LongMemEval’s knowledge-update category (37.5% vs. 73.6% for
retrieval), which they were designed to win. An extractor-size ablation pinpoints the cause: upgrading
only the extractor to a 70B model recovers +29.2 points (paired p < 10−4; retrieval, which bypasses
the extractor, is unchanged as a control) and makes the slots+retrieval hybrid the best method (80.6%)—
but at 1.8–2.2× the cost of full context on short histories. The representation works; the cheap-cascade
premise does not: with a cheap extractor the slots are wrong, and with a capable one they are not cheap.
Cheap-extractor structured memory should not be deployed without validating extraction quality
first. Third, an error analysis over all 281 LoCoMo multi-hop questions localizes where retrieval-based

synthesizer and a fully powered sample, and where the extractor break-even length lies—can be
answered by anyone with a larger inference budget.
