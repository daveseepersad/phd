Large language models (LLMs) have significantly advanced automatic code generation, yet most existing approaches rely
on single-model inference, making their performance susceptible to model-specific limitations and failure patterns. To
address this, we introduce Cross-Model Collaborative Scheduling (CMCS), a framework that enables multiple LLMs to
collaboratively generate code. At its core, CMCS combines execution-guided self-correction with a peer-to-peer corrective
handover mechanism, transferring unresolved problems between models to leverage their complementary strengths and
mitigate the limitations of any single model. Experiments on eight code generation benchmarks show that CMCS achieves
the strongest performance among the evaluated comparable-scale approaches with strong parameter efficiency. In particular,
two 7B-scale models consistently outperform a much larger 30B-scale model on every benchmark where both are evaluated.
When applied to proprietary models, CMCS boosts Pass@1 on APPS to 36.00%, more than three times that of the stronger
individual model (11.33%). CMCS also maintains competitive accuracy when only 20% of test cases are available for diagnostic
feedback. Ablation, scalability, and cost-effectiveness analyses quantify component contributions and practical deployment
trade-offs. These findings indicate that cross-model collaboration offers a practical and parameter-efficient alternative to
scaling up monolithic models for code generation.

Cross-Model Collaboration for Enhancing LLM-Based Code Generation • 3
In this paper, we propose Cross-Model Collaborative Scheduling (CMCS), a novel and effective framework
designed to coordinate collaborative code generation across multiple LLMs. In its current instantiation, CMCS
employs two LLMs as the minimal collaborative unit, both for conceptual clarity and practical efficiency. However,
the framework itself is not restricted to two models; its scheduling and handover mechanisms are inherently
scalable and can be flexibly extended to larger pools of collaborating LLMs. CMCS operates in three phases. First,
the problem set is partitioned into two disjoint subsets, and the two participating models independently generate
initial code solutions for their assigned subsets in parallel. Each solution then enters a diagnostic correction loop
driven by execution feedback and test results. If a model fails to self-correct, CMCS activates its peer-to-peer
corrective handover mechanism, assigning the unresolved problem to another model for a fresh attempt at code
generation, diagnosis, and repair. This design strategically exploits diverse complementary strengths across
models and mitigates the inherent biases of single-model generation, resulting in substantial and consistent
improvements in code generation performance.
We conducted comprehensive experiments across eight widely used code generation benchmarks with 7B-scale
LLMs, a representative and practically relevant model size for contemporary deployment scenarios. The results
show that CMCS consistently improves generation quality by integrating diagnostic correction with collaborative
scheduling. Furthermore, our experiments demonstrate that CMCS is model-agnostic: it can integrate LLMs
with different architectures and training paradigms as interchangeable collaborators. Our contributions are
summarized as follows:
• We present CMCS, a novel cross-model collaboration framework that introduces a peer-to-peer corrective
handover mechanism, enabling the exploitation of complementary strengths across LLMs and mitigating
the inherent limitations of single-model code generation.
• We introduce a fine-grained diagnostic correction mechanism that guides LLMs through iterative self-
repair using compiler, runtime, and test feedback, enabling structured error analysis and emulating the
debugging workflow employed by human developers.
• Weconductexperimentsacrosseightbenchmarks,showingthatadual7B-scaleconfigurationoutperforms
a much larger 30B-scale model and validating CMCS’s generalizability across backbone models, multi-
model scalability, and robustness under incomplete test suites.
• We release the source code to support reproducibility and foster future research on cross-model collabora-
tion for code generation [19].
2 Related Work
2.1 Code Generation with Large Language Models
Accurately understanding user requirements and translating them into correct executable code has long been
a central challenge in artificial intelligence (AI)–assisted SE [23, 51]. Traditional code generation approaches
[15, 32], largely based on handcrafted templates and rule-based systems, offer limited adaptability to diverse and
complex problem specifications.
Recent advances in LLMs, driven by large-scale pretraining on natural language and code corpora, have
substantially improved automatic code generation. Modern LLMs, built upon the Transformer architecture [45],
now exhibit strong performance across a wide range of programming tasks and have achieved state-of-the-art
results on standard code generation benchmarks. Representative open-source models, such as Code Llama [40],
WizardCoder [34] and Magicoder [50], along with proprietary systems like GPT-4 [38], continue to push the
performance frontier. Moreover, specialized systems such as AlphaCode [31] have demonstrated competitive
programming capabilities. Beyond code synthesis, LLMs are increasingly applied to broader SE tasks, including
context-aware code completion (e.g., InCoder [11]), automated program repair [30], and test case generation [41].

Despite these advances, most existing approaches still rely on single-model inference, which may suffer from
systematic biases, limited reasoning diversity, and constrained error-correction capacity.
2.2 Self-Correction in Code Generation
Akeylimitationofone-shotgenerationisthedifficultyofproducingcorrectcodeinasingleattempt.Consequently,
recent studies increasingly explore enabling LLMs to iteratively refine or repair their outputs—a process often
referred to as self-repair or self-correction. This paradigm treats code repair as a post-processing step to improve
the reliability of automated code generation [29].
Several strategies have been proposed to facilitate this. For example, Zhang et al. [55] introduced Self-Edit,
which uses execution results to guide the model’s corrections. Our work is also inspired by this line of research.
Other prominent methods used as baselines in our evaluation includeSelf-Debugging [7], which instructs
LLMs to explicitly explain the cause of errors before fixing them, and INTERVENOR [46], which simulates a
human-like interactive repair process by casting LLMs into “code learner” and “code teacher” roles. Similarly,
Self-Planning [27] adds a planning phase to decompose complex problems into sub-problems before generation.
These self-correction methods have proven effective but remain constrained by the knowledge and inherent
biases of a single model, which may fail to fix errors if the required solution is beyond its reasoning capabilities.
2.3 Collaborative and Multi-Agent Code Generation
To address the inherent limitations of single-model approaches, recent work has increasingly explored collab-
orative paradigms involving multiple LLMs or specialized agents. These systems coordinate distinct models
or prompting strategies to exploit complementary strengths, thereby improving generation robustness and
correctness.
Existing studies have explored several cross-model collaboration paradigms, including role-based coordination,
multi-model debate/review, cross-model validation, and routing-based collaboration. A common paradigm is
role-playing, where agents emulate a software development team. For example, ChatDev [39] constructs a virtual
company in which agents such as a CEO, programmer, and tester collaborate through structured dialogues.
Extending this line, MetaGPT [17] implements an assembly-line paradigm where agents assume specialized roles
(e.g., product manager, architect, engineer) following standard operating procedures. MapCoder [22], one of our
key baselines, uses a four-stage pipeline for example retrieval, planning, coding, and debugging. Other approaches
emphasize generating diverse solutions from multiple perspectives. Corex [43], for instance, coordinates multi-
model collaboration via “Debate” and “Review” paradigms, treating each model as an expert whose insights
contribute to a consolidated solution. Some frameworks employ cross-model validation, such as ConTested [9],
which uses one LLM to generate tests for another’s code, forming a test-driven refinement loop. AgentCoder [18]
similarly establishes a closed-loop system of code generation, test generation, and execution agents. Routing-
based approaches dynamically allocate models to subtasks; for instance, MasRouter [53] introduces a dynamic
routing mechanism that intelligently selects the most appropriate LLM for different agents and tasks, balancing
performance with computational cost.
Our CMCS framework represents a distinct form of cross-model collaboration that shares the goal of exploiting
collective intelligence but adopts a different interaction design. Instead of relying on structured role-playing with
extensive inter-agent communication or fixed multi-stage pipelines, CMCS employs a symmetric peer-to-peer
corrective handover mechanism. Collaboration is activated only when a model fails to self-correct, allowing the
partner model to take over unresolved cases. This selective failover strategy reduces unnecessary interactions for
straightforward problems and focuses collaboration on more challenging ones, providing a more cost-efficient
way to leverage complementary strengths across models.

3 Methodology
3.1 Overview
Inthispaper,weproposeanovelcollaborativeframeworkforcodegeneration,asdepictedinFig.2.Ourframework
consists of three main components: Dual-Model Collaborative Code Generation (DCCG), Diagnostic Correction
Mechanism (DCM), and Cross-Model Collaborative Generation (CMCG). The first component, introduced in
§3.2, initializes the process by allowing two LLMs to generate candidate solutions in parallel, improving the
efficiency of initial code synthesis. The second component, described in §3.3, enables each model to self-diagnose
and repair errors using compiler messages, runtime outputs, and test-case feedback, guided by prompts designed
to facilitate logical thought and reasoning. All correction attempts are performed in a stateless manner: each
repair query includes the current faulty code and diagnostic feedback without relying on previous conversational
history, thereby preventing context accumulation and reasoning drift. The final component, discussed in §3.4, is
activated when a model fails to self-correct. In such cases, unresolved problems are conditionally transferred to
the collaborating model, enabling the system to exploit complementary reasoning capabilities across LLMs. This
selective peer-to-peer corrective handover mechanism focuses cross-model collaboration on challenging cases
and improves the robustness of automated code generation.

3.3 Diagnostic Correction Mechanism
Once the problem subsets𝒫𝐴 and 𝒫𝐵 are processed by models𝑀𝐴 and 𝑀𝐵 to generate initial code solutions,
these solutions are subjected to compilation and testing. If a generated code snippet fails validation, we employ
DCM to prompt the same LLM to analyze the failure and correct the error. As illustrated in Fig. 3, this mechanism
leverages compiler messages, execution outputs, and test feedback to guide iterative self-repair. For languages
such as C++, the validation process involves compilation followed by execution against a predefined test suite.
Following prior work [55], errors encountered during validation can be categorized into three types:
• Compilation Errors: Errors that occur when the code does not conform to syntax rules or language
specifications, resulting in the program failing to compile.
• Runtime Errors: The program compiles but fails during execution (e.g., timeouts, crashes, or unhandled
exceptions), resulting in incomplete test execution.
• Test Errors: Errors where the program runs to completion but produces an output that does not match
the expected result for a given test case.

3.4 Cross-Model Collaborative Generation
If a code snippet generated by one model (e.g.,𝑀𝐴) fails to pass the diagnostic correction process, CMCS invokes
the CMCG module. This module addresses these self-correction failures by leveraging a collaborating LLM
(e.g., 𝑀𝐵). The core idea is simple yet powerful: reassign the failed problem. For instance, the problem that
𝑀𝐴 could not solve is now assigned to𝑀𝐵 for a fresh attempt at generation and correction. This approach is
motivated by empirical observation that a model may reach its reasoning boundary or fall into repetitive error
patterns for certain problems, thus benefiting from a different model’s perspective. This method fully utilizes the
complementary capabilities and diverse performance preferences of the models. The process is described more
formally as follows:

as final outputs.

4.1 Research Questions
We evaluate CMCS by defining the following research questions (RQs):
• RQ1: How does CMCS compare to state-of-the-art methods and simple ensembles?RQ1 evalu-
ates CMCS against diverse baselines, including direct generation, prompting strategies, and advanced

scales? RQ2 assesses the versatility of CMCS by evaluating its performance across Python, C++, and

applicability by measuring robustness under incomplete test suites (i.e., imperfect feedback) and by

4.2 Experiment Settings
4.2.1 Datasets. We evaluate CMCS on eight widely used benchmark datasets covering multiple programming
languages, including Python, C++, and Java:HumanEval [6], HumanEval+ [33], HumanEval-X [59], MBPP
[2], MBPP+ [33], CodeContests [31], APPS [16], andSPoC [28].
Among these, HumanEval and MBPP are two widely used benchmark datasets for evaluating code gener-
ation models. HumanEval focuses on Python function synthesis tasks, while MBPP includes a series of basic
programming tasks along with their corresponding test cases. To further enhance the comprehensiveness of
evaluation, researchers have proposed enhanced versions, HumanEval+ and MBPP+, which significantly improve
therobustnessofevaluationbyexpandingthecoverageoftestcases.Additionally,HumanEval-X,asamultilingual
extension of HumanEval, is specifically designed to test the multilingual code generation capabilities of models.
For more complex programming challenges, CodeContests simulates competitive programming scenarios,
providingmorechallengingtasks.APPSisalarge-scale,multi-difficulty-levelcollectionofprogrammingproblems,
suitable for comprehensive evaluation of code generation models. For APPS, we follow Islam et al. [22] and
use a subset of 150 randomly selected test problems from APPS for evaluation. SPoC contains C++ programs
with associated pseudocode and test cases, each representing solutions to competitive programming tasks. The
dataset is organized into different subsets for training, evaluation, and testing, known as Train-Train (TrainTR),
Train-Evaluation (TrainE), and Train-Test (TrainT) sets. In addition, two held-out test sets are provided: the
TestP set is divided by problems, while theTestW set is divided by workers. We followed the default data split
in the official SPoC1, and report results on theTestP and TestW sets.
For benchmark datasets lacking publicly available test cases, we followed the approach of Zhang et al. [54] by
treating the first private test case as a public test case. For MBPP+, we adopted the original three private test
cases from MBPP before they were expanded and made public.

4.2.2 Baselines. To our knowledge, existing studies have not explored a peer-to-peer corrective handover
mechanism between collaborating LLMs for code generation. To systematically evaluate CMCS, we compare it
against a diverse set of baselines, including representative state-of-the-art methods. A brief overview of these
approaches is provided below.
• Direct [6] uses the original problem descriptions as input for prompting LLMs to generate code, relying
solely on the inherent capabilities of the models.
• Chain-of-Thought (CoT)[49] guides LLMs to generate intermediate natural language reasoning steps
before producing the final solution. We adopt the classic CoT instruction “Let’s think step by step” to
elicit such reasoning from the models.
• Self-Planning [27] introduces a planning phase into the code generation process by decomposing
complex problems into a sequence of solvable sub-problems and formulating corresponding solution steps.
This helps the model better understand task intent and reduces the overall difficulty of problem solving.
• Self-Debugging [7] enables LLMs to iteratively improve their own outputs by executing the generated
code and using runtime feedback to guide corrective refinement, thereby improving the accuracy of code
generation.
• INTERVENOR [46] simulates the human interactive code repair process by using LLMs to play the
roles of code learner and code teacher, producing a Chain-of-Repair that improves the accuracy of code
generation and repair.
• MapCoder [22] employs four agents to simulate the program synthesis workflow of human developers,
including example retrieval, planning, code generation, and debugging, to improve the accuracy of code
generation.
• Naïve Ensemble: To isolate the contribution of our collaborative mechanism, we introduce a naïve
ensemble baseline. It independently generates code with two different models and marks a problem as
solved if either model succeeds. This baseline enables us to separate CMCS’s collaborative diagnostic
process from a simple parallel aggregation.

4.5.3 Ablation Study. To rigorously evaluate the contribution of each component and the necessity of our

merely additive but synergistic, working together to maximize code generation reliability by jointly reinforcing
both generation diversity and error-correction effectiveness.

5 Threats to Validity
We discuss potential threats to the validity of our empirical study and the mitigation strategies adopted to reduce
their impact, organized into the following validity aspects.

Generalizability of Results.A primary threat concerns the generalizability of our findings. To mitigate
this threat, we evaluate CMCS on eight widely used benchmark datasets, including HumanEval, MBPP, and
APPS, covering diverse code generation tasks and programming languages. These benchmarks have been widely
adopted in prior studies for evaluating code generation performance. The consistent performance of CMCS
across these benchmarks suggests that the framework generalizes across these diverse datasets and task settings.
Nevertheless, we acknowledge that performance may vary on additional benchmarks or in real-world industrial
scenarios, which remain directions for future investigation.
Data Leakage in Pre-trained Models.Another potential threat concerns data leakage, where pre-trained
LLMs may have been exposed to benchmark data during training. While such exposure cannot be conclusively
verified, this risk applies uniformly to all evaluated methods, as the same underlying backbone models are used for
CMCS and all baselines. Although asymmetric exposure across models could theoretically influence collaboration,
its precise impact is difficult to quantify. Since our evaluation emphasizesrelative performance comparisons
under identical model configurations, this threat is unlikely to invalidate the comparative conclusions.
Dependency on Test Oracles.A key threat to the practical applicability of CMCS is its reliance on test oracles
to provide feedback for the diagnostic correction mechanism. Our primary benchmarks, such as HumanEval and
MBPP, provide comprehensive test suites, allowing controlled evaluation. However, in real-world development,
completetestsuitesareoftenunavailable.Toassessthislimitation,weconductedarobustnessanalysis(Section4.7,
Fig. 9) under partial test coverage. The results demonstrate graceful degradation, with CMCS maintaining
competitive performance even when only partial feedback is available. Although this mitigates the concern to
some extent, further evaluation under alternative feedback mechanisms (e.g., static analysis or automatically
generated tests) would strengthen the construct validity of the framework.
Execution Safety and Resource Costs.The execution of machine-generated code may pose safety risks
when running unverified programs. To mitigate this concern, all experiments were conducted in a sandboxed
environment to isolate execution and prevent system-level side effects. In addition, the collaborative design of
CMCS requires loading multiple models simultaneously, resulting in higher peak GPU memory usage compared
to single-model approaches. As analyzed in our cost-effectiveness evaluation (Table 7), this increased memory
footprint reflects an inherent trade-off between resource consumption and performance. While CMCS incurs
higher peak memory usage, it maintains a competitive balance between accuracy and latency. This trade-off
should therefore be considered in resource-constrained scenarios.
6 Conclusion
In this paper, we presented CMCS, a collaborative framework for improving LLM-based code generation by
leveraging the complementary strengths of heterogeneous models. By integrating parallel generation, diagnostic
self-correction, and a peer-to-peer corrective handover mechanism, CMCS alleviates model-specific limitations
commonly observed in single-model systems. Extensive experiments across eight diverse benchmark datasets
demonstrate that structured cross-model collaboration consistently yields substantial performance gains over
competitive baselines. Importantly, CMCS achieves these improvements without increasing the scale of individual
models, highlighting that performance advancement in code generation does not solely depend on parameter
expansion. This finding suggests that structured collaboration itself provides a viable and scalable pathway for
enhancing robustness and reliability in code generation. Building on this insight, future work will explore several
promising directions, including extending CMCS to support dynamic routing over larger pools of collaborating
models, further optimizing the trade-off between performance and resource consumption in constrained environ-
ments, and enhancing real-world applicability by incorporating weaker or alternative feedback signals in place
of fully specified test suites. Overall, this work establishes structured cross-model collaboration as a powerful
and generalizable paradigm for advancing the reliability and robustness of code-generating LLMs.
